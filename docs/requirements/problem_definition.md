## 1. 产品描述

按课程[产品描述模板](https://github.com/bettermorn/IntelligentSWEPractice/blob/main/courseware/pages/part1analyze.md#产品描述)填写：

> **对于**实习经历有限、主要拥有课程项目、学科竞赛、科研或毕业设计经历，并准备技术岗位实习及校招面试的高校学生，
>
> **他们**希望将已有经历转化为岗位相关的能力表达，在即时口头问答中讲清自己做了什么、为什么这样做、取得了什么结果，并能够临场应对进一步追问。
>
> **InterviewLab（面试练习室）**是一个面向高校学生的 AI 模拟面试与复盘 Web 应用。
>
> **它能够**结合目标岗位、所选简历和学生确认的项目经历开展实时语音提问与连续追问，在面试结束后结合回答内容、语音节奏和可选镜头表现提供复盘、优势与不足总结，以及针对性重练和前后对比。
>
> **不同于**以候选人筛选为目标的系统，以及允许编辑后提交回答的回合式练习流程，
>
> **我们的产品**围绕学生项目与竞赛经历中的个人贡献、技术取舍、结果依据和岗位关联，强调即时口头作答、自然接续与追问，将具体回答片段的内容和表达观测串入面后复盘与重练，帮助学生检验能否独立讲清自己的经历。

上述完整能力为设计目标；当前文字交互演示不代表真实后端或模型能力已实现。“实习经历有限”是选定细分群体的特征，不代表所有高校学生。相关产品事实、公开用户自述与机会假设分别记录在[技术与竞品调研](../algorithm/research.md)。

| 项目要素 | 当前定义 |
| --- | --- |
| 目标用户 | 准备计算机技术岗位实习或校招，主要依靠校园项目、比赛、科研或毕设说明能力的学生 |
| 岗位范围 | 已有 1000 个计算机相关方向的公开整理内容，含软件、AI/大模型、数据、产品和设计；正式知识与标准须审核 |

## 2. 5W1H 问题定义

### What：要解决什么问题？

部分学生做过课设、比赛或科研，却可能只能描述团队用了什么技术，难以解释自己承担什么、为什么选择某种方案、遇到的问题如何解决，以及哪些结果能够支持能力表达。准备好书面答案也不代表能够在口头对话中即时组织内容、澄清问题和接住连续追问。这些是需要访谈与试用验证的痛点假设，并非已经得出的学生群体结论。

本项目选择“直接实时口头模拟面试 → 面后分析 → 针对一个缺口同题重练与对比”。首版默认 `realtime_voice`，以直接说、自动保存回合、自然接续为主要交互；不要求编辑识别稿后点击发送。`text_fallback` 支持独立完成且报告注明方式，不是教学模式。准备配置仅用于选岗位、简历和重点经历，不设置教学前置关卡。学生没有简历或重点项目也可手填经历，或直接开展通用技术问答。

### Why：为什么值得解决？

拟验证的价值是：围绕学生的真实材料开展即时口头问答和连续追问，能否帮助学生暴露并修复“团队成果与个人贡献混淆”“技术选择解释不足”“结果依据不清”“追问后组织困难”等具体缺口。报告应让学生知道哪段回答存在什么问题、哪些优势有事实支持、下一次具体改进什么；语音与可选视觉反馈须定位到实际观测片段，不能据表情猜测情绪或能力。

价值验证采用相同材料、相近时间及明确记录的交互条件，与可访问的陪练工具和认真提示的通用模型比较追问相关性、反馈准确性、建议可执行性及回答变化。满意度、重练次数或模型自评分上涨不能独立证明能力提升。

### Who：为谁解决，由谁参与？

| 对象 | 需求或职责 |
| --- | --- |
| 课程项目为主的学生 | 解释设计与实现，区分个人行动和团队产出 |
| 有比赛、科研或毕设经历的学生 | 说明实际约束、技术取舍、验证方式和协作；不被要求编造商业收益 |
| 有少量实习或已参加面试的学生 | 找到项目叙述、技术追问或表达中的具体不足并重练 |
| 维护人员 | 审核岗位与知识内容，维护权限、版本、运行及费用 |
| 项目小组与课程教师 | 小组实现与验证系统，教师检查课程交付并提供反馈 |

用户画像是设计假设。学生自主使用是首版场景，不建设教师端、班级管理或企业候选人筛选。人员分工见[团队计划](../mgmt/team_plan.md)，未确定的姓名、账号和工期不编造。

### When：何时使用，何时交付？

学生可在技术岗位面试前进行短时模拟，或在看完报告后针对一个问题重练。面试时长提供 5/10 分钟，默认 10 分钟；最多 6 个主问题，每题最多 2 次追问。12 分钟为包含暂停的安全上限；目标时间和硬上限行为见[功能需求](functional_spec.md)。

当前已用明确标注的演示数据完成可交互原型。后续按阶段 1 真实文字闭环、2 材料/内容完善、3 实时语音、4 可选能力实施；原阶段 A 对应 1–2，B 的实时核心对应 3，C 仍为稳定后的对照与小规模试用，可选镜头移至 4。3D 面试官不再是首版必需交付。同类新题检验属于后续扩展和评测内容。本轮仅改文档，具体开发时间以人员、预算及接入条件确认后安排，见[评测计划](../algorithm/evaluation.md)。

### Where：在什么环境使用与协作？

计划通过中文 Web 应用在学生可自主练习的环境中使用。默认选择实时语音不自动开始采集，明确点击开始并完成浏览器授权后才采集。麦克风不可用或语音服务失败时，文本路径可独立完成；摄像头默认关闭，拒绝开启不影响面试和内容报告。简历、音视频、个人材料和密钥不进入 Git，共享开发及评测使用合成或明确获授权材料。目标采用独立 Fastify 后端与 Better Auth 受邀账号，部署资源、供应商凭证及接入配置待确认。

### How：怎样解决与验证？

1. 选择技术岗位、难度和面试类型，使用岗位模板或输入 JD。
2. 选择已确认的库内简历与“本次重点经历”，或临时上传、手填、跳过；只冻结选定版本，待确认提取稿不能成为个人事实。
3. 确认 5/10 分钟时长、可选代码考核和面试官风格，默认以实时语音开始；允许思考、口头自纠、澄清和打断 AI，AI 主动打断仅为可选风格。通用技术问答无须有简历或项目。
4. 根据口头回答自动判断回合结束并保存，再围绕目标、职责、实现、取舍、问题、验证和协作自然追问；误截可恢复追加，面试中不给答题框架、参考答案或能力评分。
5. 结束后按专业知识、项目表达、代码能力、逻辑表达四维百分制分析，关联回答或代码证据；未观察维度不记零分。语速、停顿、疑似口头语、音量和音高变化，以及可选面部动作/头部朝向/画面质量观测单独展示，不混入总分。
6. 从报告选择一个具体问题及时间片段，创建关联的模拟会话重新回答，比较两个回答版本的内容与表达；作答方式变化时注明可比性限制。自动保存记录并支持删除。

数据及公共字段见[数据与接口](../software/data_and_interfaces.md)，布局与跳转见[界面原型](../software/prototype/README.md)。字幕用于识别呈现，不润色替换原始口头回答；面后 ASR 纠错保留原识别、原因及版本，不能补答冒充原回答。原始音视频默认临时处理后清除，只有用户明确开启复盘媒体保存时才私有保留、自采集起最长 24 小时；到期后保留可定位的时间戳和派生观测，无法回放或重算依赖原媒体的指标，不能生成替代片段。转写、回答、语音/视觉观测和报告分别保留版本。

## 3. 典型场景与事实边界

以下仅为需求检查的合成场景，不是真实访谈、用户评价或实验结果：

| 场景 | 模拟与复盘重点 | 不能推断的事实 |
| --- | --- | --- |
| 课程设计 | 学生负责 Redis 缓存，追问缓存对象、失效策略、选择依据及已有验证 | 未提供测试，不能声称性能提升百分比或生产高并发经验 |
| 团队比赛 | 学生负责特征处理，队伍获奖；分别追问本人行动、协作与方案比较 | 奖项不能归因为个人独立完成全部系统 |
| 科研/毕设 | 学生负责复现实验，追问数据划分、基线、结果解释与限制 | 未给出的结果不能补成显著提升或论文录用 |
| 少量实习 | 学生维护一个接口，追问实际改动、测试及交接 | 不把实习时长当能力分，不放大职责与业务收益 |
| 无材料/提前结束 | 通用问答可开始；保存有效回答，明确观察范围 | 不能仅凭无材料推断个人经历或优势；零有效回答不评分 |

参考表达仅重组学生确认的事实。学生在回答中补充的信息保留为回答证据，不自动反写为已确认简历。缺少实习、商业收益、上线规模或用户增长数据不能直接扣分。

## 4. 交付边界与成功判断

| 阶段 | 计划内容 |
| --- | --- |
| 1：真实业务闭环 | 独立后端、受邀登录、文本简历/经历、岗位/收藏、文字面试、证据报告、重练/比较、记录与权限 |
| 2：材料与内容完善 | PDF/DOCX、解析确认、私有文件、PDF 导出、内容维护命令、混合检索与评分人工校准 |
| 3：实时面试 | ASR/TTS、自动回合、自然接话、打断/误截恢复、重连/降级和独立语音观测 |
| 4：可选能力 | 隔离代码执行与评审、可选镜头、授权复盘媒体、管理页面 |
| 评测与试用 | 各阶段合成回归，稳定后人工评价、同材料对照、小规模授权试用与成本核对 |
| 后续验证/扩展 | 同类新题检验、更多岗位与材料接入；更复杂语气标签或视觉解释需另行论证，首版不推断情绪、诚实、人格或能力 |
| 首版不包含 | 教学前置模式、3D 必做、企业筛选、录用概率、自动投递、支付、排名、专业资格认证 |

验收应同时满足：无材料路径可完成；反馈引用可定位且不编造优势；个人数据隔离且可删除；重练保留原回答和比较依据；同材料对照不预设本系统获胜。量化标准集中在[评测与迭代](../algorithm/evaluation.md)，具体功能与场景见[功能需求](functional_spec.md)、[非功能需求](nonfunctional_spec.md)和[用户故事](user_stories.md)。

## 5. 待验证假设与文档验收

| 假设 | 后续需收集的证据 |
| --- | --- |
| 选定学生群体仍有明确困难 | 现有工具试用后的具体障碍、访谈记录和退出原因 |
| 项目材料使追问更贴合 | 同材料对照，独立评阅问题与本人职责/实现的关联 |
| 证据反馈有助于具体改进 | 原句引用准确性、建议可执行性、同题前后变化；区分新增事实与表达变化 |
| 同题改进可迁移 | 后续同类新题人工比较，避免把背熟原题当作能力改善 |
| 实时口头交互可用于临场应答训练 | 回合识别、自然接续、误截恢复、澄清和打断体验；与可编辑文本方式分开记录 |
| 多模态复盘收益大于采集与解释负担 | 语音/视觉观测准确性、可核对性、片段关联、拒绝摄像头和媒体过期场景；不以情绪推断替代证据 |
| 质量、成本与隐私可支持试用 | 核验服务条款、调用费用、隔离及删除演练 |

本轮文档验收包括：六行产品描述与 5W1H 完整；需求、页面、接口、评测可互相对应；旧教学入口及评分等冲突清理；链接及仓库检查通过。教师反馈记录为“2026-10-15，用户转述”，不等同于 GitHub Issue 已收到回复；历史提交与核验记录保留原日期。
