# 功能需求规格

版本：v0.2 · 日期：2026-10-15 · 状态：待实现、待验证。

## 2026-10-19 范围增补

岗位覆盖扩展为36个计算机相关方向，包含AI/大模型、数据、产品、交互、基础设施、机器人与游戏。新增岗位库/详情和个人目标岗位（收藏模板及个人JD）；个人中心以概览、简历、记录、目标和偏好组织，多份简历支持文本维护及独立经历。

当前实现为本地交互演示，公共岗位内容有来源与版本；真实认证、上传、数据库、实时语音和专业评分仍待接入。下文原生产目标与优先级保留，实际已实现范围以[扩展记录](../software/prototype/library-expansion.md)为准。

## 1. 范围与优先级

InterviewLab 面向实习经历有限、主要拥有校园项目、比赛、科研或毕设经历的学生，首版覆盖中文计算机技术岗位。主流程为“直接实时口头模拟面试 → 面后分析 → 同题定向重练”，配置不是教学前置关卡。首版默认 `realtime_voice`，`text_fallback` 可独立完成，报告标明实际作答方式。能力定位见[问题定义](problem_definition.md)。

P0-A 表示阶段 A 基础闭环与文本联调，属于过渡；P0-B 表示首版阶段 B 核心实时语音与基础多模态目标；P1 表示后续扩展或验证。阶段 C 为评测与小规模试用。本轮只修订文档；后续前端先交付明确标注模拟数据的可交互原型，原型结果不得冒充模型评审、代码执行或实测效果。

## 3. 六个界面单元与入口

五个主路由：首页、面试配置、面试会话、分析报告、个人中心；代码面板作为第六单元嵌入会话并可展开，不另建独立历史页或教学页。具体线框见[界面原型](../software/prototype/README.md)。

| 单元 | 内容与跳转 |
| --- | --- |
| 首页/欢迎 | 选择岗位、难度、技术问答/项目深挖/HR/综合类型；开始进入配置，记录入口进入个人中心，帮助解释流程 |
| 面试配置 | 确认 JD、时长、可选代码、风格及默认实时语音方式；检测麦克风、可选摄像头和明确的复盘媒体保存选项；从个人库选简历与重点经历，可临时上传/手填/跳过，完成后直接开始 |
| 面试会话 | 左侧 AI 提问与追问、播报/题干；右侧口头作答状态、识别字幕、可选镜头预览及代码，文本降级时才显示文本提交；顶部/辅助区显示计时、主问题进度、暂停/跳过/结束，不显示实时能力评分 |
| 代码面板 | 语言、编辑器、用例输入输出、运行和提交；支持会话内展开；提交后围绕思路追问，详细评审在面后展示 |
| 分析报告 | 突出总分、四维覆盖和右侧数据；逐题回答/点评/参考、优势/薄弱点、独立语音/可选视觉观测及问题片段定位、重练、重新面试、PDF；媒体未保存或过期时明确不可回放 |
| 个人中心 | 面试记录、简历库、偏好；未完成进入继续，已结束进入报告，简历选择与配置页共享同一库 |

无需“保存记录”才持久化；报告可展示“已保存”。首页条件传入配置，最终以用户确认配置为准。主问题进度是当前题/本次题数上限，动态提前结束时不将未问的题算作已覆盖。

## 4. 材料选择与事实确认

- 库内简历采用 `library`，原文件与版本私有保存至用户删除。支持多份命名，例如“后端岗专用”。只有库内已确认版本可设为默认。
- 临时上传采用 `temporary`，默认不入库；原文件及提取草稿自上传起最长 24 小时，用户可选择保存入库。确认经历、回答及会话快照独立按记录策略保留。
- 简历解析不自动确认事实。手填经历也需明确确认；未确认、解析失败、过期或不支持的文件均不阻断手填/无材料路径。
- 每次明确选择一份简历版本及其经历，或明确选取独立手填经历；不自动混用不同简历。选定材料开始前变更须重新确认，开始后冻结快照，未来修改不改写旧面试。
- 重点经历允许课程项目、比赛、科研、毕设及实习。结果、商业数据均可为空，不能据此判低分；模型追问缺失依据，不替学生补数字、技能或因果关系。
- 学生回答中新提供的信息保留为回答证据；若需写回经历库，必须另行确认，不由 Agent 自动修改。
- 主动删除简历文件/提取稿保留独立确认经历并解除来源关联，界面先告知；删除经历或会话另列关联影响并确认级联。临时到期只清文件与提取稿。

上传、版本及删除细则以[数据与接口](../software/data_and_interfaces.md)为准。

## 5. 面试行为与异常处理

面试默认 10 分钟，可选 5 分钟；最多 6 个主问题，每个最多 2 次追问。到目标时间提示收尾，不直接截断当前回答；自开始累计 12 分钟含暂停到达安全上限时取消生成/采集并保存已持久化的完整回合/已提交文本，未完成临时片段不得静默当作完整回答评分。学生可主动提前结束。暂停停止生成、播放与采集，硬上限继续计时。

实时语音允许学生思考、口头自纠、要求澄清及打断 AI；默认风格不主动施压打断，主动打断只在用户选择对应风格后启用。系统根据语音活动和回合状态判断结束，自动冻结并保存回答后自然接续，不强迫学生编辑字幕或点击发送。误判结束时提供恢复追加口头内容入口，取消尚未稳定的后继生成，保留追加前后版本和回合关系；不得重复入账、播放或丢掉已保存内容。

默认选择实时语音仅为配置，明确点击开始并完成浏览器授权后才启动采集；摄像头和复盘媒体保存默认关闭，分别明确选择。面试中仅展示字幕、设备质量、连接和保存状态等运行信息，表达反馈与点评在面后开放。

字幕仅呈现识别结果，不生成润色稿替换原始口头回答。面后 ASR 纠错保留原识别、修订原因与版本，相关报告/比较标记过期再按明确版本更新；新增事实或新回答应作为补答或重练保存，不冒充原口头表达。复盘同时区分识别问题、内容缺口和语音观测，不能把 ASR 错字当作技术错误。

追问围绕项目目标、本人负责部分、实现细节、方案比较、遇到的问题、验证和协作，结合岗位要求，允许材料不足时进入通用技术问答。面试中不展示参考答案、答题框架、证据报告或实时能力分数；澄清题意不演变成提示。跳过不自动给零分；缺少证据的维度标记未观察。

完整语音回合或提交文本保存后才进入下一步。离页/断线回到个人中心可继续服务端未结束记录；若已达硬上限则结束并根据有效回答生成报告。切换为 `text_fallback` 时保留已存回合并记录每个回答的方式，文本可独立完成。报告采用 `pending/generating/ready/failed`，等待和失败均有明确状态，失败可独立重试，不能重跑整场冒充恢复。

代码运行失败、超时与测试未通过分开描述；语言/资源不支持时提示可继续文字解释或关闭代码考核。未接入执行服务时，“模拟运行结果”须显著标注且不得作为真实代码执行证据或能力分数依据。执行时限等规则集中在数据/模块设计，不由 Agent 任意放宽。

## 6. 报告与重练规则

| 维度 | 公共字段 | 观察依据 |
| --- | --- | --- |
| 专业知识 | `technical_knowledge` | 技术概念、实现解释、方案选择及理由 |
| 项目表达 | `project_communication` | 项目背景、个人贡献、行动、结果依据和岗位关联 |
| 代码能力 | `coding_ability` | 已提交代码、可信运行证据及算法/实现解释；未考查不评分 |
| 逻辑表达 | `logical_expression` | 回答结构、因果衔接和回应问题的清晰程度 |

每维 `score` 为 0～100 或 `null`，未观察时状态为 `not_observed` 并说明原因。总分为已观察维度等权平均后四舍五入到整数，注明观察维度和适用范围；全部未观察或零有效回答时总分为 `null`，展示“不评分”。没有代码题不得把代码能力记零，不能将无实习、无商业指标当作能力缺陷。评分锚点与误差待人工校准，不输出录用概率、排名或真实经历鉴定。

每条核心点评应关联回答原句、代码位置或可信测试结果，说明具体缺口和下一次动作。针对学生经历的参考表达只用已确认事实；通用知识参考答案标来源，不变成学生履历。报告记录每个回答的作答方式，区分已观察错误、未回答、中断和跳过；中断原因未知时不推断作答意愿或能力。

语音/视觉观测独立于四维总分。语速、停顿、疑似口头语、音量和音高变化须有窗口及依据；视觉只描述可观测面部动作、头部朝向、画面质量，不诊断情绪、不判断诚实/人格/能力，不把看向镜头外等同缺少眼神交流。相机拒绝或画面不足时视觉不可观测，文本方式无语音时语音不可观测，不生成替代指标。可关联同一片段的内容与表达，但不能仅因同时发生就断言因果。

原始音视频默认临时处理后清除；用户明确开启复盘媒体保存才可私有保留，自采集起最长 24 小时，重连或报告重试不重置期限。时间戳和派生观测可依个人记录策略保留；未保存或过期后，报告保留文字定位和观测依据，但回放/依赖原媒体的重算不可用，不能以生成内容伪造原片段。

同题重练创建新的模拟会话，关联原会话、问题、报告、目标时间片段及明确的回答版本；面试仍不提供实时提示。比较列出原回答、新回答、目标缺口、内容及可观测表达的变化依据，区分新增事实、修改表达和评分条件改变。作答方式、录音条件、观测算法或可用媒体变化均注明可比性限制，不把文本改写与即兴口头作答直接等同。原媒体过期不阻断按保留文本进行内容重练，也不能伪造表达比较。同类新题验证放后续与评测，不写成首版已具备的迁移效果。
