# 功能需求规格

版本：v0.5 · 更新：2026-10-19 · 状态：产品目标与验收基线；文字原型可运行，真实服务待接入。

## 2026-10-19 范围增补

岗位覆盖已扩展至1000个计算机相关方向，包含AI/大模型、数据、产品、交互、基础设施、机器人与游戏。新增岗位库/详情和个人目标岗位（收藏模板及个人JD）；个人中心以概览、简历、记录、目标和偏好组织，多份简历支持文本维护及独立经历。

当前实现为本地交互演示，公共岗位内容有来源与版本；真实认证、上传、数据库、实时语音和专业评分仍待接入。下文原生产目标与优先级保留，实际已实现范围以[扩展记录](../software/prototype/library-expansion.md)为准。

## 1. 范围与优先级

InterviewLab 面向实习经历有限、主要拥有校园项目、比赛、科研或毕设经历的学生，首版覆盖中文计算机相关岗位（含 AI、数据和产品）。主流程为“直接实时口头模拟面试 → 面后分析 → 同题定向重练”，配置不是教学前置关卡。首版默认 `realtime_voice`，`text_fallback` 可独立完成，报告标明实际作答方式。能力定位见[问题定义](problem_definition.md)。

保留需求编号，优先级按新实现阶段调整：P0-A 对应新实现阶段 1（真实文字闭环）和 2（材料/内容完善），P0-B 对应阶段 3（实时语音及独立语音观测），P1 对应阶段 4 的可选能力或后续验证。原阶段 C 的效果评测贯穿各阶段回归并在稳定后开展试用。当前已有明确标注合成数据的可交互原型；原型结果不能作为真实模型评审、代码执行或实测效果。独立后端采用 Fastify、Drizzle/PostgreSQL、Better Auth 和 pg-boss，具体职责与四阶段见[架构](../software/architecture.md)。本轮仅更新文档，不安装依赖或迁移代码。第一阶段专业反馈先提供有证据的分析，评分标准校准后才启用数值。

## 3. 页面与入口

页面包括首页、岗位库/详情、面试配置、会话、分析报告和个人中心五个分区；代码面板嵌入会话并可展开，不另建独立历史页或教学页。具体线框见[界面原型](../software/prototype/README.md)。

| 单元 | 内容与跳转 |
| --- | --- |
| 首页/欢迎 | 选择岗位、难度、技术问答/项目深挖/HR/综合类型；开始进入配置，记录入口进入个人中心，帮助解释流程 |
| 面试配置 | 确认 JD、时长、可选代码、风格及默认实时语音方式；检测麦克风、可选摄像头和明确的复盘媒体保存选项；从个人库选简历与重点经历，可临时上传/手填/跳过，完成后直接开始 |
| 面试会话 | 左侧 AI 提问与追问、播报/题干；右侧口头作答状态、识别字幕、可选镜头预览及代码，文本降级时才显示文本提交；顶部/辅助区显示计时、主问题进度、暂停/跳过/结束，不显示实时能力评分 |
| 代码面板 | 语言、编辑器、用例输入输出、运行和提交；支持会话内展开；提交后围绕思路追问，详细评审在面后展示 |
| 分析报告 | 突出总分、四维覆盖和右侧数据；逐题回答/点评/参考、优势/薄弱点、独立语音/可选视觉观测及问题片段定位、重练、重新面试、PDF；媒体未保存或过期时明确不可回放 |
| 岗位库/详情 | 搜索、方向/阶段筛选、收藏、查看 JD/主题/问题/来源，携带模板或复制为个人 JD |
| 个人中心 | 概览、简历、面试记录、目标岗位、偏好；未完成进入继续，已结束进入报告，简历选择与配置页共享同一库 |

无需“保存记录”才持久化；报告可展示“已保存”。首页条件传入配置，最终以用户确认配置为准。主问题进度是当前题/本次题数上限，动态提前结束时不将未问的题算作已覆盖。

## 4. 材料选择与事实确认

- 库内简历采用 `library`，原文件与版本私有保存至用户删除。支持多份命名，例如“后端岗专用”。只有库内已确认版本可设为默认。
- 临时上传采用 `temporary`，默认不入库；原文件及提取草稿自上传起最长 24 小时，用户可选择保存入库。确认经历、回答及会话快照独立按记录策略保留。
- 简历解析不自动确认事实。手填经历也需明确确认；未确认、解析失败、过期或不支持的文件均不阻断手填/无材料路径。
- 每次明确选择一份简历版本及其经历，或明确选取独立手填经历；不自动混用不同简历。选定材料开始前变更须重新确认，开始后冻结快照，未来修改不改写旧面试。
- 重点经历允许课程项目、比赛、科研、毕设及实习。结果、商业数据均可为空，不能据此判低分；模型追问缺失依据，不替学生补数字、技能或因果关系。
- 学生回答中新提供的信息保留为回答证据；若需写回经历库，必须另行确认，不由 Agent 自动修改。
- 主动删除简历文件/提取稿保留独立确认经历并解除来源关联，界面先告知；删除经历或会话另列关联影响并确认级联。临时到期只清文件与提取稿。

上传、版本及删除细则以[数据与接口](../software/data_and_interfaces.md)为准。

## 5. 面试行为与异常处理

面试默认 10 分钟，可选 5 分钟；最多 6 个主问题，每个最多 2 次追问。到目标时间提示收尾，不直接截断当前回答；自开始累计 12 分钟含暂停到达安全上限时取消生成/采集并保存已持久化的完整回合/已提交文本，未完成临时片段不得静默当作完整回答评分。学生可主动提前结束。暂停停止生成、播放与采集，硬上限继续计时。

实时语音允许学生思考、口头自纠、要求澄清及打断 AI；默认风格不主动施压打断，主动打断只在用户选择对应风格后启用。系统根据语音活动和回合状态判断结束，自动冻结并保存回答后自然接续，不强迫学生编辑字幕或点击发送。误判结束时提供恢复追加口头内容入口，取消尚未稳定的后继生成，保留追加前后版本和回合关系；不得重复入账、播放或丢掉已保存内容。

默认选择实时语音仅为配置，明确点击开始并完成浏览器授权后才启动采集；摄像头和复盘媒体保存默认关闭，分别明确选择。面试中仅展示字幕、设备质量、连接和保存状态等运行信息，表达反馈与点评在面后开放。

字幕仅呈现识别结果，不生成润色稿替换原始口头回答。面后 ASR 纠错保留原识别、修订原因与版本，相关报告/比较标记过期再按明确版本更新；新增事实或新回答应作为补答或重练保存，不冒充原口头表达。复盘同时区分识别问题、内容缺口和语音观测，不能把 ASR 错字当作技术错误。

追问围绕项目目标、本人负责部分、实现细节、方案比较、遇到的问题、验证和协作，结合岗位要求，允许材料不足时进入通用技术问答。面试中不展示参考答案、答题框架、证据报告或实时能力分数；澄清题意不演变成提示。跳过不自动给零分；缺少证据的维度标记未观察。

完整语音回合或提交文本保存后才进入下一步。离页/断线回到个人中心可继续服务端未结束记录；若已达硬上限则结束并根据有效回答生成报告。切换为 `text_fallback` 时保留已存回合并记录每个回答的方式，文本可独立完成。报告采用 `pending/generating/ready/failed`，等待和失败均有明确状态，失败可独立重试，不能重跑整场冒充恢复。

代码运行失败、超时与测试未通过分开描述；语言/资源不支持时提示可继续文字解释或关闭代码考核。未接入执行服务时，“模拟运行结果”须显著标注且不得作为真实代码执行证据或能力分数依据。执行时限等规则集中在数据与接口设计，不由 Agent 任意放宽。

## 6. 报告与重练规则

| 维度 | 公共字段 | 观察依据 |
| --- | --- | --- |
| 专业知识 | `technical_knowledge` | 技术概念、实现解释、方案选择及理由 |
| 项目表达 | `project_communication` | 项目背景、个人贡献、行动、结果依据和岗位关联 |
| 代码能力 | `coding_ability` | 已提交代码、可信运行证据及算法/实现解释；未考查不评分 |
| 逻辑表达 | `logical_expression` | 回答结构、因果衔接和回应问题的清晰程度 |

每维 `score` 为 0～100 或 `null`，未观察时状态为 `not_observed` 并说明原因。总分为已观察维度等权平均后四舍五入到整数，注明观察维度和适用范围；全部未观察或零有效回答时总分为 `null`，展示“不评分”。没有代码题不得把代码能力记零，不能将无实习、无商业指标当作能力缺陷。评分锚点与误差待人工校准，不输出录用概率、排名或真实经历鉴定。

每条核心点评应关联回答原句、代码位置或可信测试结果，说明具体缺口和下一次动作。针对学生经历的参考表达只用已确认事实；通用知识参考答案标来源，不变成学生履历。报告记录每个回答的作答方式，区分已观察错误、未回答、中断和跳过；中断原因未知时不推断作答意愿或能力。

语音/视觉观测独立于四维总分。语速、停顿、疑似口头语、音量和音高变化须有窗口及依据；视觉只描述可观测面部动作、头部朝向、画面质量，不诊断情绪、不判断诚实/人格/能力，不把看向镜头外等同缺少眼神交流。相机拒绝或画面不足时视觉不可观测，文本方式无语音时语音不可观测，不生成替代指标。可关联同一片段的内容与表达，但不能仅因同时发生就断言因果。

原始音视频默认临时处理后清除；用户明确开启复盘媒体保存才可私有保留，自采集起最长 24 小时，重连或报告重试不重置期限。时间戳和派生观测可依个人记录策略保留；未保存或过期后，报告保留文字定位和观测依据，但回放/依赖原媒体的重算不可用，不能以生成内容伪造原片段。

同题重练创建新的模拟会话，关联原会话、问题、报告、目标时间片段及明确的回答版本；面试仍不提供实时提示。比较列出原回答、新回答、目标缺口、内容及可观测表达的变化依据，区分新增事实、修改表达和评分条件改变。作答方式、录音条件、观测算法或可用媒体变化均注明可比性限制，不把文本改写与即兴口头作答直接等同。原媒体过期不阻断按保留文本进行内容重练，也不能伪造表达比较。同类新题验证放后续与评测，不写成首版已具备的迁移效果。

### 9.1 岗位库、收藏与个人 JD（FR-01/11）

平台模板与个人 JD 分开维护；岗位库覆盖 1000 个方向，支持名称/技能搜索、分类、实习/校招筛选、收藏、备注与常用简历。详情展示通用 JD、主题、平台整理题、来源和复核日期。支持携带模板进入配置，以及复制成个人 JD；未发布或失效模板不能用于新会话。

#### 目标与交互

把前端、后端、算法、测试等岗位 JD 转成可核对的职责、技术要求与可能的面试主题，帮助学生选择可讨论的真实项目。系统不输出录用概率，不把所有学生都假定为缺少实习，也不把某公司的 JD 扩写成通用招聘标准。

首页选岗位、难度与面试类型；配置页可使用团队发布的通用模板或粘贴JD。展示原文、结构化要求及解释，学生确认或修正后直接开始实时口头模拟，文本替代仍可独立完成。岗位解释可展开查看，不强制完成岗位问答或材料整理课程。

内容区分“JD 明确写明”“岗位知识补充”“系统推断”。模板标通用参考及版本；“了解”不能升级为“精通”，“优先”不能升级为必需。面试主题建议不等同于该企业真实题库或能力权重。

#### 数据与处理

输入为岗位名、JD 或模板 ID/版本及当前用户上下文，输出 `JobTarget` 的职责、要求、来源片段、待澄清项与确认版本。个人经历不在本功能创建；“这个要求可用项目解释”不等于“学生已具备该能力”。

服务端校验空内容和长度，LLM 约束提取后核对原文片段，再按岗位/技术主题检索已发布知识。原 JD 与知识引用分别保留；检索不足可解释字面含义，不能伪造来源、企业规定或专业结论。JD 中的命令视为待分析数据，不获得工具或网络权限。

映射优先考虑学生可提供的经历证据：功能实现、技术取舍、测试或实验、协作分工。商业化指标、海量并发、真实用户规模仅在 JD 与经历确有相关依据时讨论，不要求课设编造生产指标。

相同目标修订与知识版本可复用分析；修订 JD 使未开始配置提示更新，但不能改写历史会话快照。缓存隔离当前用户，不通过模型 URL 直接读取外部页面。

#### 边界与失败

- JD 过短或冲突：保留原文与未知项，可显式改选模板；不能自动添加缺失要求。
- 未覆盖专业：说明资料不足，允许通用问答，专业评分只在有实际可判断回答时观察。
- 模型超时/结构错误：保存用户输入，允许有界重试或直接使用模板；错误结果不当有效分析。
- 版本变化：开始前要求重新确认所选目标；旧会话继续显示冻结版本。
- 越权、指令注入、无效引用：服务端拒绝或丢弃，不开放任意 URL、SQL 或他人目标。

### 9.2 简历与确认经历（FR-02）

当前文本简历编辑字段为基本信息、教育、技能、自我介绍与补充文本；经历可新增、删除、排序、确认个人贡献。复制生成独立简历和经历 ID，保存检查版本。无材料路径保持可用。

#### 目标与交互

让学生针对技术岗位维护不同简历，并把课程项目、比赛、科研、毕设或少量实习中的真实行动用于个性化追问。解析只是辅助录入；上传成功、解析成功和学生确认分别记录，均不构成系统对经历真实性的认证。

个人中心提供多简历上传、命名、预览、下载、删除、设默认。配置页先选择已有简历，也能临时上传或手填一段经历。补充材料不要求上传完整代码仓库、商业数据或全部履历；无简历仍能直接进入实时口头通用模拟，文本替代同样可独立完成。

流程为“校验与私有保存 → 异步提取 → 原文与候选核对 → 逐项确认 → 选择本次重点经历”。学生可确认一部分并忽略其余项，批量确认仅在能查看每项内容时提供。切换简历只列该版本已确认经历；其他简历和独立手填经历必须明确另选。

#### 数据与保存

`ResumeDocument` 包含 `name/version/is_default/storage_scope/parse_status`。`storage_scope=library|temporary`；`parse_status=uploaded|parsing|needs_confirmation|confirmed|failed`。仅 library+confirmed 当前版本可设默认，同一用户至多一份默认；删除默认后清空，不自动另选。

| 范围 | 保存与选择规则 |
| --- | --- |
| library | 私有保存至主动删除，可再次预览和下载，不受临时 24 小时清理影响 |
| temporary | 配置页上传默认值，不自动入库；自上传起最长 24 小时，已确认不等于入库 |
| 显式转入库 | 有效期内显式转入库，改 scope 并清除 expires_at；目标接口为 PATCH /resumes/{id}；已清理文件不可恢复 |

文件替换产生新版本并重新核对，不能覆盖历史快照；解析失败也可删除文件或转为手填。暂存到期后独立确认经历与必要会话快照按各自策略保留，源原文显示已不可用。

`Experience` 保存 `kind/personal_role/actions/technical_decisions/results/evidence_refs/confirmed/version`，来源关联简历 ID 与版本；独立手填来源可为空。kind 包含课设、比赛、科研、毕设、实习及其他。缺少量化结果允许写产物、测试、实验或未知；团队结果与本人行动分开，参考表达不能新增“独立完成”“增长 X%”等未确认事实。

### 9.3 面试配置（FR-03/15）

#### 目标与交互

将首页意向和学生材料变为一场明确、可开始的模拟面试，不要求先完成经历整理课程或长期准备计划。首页预选岗位、难度、面试类型，点击开始后进入配置；配置页确认 JD、时长、代码考核、面试官风格、输入方式和本次使用的简历/经历。

简历区优先下拉/卡片选择个人中心的库内版本，显示名称、版本、默认标记及确认状态。可临时上传、显式入库或直接手填一段经历；“本次重点经历”只需轻量勾选。项目说明、本人职责及少量关键代码/材料为可选补充，无材料可通用问答。

开始按钮前展示本次目标、已选经历和资料缺口；提示缺口不拦截通用模拟，也不以“必须量化成果”要求编造数据。不设置教学/模拟切换，不提供实时评分开关，评分在面后集中展示。

#### 配置合同

| 项目 | 首版约定 |
| --- | --- |
| 模式/面试类型 | mode 仅 mock；technical_qa / project_deep_dive / hr / mixed |
| 岗位 | 前端、后端、算法、测试等技术方向；JD 或明确标注的通用模板 |
| 时长 | 5 或 10 分钟，默认 10；目标时长收尾，12 分钟含暂停安全上限 |
| 问题预算 | 最多 6 主问题、各最多 2 追问，实际数取决于回答与时间 |
| 简历与重点经历 | 所选简历 ID/版本、其已确认经历；手填/其他来源需显式选择 |
| 代码考核 | 默认关闭，可在配置开启；能力可用时嵌入面试，语言 C++/Python/Java |
| 风格 | 可选支持、平衡、深入追问等措辞风格，不改变事实边界、评分标准或轮次上限 |
| 交互模式 | interaction_mode 默认 realtime_voice，主动授权后直接说、端点自动提交；text_fallback 可独立完成且明确标注 |
| 可选镜头 | camera_enabled 默认 false；当场授权后采集，只作描述性面后复盘，不影响四维专业分 |
| 复盘媒体 | review_media_enabled 默认 false；分别说明音频/视频授权、私有保存及自采集起最长24小时，不保存也能获得可用派生观测 |

偏好只提供新配置的初值，学生可覆盖；不能悄悄改变进行中的会话。更改简历时重算候选并清理已失效选择，独立手填若仍保留必须清楚列出，不能混用其他简历的个人经历。

#### 数据流与开始事务

`POST /interviews` 创建 draft/ready，关联 `JobTarget`、`ResumeDocument`、`focus_experience_ids` 及所选版本。ready 只表示配置齐备；`start` 再校验归属、确认状态、版本和预算，事务内冻结材料、JD、知识/题目/标准/提示版本，进入 in_progress 后请求首题。

开始前资料变化返回版本冲突，展示差异要求重新确认；不能自动取最新材料继续。开始后不能换简历、类型或代码开关，需结束后新建会话。重练配置关联 `parent_session_id/parent_turn_id`，同样 mode=mock，不复活教学模式。

临时文件允许确认并用于本次会话，默认不入库。到期前已确认经历可独立保留；文件到期不伪装仍可预览。无可用材料时配置和会话明确标“通用问答，个性化有限”，不生成个人事实。

### 9.4 模拟面试（FR-05）

#### 目标与交互

围绕学生确认的课程项目、比赛、科研、毕设或实习进行连续提问，让学生独立解释个人贡献、技术决策、结果依据及岗位关联。系统 mode 仅 mock，进行中不提供答题框架、参考答案或逐题评分；学生可以澄清题意、重复、跳过、暂停和结束。

会话采用双栏空间：左栏为 AI 面试官状态、当前题与提问轨迹，右栏为学生实时回答和可展开代码编辑器。采用静态/简化面试官呈现，不要求真人视频或 3D；可选镜头为小预览。顶部/辅助区显示岗位、时间、主问题号与当前追问号及控制按钮，进行中不展示参考回答、表达点评或能力分。

每次只有一个待回答问题。默认实时口头作答：学生思考后直接说，端点确认自动保存原识别和片段轨迹，再自然生成追问/下一题；不编辑转写后发送。允许口头自纠、澄清、打断AI和误截后的口头追加。text_fallback 可独立完成并标注模式。退出后可在个人中心找到未完成记录继续；会话结束转到报告生成状态页，ready 后展示分析。

#### 数据、预算与状态

开始事务冻结岗位、简历及重点经历版本，连同题库、标准、提示及模型版本保存。核心 `Session`、`Turn`、`AnswerSegment` 和状态以[数据与接口](../software/data_and_interfaces.md)为准；ASR 原识别、片段轨迹、面后识别纠错、完整问题和实际呈现/播放范围分开，不能润色替换原话。

| 约束 | 首版行为 |
| --- | --- |
| 时长 | 5 或 10 分钟，默认 10；目标时间提示收尾，不即时截断回答 |
| 安全上限 | 自start起12分钟总经过时间，包含暂停和断线；取消生成/采集，封存已保存内容及带缺口片段，未完成片段不静默当完整回答评分 |
| 题量 | 最多 6 主问题、各最多 2 追问；显示主问题号和追问号，不伪称固定总题数 |
| 终态 | completed 不重开；failed 不改 completed，可对已保存回答请求部分报告 |
| 输入恢复/纠错 | 误截口头追加产生新revision并取消过早追问；面后仅ASR识别纠错，新revision使报告/比较/对齐过期 |

编排器控制 `draft/ready/in_progress/paused/ending/completed/failed`。暂停停止录音、生成及播放，不冻结 12 分钟安全时钟。可恢复服务故障优先转文本或有界重试，不立即把会话标 failed。

#### 提问与处理策略

根据 interview_type、JD 与本次经历建立问题覆盖表，主问题可来自发布题库并按材料改写。项目深挖优先问本人负责模块、技术选型、具体困难、实验/测试及协作；技术问答和 HR 面仍遵守材料边界。无材料使用通用题，不假装了解学生项目。

每次已保存回答后记录已回答信息与缺口，优先追问尚未说明的个人行动、技术原因或结果依据。已补充信息不反复追问，学生没有做过的事项可以询问理解或设想，但不变成“你曾独立完成”的前提。课设可用功能、实验、测试和产物说明结果，不强求商业收益或线上规模。

LLM 返回问题文本、目的、关联回答证据与建议动作，程序检查事实、题意重复、主/追问数量和剩余时间后执行。动作失败保留原已保存回答，不能重复保存或让模型自行放宽预算。澄清只解释题目所问，不暗示正确答案。

文本/语音共用提交与状态服务；端点候选可因继续说话撤销，短暂停顿不能直接判答完。`generation_id` 标识生成代；打断先停止本地队列，再取消服务端代，丢弃迟到文本/音频。AI主动打断仅可选风格。问题从未展示且未播放时不计已问；重连读取权威会话、已保存回合与时间预算，不自动重放全部帧，媒体缺口如实记录。

### 9.5 实时语音与独立表达观测（FR-06/14/17）

#### 目标与交互

让学生在连续对话中临场组织项目经历、解释技术选择并接住追问。默认 `interaction_mode=realtime_voice`：主动启用麦克风后，听题、思考、直接说、自动保存并自然接话。转写仅为字幕，不以编辑转写后发送作为主线。`text_fallback` 可独立完成，记录实际输入模式，不声称具有相同口语训练条件。

端点检测结合静音、识别稳定性和显式“回答完毕”信号，短暂停顿不立即判答完。学生可以思考、口头自纠、请求澄清、重复问题或打断 AI。误截后可继续口头追加到原回合，保存原片段、新片段和恢复事件，取消依赖旧回答的未完成后续代。AI 主动打断只在学生明确选择相应风格时使用。

摄像头默认关闭，开启需当场授权；无需摄像头也能完成全部专业面试。画面可选小预览，不设置常驻第三栏。面试中只显示采集、识别、播报与设备质量状态，不推送表达点评、能力评分或参考答案；完整语音/镜头反馈由服务端在面后开放。

声学指标的定义、参数与质量条件见[语音观测口径](../algorithm/knowledge_and_agent.md#speech-metrics)。

#### 处理、取消与保存

浏览器分片采集 → Fastify 实时接入鉴权 → ASR 与端点确认 → 自动封存原作答 → 会话编排 → LLM → 分句 TTS → 有界播放队列。可选视频走独立质量/动作观测任务，不阻塞接话。编码、采样率、视频抽样和分段格式由适配层协商，供应商延迟、中文术语、取消、费用与数据条件均须实测。

前后端共同维护有效generation。打断先停本地播放、清队列，再取消服务端代；旧文本/音频不得重新展示。暂停、关闭和离开页面停止采集与播放；断线保存已收妥片段和缺口，重连重新鉴权、读取权威状态，不盲目补发全部帧。finish或12分钟安全上限优先于重连与迟到观测，未完成片段不静默当完整有效回答评分。

运行设置经 `PATCH /interviews/{id}/interaction-settings` 或 `interview.interaction.settings` 统一处理：可切text_fallback、关闭/分别重新授权镜头或媒体保存，携version、原因和授权版本。服务端返回 `interview.interaction.updated` 并保留事件；关闭立即停对应采集/写入，使旧capture generation失效并丢迟到帧。重新授权只处理后续片段，不延长已有媒体期限；关闭媒体保存不影响必要临时识别，删除已有媒体另有明确入口。

默认原音视频只作临时处理，完成后清除。开启 `review_media_enabled` 时，音频/视频须分别说明并授权，私有保留自采集起最长 24 小时，可提前删除；媒体不进入长期备份。时间定位、派生观测可以保留，但媒体过期后显示“原媒体不可用”，不能伪造回听或重算。无原媒体且无可靠对齐时相关指标标过期或不可用。

### 9.6 报告与导出（FR-08/16）

#### 目标与页面

帮助学生看清“哪段回答暴露了什么问题、已有何种事实支撑的优势、下一次怎样改”，同时说明观察不足。报告分析本次表现，不把缺少实习或商业成果视为能力差，不生成录用概率或人格判断。

结束后进入同一报告页的 pending/generating 状态，ready 时展示总分与覆盖、四维反馈、逐题复盘、薄弱点与单题重练。界面在右侧更突出维度数据、证据和重点建议，左/中部保留问题、本人回答及定位，避免数字脱离上下文。未考查项清楚显示“未观察”。

逐题复盘包含原题、原始作答轨迹及识别纠错版本、Agent点评、依据及参考表达；参考表达仅在面后出现，并限定于已确认事实。关联具体回答与时间片段，展示原媒体是否仍可回放；媒体到期不伪造播放。无足够材料时用待补充问题或有标记的通用示例，不能编写虚构个人履历。操作为PDF导出、重新面试、单题重练；记录已自动保存。

#### 评分和分析合同

| 维度 | 观察对象 | 未观察示例 |
| --- | --- | --- |
| technical_knowledge 专业知识 | 被实际问到的概念、机制、技术推理及正确性 | 未出现可判断技术回答 |
| project_communication 项目表达 | 本人职责、具体行动、技术决策、结果依据与岗位关联 | 未讨论个人项目/经历 |
| coding_ability 代码能力 | 实际代码/代码考核的实现、边界、复杂度、验证 | 未开展代码考核或无有效作答 |
| logical_expression 逻辑表达 | 回答的问题对应性、结构、因果与解释清晰度 | 无足够可判断回答 |

每维 `status=observed|not_observed`，未观察项必须 score=null。报告标记 `scoring_status=uncalibrated|calibrated`；未校准时即使有可观察回答也只分析证据，四维及总分为空。校准后已观察维度为 0～100 整数，总分取这些维度等权均值四舍五入（.5 向上），未观察不进入分母，并展示覆盖及限制。零有效回答或无已观察维度时不评分。评分标准版本冻结，不能将模型自信视为可靠性。

专业总分不包含语速、停顿、疑似口头语、音量/音高变化及可选镜头观测。独立区显示质量、覆盖、对齐、口径和建议；视觉仅描述画面质量、头部朝向与面部动作，低置信标unavailable，不推断情绪、诚实、人格或技术能力。摄像头关闭不扣分。代码运行结果与Agent对代码/思路的评审分开，静态评审不能写成运行通过。

每条优势和不足关联已保存回答 revision、精确引文或代码/执行位置，分别审查个人贡献、技术选择、结果依据、岗位关联。团队获奖不自动证明个人算法能力，课设没有用户量不构成缺陷，材料缺口与知识理解错误分开描述。

#### 生成、版本与导出

finish 先封存会话和已保存作答文本，再创建唯一报告任务，`pending → generating → ready|failed` 与 Session 终态独立。失败保留回答供重试；failed 会话若有确认内容可生成标记 is_partial 的部分报告并保持失败终态。跳过/提前结束报告说明覆盖，不补齐未观察分数。

生成器分步抽取证据、按冻结标准评价、给可执行建议，然后校验所有引文确在相应已保存作答文本/代码版本中。出错可在有预算且无成功结果时有界重试一次；仍缺依据时保守输出或失败，不发布伪引文。模型、知识和提示版本随报告保存。

面后ASR识别纠错或代码修订创建新revision，旧报告保持可追溯但标过期；原口头回答不能被润色替换。报告绑定回答与观测版本摘要，新增观测也须检查依赖；新任务提交前复核版本与删除状态，旧任务不能覆盖当前版本。报告须纳入口头自纠、误截追加与追问补充，可区分“首答缺少”与“整场仍缺少”。

PDF 由报告固定版本异步导出，包含观察覆盖、部分/过期标记、维度、复盘与限制，不能导出时伪称完整 ready。私有临时文件默认生成起最长 24 小时，下载再鉴权；删除报告/会话撤销下载并清理文件。

### 9.7 同题重练与比较（FR-09）

#### 目标与交互

把报告里的一个明确缺口转成下一次独立作答，例如“首答讲清本人负责模块”或“解释技术选择的依据”。首版同题重练共用模拟会话界面，`Session.mode=mock`，不先进入教学课程，也不在作答过程中提供框架、参考答案和即时评分。

学生面后选择目标，查看来源题、原回答版本/具体片段、报告依据与已确认事实，可隐藏原回答后开始。默认继续实时口头作答；新回答单独保存，完成后并列展示两份原作答、识别纠错版本、具体变化、仍存在的问题与限制。学生可以再次重练，不自动只展示最高分或把背熟原题说成掌握能力。

个人中心记录显示原面试与重练的关联；报告或记录入口能回看比较，不独立建立历史页或强制长期课程。自动同类新题推荐属后续，阶段 C 可人工安排同类新题评测迁移。

#### 数据与可比性

创建新会话关联 `parent_session_id/parent_turn_id`、来源题意、原 turn/revision、报告版本（如有）、目标缺口、岗位/经历快照和共同评分标准。原题与原回答不覆盖，新的 Session/Turn 仍走身份、确认、计时和限额逻辑；单题会话通常完成一次回答及必要澄清，无须凑满六题。

`RetryComparison` 必须指定两份 turn ID 与 revision，而非默认取最后回答；包括原/新引用、已改善/仍存在/新增问题、事实变化与不可比原因，`pending → generating → ready|failed`。回答纠正令关联比较过期，任务提交检查输入摘要、归属和删除状态。

共同评价标准支持内容对比，不强制算“提升百分比”。材料、岗位、题意、标准或练习前参考内容变化时说明限制；标准不同不混算分数趋势，事实新增不能全部归为表达进步。语音/镜头观测必须输入模式、设备质量、覆盖和算法口径可比，不能与专业总分合并成“进步指数”。文本替代与实时口头回答可比较内容，但不得直接比较语音变化；媒体到期仅剩观测时如实标注不能回放或重算。

#### 处理与建议

优先选来源报告有确切回答证据、可在一次作答中观察的缺口。报告失败时可由学生从已确认题和回答手动选择目标，不伪造原报告评分。开始时校验来源可访问、版本有效，再冻结到新 mock 会话。

比较先抽取两份回答里的个人行动、技术理由、结果依据与岗位联系，再校验双方引文后生成解释。变长但无新信息应明确“仍未解释原因”；数字或职责改变需提示事实差异、由学生确认，不能立即奖励分数。新补充事实独立确认并记录，默认不回写原简历/原回答，也不把新事实作为已外部核实结论。

进展优先汇总练过的主题、反复出现的缺口和有证据的变化。完成次数、字数、同题涨分和模型自评不能证明真实求职能力提升；不同标准的报告不合并趋势，未观察维度不当零分。真正迁移需同类新题和独立评审，不能用同一模型认可自身建议代替。

### 9.8 内容维护与运行管理（FR-11）

#### 目标与范围

2026-10-19 增补：当前已建立[结构化岗位内容库](../algorithm/content/README.md)，包含来源索引、模板/问题版本、首稿归档和结构校验/到期复核清单。实际审核身份、后台页面、数据库和索引任务仍未接入；本轮是公开资料交叉核对与平台原创整理，不代表完成专家校准。

维护技术岗位知识、学生项目问题、评分标准和事实边界，并能定位解析、会话、语音、报告及代码服务故障。首版为团队受限维护能力，可先用授权脚本，不建设教师管理、人才筛选或学生监控系统。

维护权限不自动获得学生原始简历、回答、音视频和复盘媒体。内容质检优先使用合成课设、比赛、科研、毕设和少量实习样例；真实材料的研究/人工质检需要单独明确授权，排障角色不等同研究许可。

#### 内容工作流与数据

流程为“登记来源与适用范围 → 编辑/导入草稿 → 切分/检索预览 → 题目/评分抽检 → 发布新版本”，内容状态 `draft → reviewed → published → retired`。未发布或撤回内容不进入新检索，回滚只改变新会话默认版本，不原地篡改旧会话依据。

| 对象 | 维护字段和发布要求 |
| --- | --- |
| 岗位知识 | 来源标题/地址、授权、获取/审核日期、适用技术岗位、正文及版本 |
| 项目追问题 | 适用经历类型、题意、个人职责/技术选择/结果依据/岗位关联目标、追问边界与版本 |
| Rubric | 四维 0～100 锚点、observed/not_observed、证据要求、正反样例与版本 |
| 代码题 | 题干、语言、示例/测试版本、参考解依据、执行资源配置版本 |
| 实时与观测配置 | ASR/端点/算法版本、误截恢复、语速/停顿/疑似口头语、音量/音高变化、视觉描述范围、质量规则及验证记录 |
| 竞品研究 | 官方能力事实、用户自述、机会假设分栏；记录模块、日期与来源偏差，不直接变成产品证明 |

评价样例覆盖“团队获奖但个人贡献有限”“本地课设无商业指标”“科研结论有实验限制”“只有少量实习”等情况。个性化优势必须能回到回答和材料，不能奖励虚构商业成绩。

### 9.9 可选代码考核（FR-13）

#### 目标与交互

让需要代码考核的技术岗位面试在同一会话中展示实现、验证和思路；项目表达面试可关闭此能力。面板嵌入作答区，可展开或弹窗展示，不成为独立必经页面。提供 C++、Python、Java 选择、语法高亮、输入/期望输出/实际输出、运行与正式提交。

题干支持文字、受控代码片段及已授权图片。图片URL来自受权资源服务，不能执行模型生成的任意链接；渲染统一转义/过滤。代码允许编辑草稿，与实时口头回答不可润色替换的规则分开；讨论思路的口头片段仍保留原始轨迹。语言切换保留各语言草稿或提示未保存变化，不能覆盖已正式提交版本，提交/执行状态分别记录。

运行只针对明确提交 revision 与输入，显示队列、执行、超时/错误及逐例结果。正式提交后 Agent 可内部分析边界、复杂度等以选择追问；不必先运行，没运行则清楚说明“未执行”。面试中仅提不泄露答案的问题，详细漏洞点评、改进建议、评分和参考实现均在面后复盘展示。

#### 数据与执行结果

| 对象 | 保存内容 |
| --- | --- |
| CodeTask | 会话内分配题、主问题/追问关联、题目/用例版本、支持语言、执行限额配置 |
| CodeSubmission | owner/session/task、language、source_code、revision、正式提交标记与时间 |
| CodeExecution | 提交 revision、输入/用例版本、queued/running/终态、execution_mode、资源用量、各例结果 |
| CodeReview | 提交/执行版本、代码位置与问题、思路点评、证据、标准/模型版本与异步状态 |

API 语言为 cpp/python/java，支持范围和运行时版本由服务能力返回，不在本文绑定未来编译器版本。`execution_mode=real|simulated` 必须显式；succeeded 表示执行任务完成，是否通过在用例结果中分别记录，不能与“全部测试通过”混用。

Agent 评价与执行结果独立。测试通过仅覆盖已执行用例，不保证正确性/安全性；静态点评可以指出候选问题，不得编造编译日志、耗时、内存或通过率。代码能力只有实际被考查且有足够可判断回答才 observed，未启用或无有效作答标 not_observed。

个人中心统一维护材料、目标与练习，采用左侧导航，手机为分区导航；记录自动保存，未完成继续、结束后查看报告，入口按权威状态和安全预算路由。
