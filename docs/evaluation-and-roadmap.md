# 评测、成本与迭代计划

版本：v0.1 · 日期：2026-10-03 · 状态：验收设计，尚无运行或教学效果测量结果。

本文将[需求分析](requirements.md)转为可执行的验证计划。质量门槛分为必须通过的业务/数据约束和需要在原型中检验的性能目标；没有供应商报价、真实试用数据或上线承诺。任何阶段都不能仅因页面可用或模型自评上涨就声称教学有效。

## 1. 评测对象与统一记录

分别评测完整学生流程、单个 AI 任务、实时语音与角色、数据访问及教学效果。完整链路测试负责发现模块衔接问题，独立任务测试负责定位岗位解释、检索、追问和反馈错误，两者互相补充。

一次测试保存样例 ID、样例版本、知识/题库/评分版本、提示与模型标识、检索配置、输入输出、错误类型、延迟及用量。真实学生材料不进入公共测试仓库；日常开发使用合成案例。需要真实样本时在明确用途与授权范围内去标识保存，并限定访问，不能因为“评测需要”复制所有简历。

AI 输出具有波动性：每个固定样例至少运行 3 次，报告通过数量、严重错误数和变化范围，而非只挑最好一份展示。延迟从浏览器和服务端分别记录；业务/服务异常导致的失败或取消计入故障率，但不混进成功延迟分布。学生主动跳过、结束或打断单独统计，不作为故障；取消失败、异常断线仍计为故障。报告 P50/P95、样本量、环境和供应商，不只报告平均值。

## 2. 可重复评测集

建立版本化评测目录，包含输入材料、期望行为、允许的不确定回答、禁止断言及人工判定表。将开发调参集与最终回归集分开；最终集只用于阶段验收，不能根据一次结果反复改标准。

| 集合 | 初始规模建议 | 覆盖内容与判定重点 |
| --- | --- | --- |
| 岗位解释 | 20 份合成 JD，覆盖运营、技术、设计、行政等初级岗位 | 原文要求、通用解释、推断分别标记；模板与自带 JD 冲突 |
| 材料处理 | 15 份合成 PDF/DOCX 或手填样本 | 多栏/表格、缺失日期、职责含糊、扫描件、空文件、受保护文件；失败应可手填 |
| 知识检索 | 60 条查询，含至少 15 条无有效资料查询 | 中文同义词、英文技能词、专业词、范围过滤、版本和过时材料 |
| 面试追问 | 30 组问题与回答 | 空泛、跑题、个人贡献混淆、已经说清、重复答案、跳过和材料不足 |
| 反馈与对比 | 30 组回答及重练对 | 引用准确、三维锚点、not_observed、新增事实与表达改进分别说明 |
| 对抗与越权 | 至少 20 个场景 | JD 指令注入、伪造资料 ID、跨用户 ID、异常工具参数、模型虚构引用 |
| 中文语音 | 30 段合成或授权音频，并加入实时打断场景 | 数字、否定词、英文技能词、近音专名、背景噪音和连续话语 |

规模是首轮可操作基线，后续根据错误类型补充；不能据此声称覆盖所有专业、口音或网络条件。每个评测项记录失败原因，例如何处遗漏 JD 条件、哪个引用失配，避免只留下“效果不好”。

合成贯穿案例固定为小林：初级产品运营 JD 关注活动执行、基础数据、跨团队；读书活动负责报名表、签到、群提醒，60 人报名、45 人到场，无独立 SQL 分析或增长贡献证据。首答“我负责组织活动，效果很好”，重练补充职责和人数。期望输出是指出信息更具体；禁止把 45/60 解释为增长归因、替小林添加 SQL 履历或预测录用。该样例既验证事实边界，也不能独占最终评测集。

## 3. 功能、AI与安全验收

### 业务与恢复路径

| 场景 | 通过条件 |
| --- | --- |
| 完整文本闭环 | 岗位 → 确认材料 → 准备 → guided/mock → 报告 → 重练 → 历史均可完成；关联原题和版本正确 |
| 无材料/解析失败 | 能跳过、手填或使用通用训练；草稿不被评价为已确认事实 |
| 模式区别 | guided 可提示，mock 不给参考答案；切换到教学创建关联会话并标记提示条件 |
| 提前结束/时长控制 | 保存已确认回合；mock 10 分钟提示收尾、12 分钟终止；guided 同样12分钟资源上限但不强制6主问题；含暂停且重连不重置预算 |
| 重复请求/任务重试 | 同一确认键不重复保存，结束不重复建报告，失败重试不发布两个活动报告 |
| 报告失败/转写纠正 | 训练记录保留；可重试报告；回答版本改变后旧报告标为失效并重新生成；failed会话有确认回答时可请求部分报告，保持终态 |
| 断线与重启 | 重连从已保存状态继续，暂停不重置预算；网关/任务进程重启不丢确认回答 |
| 删除 | 用户能删除材料与记录，关联快照/报告/任务清除；后台不能继续生成已删数据的报告 |

所有 P0 主流程与关键异常用例需通过，出现越权、确认回答丢失或无界费用调用时阻止进入下一阶段。

### AI质量

| 指标 | 计算或检查方式 | 文本阶段门槛 |
| --- | --- | --- |
| 检索有效召回 | 人工标注有依据查询中，前 5 候选含有效片段的比例 | ≥85%，同时报告各岗位/术语组结果 |
| 空检索处理 | 无依据查询不伪造来源，正确说明不足 | 回归集中全部通过 |
| 追问相关性 | 人工判断与岗位目标及当前回答有明确关联 | ≥90%；绕回同一问题或已答信息判无效 |
| 模式与预算遵守 | 自动检查模式、主问题/追问次数及计时，人工检查答案泄露 | 回归集中全部通过 |
| 引用有效性 | 引用 ID/版本存在，逐字文本匹配，且支持对应评价 | 程序校验全部通过；人工语义支持率≥95% |
| 个人事实边界 | 不添加未经确认的履历、数字、技能或成长归因 | 不允许发布含此类错误的报告；固定集不得有此错误 |
| 反馈可执行性 | 人工判断建议具体、依据明确、能转为练习动作 | ≥85%，提供未达标示例 |
| 未观察项处理 | 题目未触及、跳过或有效回答不足时正确标记 | 回归集中全部通过 |

百分比均以明确可判定样例为分母，并报告“不可判定”数量。自动校验负责来源/权限/结构等可机械判断的问题；人工仍要判断引用是否支持结论、提示是否有教学价值。高召回或结构化 JSON 通过不能替代语义正确性。

三维评分采用表达、岗位理解、经历证据的 1～4 档与 `not_observed`。随机抽取至少 20 份报告由两名评阅者独立按锚点评阅，记录相差两档以上的项目并讨论原因。首轮若一致性不足，先修订锚点、题目与提示，再扩大样本；不通过调整权重隐藏分歧。模型分数只用于本次训练反馈，不作为排名或招聘筛选依据。

### 访问、隐私与运行

使用账号 A/B 测试所有材料、会话、回答、报告和下载入口，替换资源 ID 也必须拒绝越权；检索不能返回其他用户记录。资料中的指令不能触发工具写操作、任意网络请求或密钥输出。检查浏览器包、响应、错误和日志无长期供应商密钥；日常日志仅记录必要 ID、版本、用量和错误摘要。

测试删除时仍在执行的解析/报告任务、服务重启后的任务重放以及备份恢复后的删除应用。原始音频默认不长期保存，检查缓冲清理，而不是仅在文案中声称如此。供应商处理与留存设置在选型后逐项核对，未完成者不使用真实学生材料试用。

监控完整会话失败率、报告失败率、工具错误、重复调用、每日用量、单会话费用和取消后残留调用。异常费用按配置限额停止新生成并提示可保存/稍后继续；故障告警可基于聚合记录，不将完整简历发往外部告警渠道。

## 4. 语音、3D与性能试验

ASR 先用标注音频计算中文字符错误率，并对人数、日期、否定词、英文技能词单独检查；后者对经历含义影响更大。初始目标是安静环境字符错误率≤12%，关键字段正确率≥95%，作为服务比较基线而非面向所有口音的保证。临时字幕与最终字幕须区别显示，错误转写可纠正，未确认临时字幕不参与报告。

语音测试覆盖说话中打断 TTS、模型仍在生成时打断、迟到音频、快速连续打断、麦克风拒绝、音频设备改变、浏览器播放限制和弱网重连。取消时旧 `generation_id` 的文本/音频不继续播放；保存生成问题与实际播放进度，不能将学生没听到的后半句当作已问内容。语音服务不可用时允许文本回答，避免丢弃已确认回合。

在目标部署网络、往返延迟 RTT≤100 ms、丢包率<1%、10 场并发下，采集至少 200 个有效回合，试验目标为：用户确认回答到首片面试官文本 P95≤5 秒，语音端点确认到首段可播放音频 P95≤6 秒。端点检测、LLM 首 token、TTS 首段和浏览器播放分别计时，说明是否包含检索。未达标优先定位慢段与队列，若仍无法达到，应调整产品目标并重新评审，不删除慢样本。

3D 验证待机、倾听、思考、说话状态与实际音频一致：角色不得在音频停止后持续说话；嘴型由播放的音频驱动，不能按生成文本计时假装同步。记录首次加载大小、加载时间、帧率及内存，至少测试一台普通集成显卡电脑与一个低性能场景。资源失败或性能不足时静态头像降级，字幕、结束和回答操作始终可用。3D 是否促进练习是教学/体验假设，不能仅凭动画可运行认定价值。

## 5. 服务商选型与成本估算

### 统一样例选择方法

LLM、ASR、TTS、嵌入分别使用适配层比较，不默认同一供应商全部最优。先筛选目标网络可达、处理地区及留存条件符合项目要求的服务，再用同一评测集和部署环境比较；开始实现时核验当前模型版本、能力限制与正式报价。

| 服务 | 统一测试方法 | 选择依据 |
| --- | --- | --- |
| LLM | 相同 JD、确认事实、检索上下文、评分锚点；记录实际 token | 事实/引用错误、追问与建议质量优先；再比较结构输出、取消、延迟、费用 |
| ASR | 相同音频、格式和端点设置；增加实时说话/打断 | 关键字段错误、临时/最终转写、端点延迟、恢复能力、计费方式 |
| TTS | 相同中文问题，含英文技能词、数字和标点 | 可懂度、自然度、首段延迟、分段边界、取消和浏览器播放兼容 |
| 嵌入 | 相同知识版本、切分和检索查询 | 有效召回、空检索误召回、维度/迁移成本、费用与速度 |

先执行固定质量门槛，再在通过的候选中比较 P95 和每场费用，不把所有项目随意加权成一个总分。评测者看不到供应商名称；未通过严重事实或数据要求的候选，不因价格低入选。保留一个经过同样验证的备选适配器；自动切换须记录模型变化，报告对比时说明。

### 费用模型与虚构算例

每场费用按实际计费单位计算：

`C_session = Σ(input_tokens × input_price / token_unit + output_tokens × output_price / token_unit) + ASR_usage × ASR_price + TTS_usage × TTS_price + embedding_cost + variable_storage/network_cost`

另计固定服务器、数据库/备份、带宽、角色素材与开发成本。包含失败、修复、重试、报告和重练调用，缓存优惠只有确实生效且有计费证据时才扣除；不能只算面试中的成功输出。

以下单价完全是假设数字，用于展示预算方法，**不是任何供应商的报价**：一场约 10 分钟，8 次面试 LLM 调用各 4,000 输入 token、350 输出 token，1 次报告 8,000 输入、1,200 输出；总计 40,000 输入和 4,000 输出。假设输入 2 元/百万 token、输出 8 元/百万 token，ASR 6 分钟按 0.03 元/分钟，TTS 800 字符按 0.10 元/千字符。

| 项目 | 假设计量与计算 | 假设费用 |
| --- | --- | --- |
| LLM 输入 | 40,000 / 1,000,000 × 2 | 0.080 元 |
| LLM 输出 | 4,000 / 1,000,000 × 8 | 0.032 元 |
| ASR | 6 × 0.03 | 0.180 元 |
| TTS | 800 / 1,000 × 0.10 | 0.080 元 |
| 上述调用合计 | 未含嵌入、重练、基础设施 | 0.372 元/场 |

若再假设 LLM 重试额外用量为成功 LLM 用量的 20%，增量为 0.112×20%=0.0224 元，调用合计约 0.39 元/场。这一比例也不是实测值。每月 1,000 场只能得到此组假设下约 394.4 元调用费，仍需加固定设施和其他用量，不能对外作为总成本承诺。ASR 是否按输入音频、静音或连接时长计费，TTS 是按字符、token 或音频秒计费，均以实际供应商条款和账单为准。

知识入库嵌入是内容更新成本，按来源版本计量，避免混入每场调用后重复计算。个人材料解析、岗位解读和重练应另按用户旅程计费。发布前进行 50 场以上代表性训练，比较应用用量与供应商账单，给出 P50/P95 费用，再确定限额。

## 6. 开发阶段与门槛

| 阶段 | 实现范围 | 进入下一阶段的门槛 |
| --- | --- | --- |
| A 文本闭环 | 受邀账号、岗位/材料、准备、两种模式、报告、重练、知识维护与监控 | P0-T 全链路和异常通过；AI固定集达到门槛；引用/事实/隔离无严重错误；完成删除与任务恢复测试 |
| B 语音闭环 | ASR、确认字幕、流式 TTS、取消、降级、实时网关 | 文本回归保持通过；转写与打断目标通过；目标网络延迟采样达标或经评审调整；完成50场费用核对 |
| C 3D交互 | 一位半身角色、四类状态、音频嘴型、静态降级 | 真实播放状态同步、弱设备/资源失败可用；不破坏语音与文本；素材使用依据明确 |
| D 小规模试用 | 学生自主完成旅程，收集体验、人工反馈与迁移表现 | 严重数据/事实问题修复后方可扩大；形成教学效果与3D价值的有边界结论，以及下一轮需求清单 |

不以未经验证的人天估算承诺日期。排期需要团队人数、角色素材、云服务接入条件与预算信息；任务优先级按上述阶段确定，每阶段由产品、技术和教学内容负责人共同确认验收记录。

试用前先由团队成员完成合成材料演练，再邀请约 12～20 名不同专业、不同准备程度的应届生进行可用性探索。该人数用于发现流程障碍和估计效应，不能自动支持广泛教学有效性结论；若后续准备开展正式对照研究，另立研究方案与样本量分析。

## 7. 教学效果与风险验证

前测让学生在无提示条件回答一组题；训练后用不同但同类的题做后测，并尽可能一周后进行延迟测试。题目围绕同一可观察能力、难度近似，控制顺序，避免把背熟原答案当作迁移。记录是否补充了新经历事实、是否使用提示以及练习次数。

两名熟悉面试教学的评阅者在看不到前后标签的情况下，用相同三维锚点评价去标识回答。记录一致性、分歧、缺失数据和具体改进证据。报告配对变化及其不确定性，并访谈学生能否解释岗位要求、理解建议、独立应用方法。没有对照条件的结果只能作为探索性证据，不能归因所有改善于 AI 系统。

如需判断 3D 的额外价值，可比较相同题目、模型和语音下的“语音+静态头像”与“语音+3D”，平衡体验顺序，观察重练选择、任务完成、分心和疲劳；教学质量条件保持一致。满意度、使用时间和模型分数分别报告，不合并成“学习有效”结论。

| 风险/假设 | 观察信号 | 优先应对 |
| --- | --- | --- |
| 学生跳过材料确认 | 退出或误确认多，事实纠错频繁 | 精简必要确认项、允许手填与通用练习 |
| 反馈正确但难以执行 | 反馈查看多、重练少，学生不知如何修改 | 改为一项具体任务，引用原句，减少泛泛建议 |
| 不同专业结果差异大 | 某类 JD 检索/追问错误集中 | 限定可支持岗位范围、补充审核知识与题库 |
| 模型版本变动 | 固定集出现新错误，费用/延迟突变 | 回归再发布，冻结配置并保留可回滚版本 |
| 语音干扰学习 | ASR纠错多、等待和打断失败 | 修复端点/播放，提供显式文本入口 |
| 3D增加负担 | 低性能设备降级多、学生分心 | 保留关闭角色入口，依据试用决定后续投入 |
| 评价引发误解 | 学生把低档理解为不会或录用概率 | 明确本次证据边界、展示未观察项与重练路径 |
| 费用异常 | 长上下文、重复任务、取消仍计费 | 调用预算、幂等、取消验证与账单核对 |

尚待验证的关键假设是：学生愿意提供并确认真实材料；岗位解释帮助确定训练目标；证据反馈能促成可迁移的改进；语音与3D的体验收益足以覆盖延迟、维护与费用。每个阶段记录支持或反驳证据，并据此修订下一版需求，而非把当前设计假设写成既定结果。
