# 需求分析

版本：v0.1 · 日期：2026-10-03 · 状态：立项与团队讨论基线，尚未实现。

## 1. 产品目标与边界

InterviewLab 是面向应届生的自主面试教学系统。学生通过 AI 理解目标岗位、整理真实经历、练习面试回答，并根据证据反馈反复练习。核心目标是提高岗位理解和可观察的面试表达能力，不以招聘决策或录用概率作为产品输出。

首版是中文 Web 应用，以语音和一位风格化 3D 面试官为最终体验；先完成文本教学闭环，再增加语音和角色。系统面向跨专业通用面试，覆盖自我介绍、项目/实习/校园经历、行为问题和基于材料的岗位理解，不承担跨行业专业资格认证或高级技术能力判定。

学生是唯一教学用户。维护人员只管理内容、权限和运行，不建设教师端、班级、课程作业、自动投递、支付、摄像头情绪识别、写实视频数字人或算法 IDE。岗位探索与实时招聘搜索不在首版范围内。

## 2. 用户画像与需求假设

以下画像是设计假设，不代表已完成访谈。立项后需用学生试用和访谈验证。

| 画像 | 当前状态 | 主要任务 | 常见障碍 | 所需支持 |
| --- | --- | --- | --- | --- |
| 初次准备面试的学生 | 有目标岗位但经验少 | 理解 JD，准备自我介绍 | 将岗位要求当作关键词背诵 | 用工作任务解释能力要求，说明为什么会被问 |
| 有项目经历但表达困难的学生 | 做过项目或校园活动 | 说清职责、行动与结果 | 团队贡献和个人贡献混在一起 | 根据回答追问，帮助整理可验证事实 |
| 已经面试过、需要改进的学生 | 有明确薄弱点 | 模拟面试并专项重练 | 建议泛泛，无法执行 | 原文证据、具体练习任务、前后对比 |

需求不是“得到标准答案”，而是知道岗位关注什么、自己能提供哪些经历证据，以及怎样把这些证据讲清楚。用户材料不足时，系统应帮助补充或选择通用练习，而非虚构一个完整履历。

## 3. 用户旅程与页面组织

主流程：岗位模板/自带 JD → 简历解析与确认 → 经历补充 → 岗位理解与准备重点 → 教学练习/模拟面试 → 反馈 → 单题重练 → 历史回顾。

| 阶段/页面 | 学生操作 | AI/系统响应 | 阶段完成标志 |
| --- | --- | --- | --- |
| 目标岗位 | 选模板，或粘贴 JD；确认目标 | 提取职责和要求，保留来源 | 保存一个岗位目标，明确模板与 JD 的区别 |
| 我的材料 | 上传简历，编辑提取内容，补充经历 | 标记缺失、歧义与待确认内容 | 可用材料由学生确认；也可跳过进入通用训练 |
| 岗位与准备 | 查看解读、提问、选择练习主题 | 解释工作任务，关联经历，给准备建议 | 学生知道此次训练的岗位要求和目标 |
| 练习室 | 选择模式、时长、文本/语音，回答 | 教学模式给予提示；模拟模式提问追问 | 正常完成或主动结束，保存有效回合 |
| 反馈页 | 查看回答、证据、建议，纠正转写 | 按维度反馈，标记未观察项 | 每项核心建议有可定位证据或说明缺失 |
| 重练页 | 针对一个问题重新回答 | 对比结构和新增信息 | 原回答、重练回答、变化说明可同时查看 |
| 历史页 | 回顾主题、继续练习、删除记录 | 呈现可比较记录和下一步建议 | 可找回一次训练，也能管理个人数据 |

补充路径：不上传简历可手动填写或通用训练；没有自带 JD 可用岗位模板；不熟悉岗位可先讲解再练习；拒绝麦克风权限或设备不支持 3D 时可继续文本训练。

## 4. 功能需求与优先级

P0-T 表示文本闭环必需；P0-V 表示首版完整体验的语音与角色阶段必需；P1 为闭环稳定后扩展。P0-V 不是可省略功能，只是安排在后续阶段交付。

| 需求编号 | 功能与行为 | 优先级 | 对应技术文档 |
| --- | --- | --- | --- |
| FR-01 | 支持常见岗位模板与自带 JD；区分原文要求、知识解释和推断 | P0-T | [岗位理解](modules/01-job-understanding.md) |
| FR-02 | PDF/DOCX 文本简历解析、学生确认、经历手动填写和修改 | P0-T | [个人材料](modules/02-personal-materials.md) |
| FR-03 | 将岗位能力与确认经历关联，生成可选择的准备主题 | P0-T | [准备重点](modules/03-preparation-plan.md) |
| FR-04 | 教学练习提供结构提示、解释与分步重答 | P0-T | [教学练习](modules/04-guided-practice.md) |
| FR-05 | 模拟面试动态追问、覆盖目标、限制时长，支持提前结束 | P0-T | [模拟面试](modules/05-mock-interview.md) |
| FR-06 | 中文 ASR、字幕、流式 TTS、打断、文本降级 | P0-V | [语音与3D](modules/06-voice-and-avatar.md) |
| FR-07 | 3D 角色待机、倾听、思考、说话及实际音频驱动嘴型 | P0-V | [语音与3D](modules/06-voice-and-avatar.md) |
| FR-08 | 原文证据、分维度反馈、改进任务、证据不足标记 | P0-T | [反馈报告](modules/07-feedback-report.md) |
| FR-09 | 单题重练、回答对比、主题历史和可比性说明 | P0-T | [重练与进展](modules/08-retry-and-progress.md) |
| FR-10 | 学生登录、个人记录隔离、查看和删除材料/记录 | P0-T | [数据与接口](data-and-interfaces.md) |

| FR-12 | 扩展岗位包、角色和外部资料接入 | P1 | [知识库与智能体](knowledge-and-agent.md) |

登录是支撑个人材料与历史隔离的基础能力。原型采用受邀学生账号，不建设开放注册、学校单点登录或收费体系；具体认证库在代码阶段确定，安全要求见数据文档。

## 5. 教学行为与评价要求

### 两种模式

| 行为 | 教学练习 guided | 模拟面试 mock |
| --- | --- | --- |
| 解释问题 | 可随时解释问题意图和术语 | 只解释题意，不提供答题框架或参考回答 |
| 学生卡住 | 给分级提示、拆成小问题 | 可换题或跳过；需要教学时结束/切换到新教学会话 |
| 反馈时机 | 单题后可以即时反馈和重答 | 结束后集中反馈 |
| 参考表达 | 基于确认事实示范，缺失事实用提问补充 | 面试过程中不提供 |
| 历史比较 | 标记提示使用情况 | 标记模拟条件；不直接与有提示表现比较 |

反馈分为表达结构与清晰度、岗位理解、经历证据三个维度。评价采用有描述锚点的 1～4 档，并允许 `not_observed`；首版不生成加权总分、班级排名或录用概率。题目没有触及的能力不评分，事实真实与否也不能仅由回答判定。

每条改进建议应回答“哪一句/哪段存在什么问题、怎样修改、下一步练什么”。学生纠正转写后，相关报告重新生成并注明版本；不把 ASR 错误作为表达能力问题。

## 6. 贯穿示例：小林的训练

本例全部为合成材料，各技术文档共用，不作为真实受访者数据。

- 小林是应届生，目标为初级产品运营。JD 关注活动执行、基础数据分析、跨团队协作。
- 小林在校园读书活动负责报名表、签到和群提醒；60 人报名、45 人到场。没有材料证明业务增长贡献，也没有独立 SQL 分析经历。
- 岗位解读说明活动执行可能涉及准备、现场与复盘；这些是知识说明，不直接当作这份 JD 的全部明确要求。
- 准备计划把该活动作为“说明个人行动与结果”的练习素材，数据分析经验标记为尚缺证据，而非判定“小林不会分析”。
- 首次回答：“我负责组织活动，效果很好。”AI 追问：“你具体做了哪些工作？怎样说明活动的结果？”
- 报告指出“效果很好”缺少结果信息，建议补充个人职责与已知数据。重练可回答：“我负责报名表、签到和群提醒。这次活动有 60 人报名、45 人到场。”
- 对比指出回答更具体；45/60 为到场比例，不应被解释为活动转化增长或全部由小林造成。下一次用其他题目检验迁移，不仅重复同一个答案。

## 7. 非功能需求

以下为设计基线和试验要求，不是已经达成的性能承诺；量化门槛与测量方法集中在[评测与迭代](evaluation-and-roadmap.md)。

| 编号 | 要求 | 验证方式 |
| --- | --- | --- |
| NFR-01 可用性 | 语音、3D 和模型单点失败有明确提示与可继续路径 | 拒绝权限、断网、模型超时、角色加载失败的场景测试 |
| NFR-02 延迟 | 记录端点检测、首个回答文本、首段可播放音频等分段延迟 | 按网络、浏览器、提供商记录 P50/P95，不只平均值 |
| NFR-03 可追溯 | 记录题目、回答版本、知识引用、模型/提示/评分标准版本 | 报告可回溯到当次冻结材料和确认逐字稿 |
| NFR-04 隐私 | 用户材料隔离、最少传给模型、密钥服务端保管 | 跨账号访问拒绝、日志脱敏、删除流程演练 |
| NFR-05 费用 | 单会话限制时长/回合与调用预算，不无限重试 | 注入重复请求和供应商失败，统计重复调用和计费 |
| NFR-06 可维护 | LLM/ASR/TTS/嵌入服务经适配层接入 | 更换提供商不改变业务状态和报告数据含义 |
| NFR-07 可访问 | 提供字幕、文本入口、暂停/结束按钮、键盘操作 | 不依赖声音或角色动画才能完成任务 |

## 8. 成功指标与需求验证

产品指标：岗位解读完成率、训练启动/完成率、反馈查看率、建议可执行性、主动重练率。必须说明分母和观察窗口，例如重练率按看过可重练报告的学生计算，不能按所有注册者混算。

AI 指标：追问相关性、重复率、引用准确性、无依据断言、空检索处理，以及不同材料完整度下的表现。运行指标：完整会话失败率、文本/音频延迟、每场实测费用与降级率。

教学指标：用人工盲评比较练习前后与同类新题的表达及岗位理解，标记是否用过提示。模型自评分只能帮助筛选问题，不能代替教学效果验证。留存与满意度亦不能独立证明能力提高。

需验证的需求假设包括：学生是否愿意先确认材料；岗位解读是否帮助选择准备重点；3D 是否增加持续练习意愿；具体反馈是否促成重练；学生是否能将改进迁移到新题。试用记录这些假设，而非将设计假设写成研究结论。
