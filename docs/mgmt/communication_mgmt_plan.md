# InterviewLab 沟通管理计划

版本 v0.4 · 更新日期 2026-11-12

小组聊天用于同步进度和处理阻塞，GitHub Issue 用于留存任务和决定，PR 用于审查改动。下表使用[团队计划](team_plan.md)中的角色，具体由小组分工确定。

| 沟通内容 | 沟通频度 | 沟通方式 | 产出物 | 责任人 |
| --- | --- | --- | --- | --- |
| **分析** · 这次课要交什么、演示哪个岗位和流程、哪些功能先放到后续 | 收到课程要求或教师反馈时，开工前确认一次 | 小组讨论，在对应 Issue 记录结论。教师反馈保留实际来源 | 本次交付清单和教师反馈处理记录 | 项目协调 |
| **设计** · 从选择岗位、开始面试到报告和重练的主流程，协调页面、接口和 Agent 的交接 | 开始联调前，对接口或流程有改动时再同步 | 前端、后端和 AI 负责人一起过一遍流程，有变更时在文档或 PR 里写清 | 演示流程、改动的接口和待联调项 | 软件工程 |
| **开发** · 谁在做什么、哪项任务卡住、什么时候能开始联调 | 每周同步一次，卡住时即时说明 | 小组聊天同步进度，在 Issue 或看板更新负责人和状态，改动通过 PR 检查 | 更新后的任务状态、待解决的阻塞和下一步 | 项目协调 |
| **测试** · 跑一遍登录、作答、出报告，实测麦克风、断线和文字切换 | 每轮联调后，彩排时在演示设备上再跑一次 | 小组共同看演示结果，能复现的故障记到 Bug tracker | 验收清单、缺陷复现步骤和复验结果 | 测试与质量 |
| **测试** · API 免费额度够不够完成彩排和正式演示，哪些真实调用先停 | 有真实调用的当天检查，批量评测、彩排和正式演示前复核。额度不足即时通报 | 软件工程在小组聊天报各服务的余量、预计用量和受影响的功能，项目协调确认测试和演示安排 | 额度核对记录，继续实测、缩减调用或启用备用展示的决定 | 软件工程 |
| **发布** · 确认提交链接、演示设备、主讲人和备用展示 | 提交及演示前各确认一次，有改动即时同步 | 小组按实际演示顺序彩排，通过课程指定渠道交付 | 提交版本与链接、提交凭据、彩排报告截图和离线录屏 | 项目协调 |
| **运行维护** · 处理试用期间的额度告警、语音中断和报告失败 | 收到问题时记录，影响试用或演示时即时同步 | 小组聊天通知项目协调与处理人，Issue 记录脱敏错误和修复进展 | 临时处理办法、修复结果和下一次复核时间 | 软件工程 |

同步阻塞时，用一条消息说明发生了什么、影响哪次测试或演示、谁在处理、何时复核。额度预警和备用展示按[风险管理计划](risk_mgmt_plan.md)执行，教师反馈归档到[教师反馈记录](../retrospection/teacher_feedback.md)。
