# 沟通管理计划

版本：v0.2 · 日期：2026-10-15 · 状态：当前协作规则；成员与排期待确认。

## 1. 角色与沟通入口

| 事项 | 发起与检查角色 | 记录位置 |
| --- | --- | --- |
| 产品定位、需求与验收变更 | 产品与需求发起，软件/AI/测试共同核对 | 需求正文、Issue 或本地变更记录 |
| 状态、字段和接口 | 软件工程负责，前端/后端/AI 接口双方核对 | [数据与接口](../software/data_and_interfaces.md) |
| 提问、实时接话、报告与表达观测 | AI 与面试内容负责，软件/测试共同核对端点、取消、指标与评分边界 | [知识与 Agent](../algorithm/knowledge_and_agent.md)、[评测](../algorithm/evaluation.md) |
| 课程要求与教师反馈 | 项目协调收集，产品与需求记录 | [反馈记录](feedback.md) |
| 故障与验收 | 测试与质量提交复现，责任角色处理 | Bug tracker / Issue，未建则注明待登记 |

一项任务设置一名负责人和一名检查人，成员未落实时保留角色占位，不编造姓名。沟通频率以课程检查和每次交付为节点；具体每周时间、截止日期及联络方式由团队确认。

## 2. 决策与变更流程

1. 说明问题、来源、受影响场景、替代方案及取舍，区分教师原要求、用户决定与团队假设。
2. 在需求中更新当前结论，保留需求编号追溯；取消项标明退出范围。
3. 同步页面、数据、Agent、模块和验收引用。评分、状态和删除合同不得由单个模块私自改变。
4. 在变更记录列出修改范围和检查证据，通过 PR 检查后再按团队流程集成。
5. 未获得新的事实依据时保留待验证状态，不把评论、合成示例或模型输出升级成用户研究结论。

本轮范围已由用户明确授权为整套文档修订，前端暂缓。同日后续讨论确认以实时口头面试为主线，纳入语音节奏与可选镜头表现复盘；产品描述直接呈现用户、能力和设计重点。摄像头默认关闭，复盘音视频只保存学生明确开启后采集的片段，每段自采集起私有保留最长 24 小时，重连或重试不重置期限。长期媒体库、情绪或人格判断、完整代码仓库分析及更长会话仍需单独讨论。

## 3. 教师反馈与外部记录

2026-10-15 的教师反馈由用户在聊天中转述：参考课程目录，在指定问题定义中填充六行产品描述。该来源可以记录为实际收到的反馈，不代表 GitHub Issue #7 有评论或课程已经验收。

保留 2026-10-05 第一周 PR、检查、看板的原证据与日期。需要在 GitHub 留言、发送邮件或给他人发消息时，按用户明确授权执行；文档修订本身不自动触发对外发送。

## 4. 问题升级和交接

资料缺失先标明缺什么、影响什么和临时可继续路径；状态不一致以公共合同为准，仍冲突则交给相关责任角色确认。无法按约交付时说明已完成范围、阻塞条件、下一步动作及谁负责处理，不靠修改状态掩盖问题。

每次交接至少给出需求/文件入口、已做决策、未验证项、验证结果和后续责任。会议或聊天决定整理成简短记录并链接正文；不维护多份相互矛盾的最终结论。
