# InterviewLab 风险管理计划

版本 v0.4 · 更新日期 2026-11-12

本次课程交付的首要风险是 **API 免费额度不足**。批量评测、联调和试用都会消耗额度，可能导致正式演示时无法生成下一题或报告。各服务的实际剩余额度、到期或重置时间及超额计费方式，由账号使用人核对后更新。

## API 额度预案

1. **按服务核对。** 软件工程记录 ChatECNU 生成、嵌入和火山 ASR／TTS 各项可用余量、计量单位及到期或重置时间。查不到的字段标为待确认。用一次短流程的实际用量，分别估算各服务在彩排、正式演示和一次重跑中需要预留的额度，并同步到小组。服务依赖见[系统架构](../software/architecture.md)。
2. **给演示留量。** 日常回归先用现有受控测试，真实 API 只跑选定样例。余量不足时停跑批量评测和全量嵌入构建，保留课上需要的调用。遇到限流或额度报错先核对供应商返回的原因。需要追加付费额度时，由小组决定金额和承担方式。[项目验证](../../tests/README.md)
3. **按故障准备备用展示。** 语音服务不可用而模型调用正常时，改用文字作答。模型调用受限时，用报告截图和离线录屏展示提问到复盘的过程。彩排用合成材料，提前把截图和录屏保存在演示设备上。[语音故障恢复](../software/voice-interview.md)

触发风险时，负责人按[沟通计划](communication_mgmt_plan.md)同步影响、当前处置和下次复核时间。影响试用或课程演示的事项在对应 Issue 留一条记录，复验后更新结论。
