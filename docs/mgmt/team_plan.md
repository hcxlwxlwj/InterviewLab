## 当前阶段与后续顺序

当前已实现独立 TypeScript/Node 后端公共骨架、岗位读取、迁移和任务基础。公共工程统一维护，各成员负责自己的模块及前后端联调；成员姓名和具体任务仍由小组确认。本轮通过本地 Git 提交交付，未推送或部署。

后续以[架构](../software/architecture.md)的六个模块和[接口合同](../software/data_and_interfaces.md)作为分工边界，按[评测方案](../algorithm/evaluation.md)推进：

| 阶段 | 交付目标 | 验收重点 |
| --- | --- | --- |
| 当前 | 文字原型、36 个岗位资料、独立后端公共骨架和测试 | 基础设施已验收；完整业务仍按下述阶段实施 |
| 1 真实业务闭环 | 独立 API/worker、受邀身份、数据库、文本简历、岗位/收藏、文字面试、Agent 证据报告、重练比较与记录 | 主路径、前端异步联调、权限/版本/幂等、outbox 恢复、删除；未校准不填专业分数 |
| 2 材料与内容完善 | 上传解析确认、私有文件、PDF、内容维护命令、混合检索、评分人工校准 | 文件/索引/导出版本与到期、事实引用、审核/撤回、检索与校准证据 |
| 3 实时面试 | ASR/TTS、自动回合、打断/误截恢复、重连/文本降级、独立语音观测 | 端点与接话测量、保存/取消/纠错/恢复、反馈面后开放 |
| 4 可选能力 | 真实代码执行/评审、镜头观察、授权复盘媒体、管理页面 | 隔离、授权、低质量不可用、媒体清理和维护权限 |
| 对照与试用 | 同材料对照、授权探索性试用、成本与变化记录 | 保留负面结果及局限，不把同题涨分当迁移效果 |

原 A 对应新阶段 1–2，B 的实时核心对应 3，C 为稳定后的效果评测；可选镜头和代码执行放 4。第一阶段文字联调不代表目标实时体验交付。每阶段拆可验收事项后再由小组确认负责人、检查人、期限和预算，本轮不创建 Issues 或编造排期。

业务规则与事务由模块服务承担，数据库负责持久化及一致性，Agent 负责受约束的内容任务。接口、schema 和输入输出先对齐，再独立开发；进程和模块不是固定人数或单独微服务。配合[沟通计划](communication_mgmt_plan.md)和[风险计划](risk_mgmt_plan.md)维护依赖与决策，第一周已发生安排保持原文。
