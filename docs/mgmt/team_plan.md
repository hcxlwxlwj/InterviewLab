## 第一周任务

以下任务均须在**课程第一周结束前**完成。实际截止日期尚未提供，确认后同步到 Issues 和 Team planning；不把文档更新日期当作课程截止日期。

| 编号 | 任务 | 责任角色（成员待绑定） | 验收条件 |
| --- | --- | --- | --- |
| W1-01 | 仓库建立与访问 | 项目协调 | 仓库可访问，协作者已接受邀请；若仓库私有，老师有访问权限 |
| W1-02 | 5W1H 与产品描述 | 产品与需求 | `docs/requirements/problem_definition.md` 包含六个问题、产品描述、首版边界和待验证假设 |
| W1-03 | README 与目录规范 | 软件工程 | 根 README 能导航到报告、协作说明与看板；课件要求的目录在 Git 中可见 |
| W1-04 | 分支与协作流程 | 软件工程 | 远端存在 `main` 和 `develop`；说明从开发分支开展任务、PR 检查与合并方式 |
| W1-05 | 项目看板与任务登记 | 项目协调 | 可打开 Kanban、Team planning、Bug tracker；本周任务有状态、优先级、验收条件，成员确认后绑定负责人 |
| W1-06 | 第一轮反馈入口 | 产品与需求 | 已创建反馈 Issue，问题具体；老师回复后记录原文链接、处理方案和结果 |
| W1-07 | 提交仓库链接 | 项目协调、测试与质量 | 按[提交清单](week1_submission.md)检查后，在课程指定渠道提交仓库链接，保留提交凭据 |

各任务当前状态与链接以 GitHub Issues / Projects 为准，避免在多份文档中分别维护状态。尚未确定负责人和课程截止日期的字段保持“待定”，不能仅因文档完成就视为团队排期完成。

## 后续开发顺序

第一周交付之后，沿用[评测与迭代计划](../evaluation-and-roadmap.md)的阶段门槛：文本教学闭环 → 语音闭环 → 3D 交互 → 小规模试用。每阶段拆成可验收 Issues 后再安排成员与日期；现有技术方案和试用规模均为规划，尚无实际用户研究或运行结果。
