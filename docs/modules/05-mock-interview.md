# 05｜模拟面试

> 版本：v0.1 · 日期：2026-10-03 · 文档性质：首版设计与验收依据，尚未实现。相关设计：[需求分析](../requirements.md)、[总体架构](../architecture.md)、[智能体设计](../knowledge-and-agent.md)、[数据与接口](../data-and-interfaces.md)。

## 1. 目标与用户需求

让学生在接近面试节奏的对话中练习回应问题、说明个人贡献和应对追问。学生需要的是能够根据回答继续询问的练习对象，而不是随机题目播放器。系统应围绕目标岗位和学生已确认的经历提问，同时控制压力与时长，让第一次使用的学生也能完成一场练习。

模拟面试与教学练习分开：`Session.mode=mock` 在进行中主要提问，结束后集中反馈；`guided` 才提供结构提示和即时指导。模拟模式允许学生请求解释题意、重复问题、跳过和结束，但不在每题后展示评分或完整示范答案。结束报告评价本次回答，不代表学生完整能力或录用可能性。

## 2. 首版范围与交互流程

1. 学生选定 `JobTarget`，确认本次使用的经历材料，看到中文练习时长、材料完整程度和可用输入方式。
2. 进入准备页面，选择文本或语音，完成必要的设备检查。没有简历或经历时也可训练，页面提示个性化程度有限。
3. 开始后展示当前问题、回答输入区域、字幕、暂停和结束入口。每次只有一个需要学生回答的问题。
4. 学生提交回答后，面试官选择追问、下一主问题或收尾。跳过明确记录为跳过，不能当作能力不足的自动证据。
5. 结束时展示已保存回答和报告生成状态，报告就绪后进入反馈及单题重练。

首版默认目标为 5～10 分钟，最多 6 个主问题，每个主问题最多 2 次追问。达到 10 分钟后提示收尾，不截断正在进行的回答；达到 12 分钟硬停止时取消生成和录音，只保留已确认回答，未确认草稿不进入评估。安全上限按开始后的总经过时间计算，含暂停与断线，避免无限延长会话。

## 3. 输入输出与数据

| 对象 | 本模块使用的信息 | 产生或更新的信息 |
|---|---|---|
| `JobTarget` | 已确认职责、能力要求、要求来源 | 本次训练的岗位快照引用 |
| `Experience`、`PreparationPlan` | 已确认个人事实、推荐训练主题 | 本次关注的能力与经历引用 |
| `Session` | 用户、模式、配置、内容版本 | 状态、时间、结束原因、覆盖情况 |
| `Turn` | 问题、学生输入草稿、确认文本 | 主问题/追问关系、确认版本、取消状态 |
| `Report` | 会话与确认回答版本 | 独立的异步报告状态 |

首轮开始时固定岗位、经历与评价标准快照，避免学生编辑简历后改变本场面试的上下文。回答必须区分草稿、ASR 最终转写和已确认版本：`transcript.final` 只表示识别阶段结束，不自动等同于可评估的真实回答。用于后续追问、持久化评价与报告的正式输入以提交确认文本为准。

## 4. 处理逻辑与技术方案

会话编排器维护 `draft → ready → in_progress → ending → completed`，进行中可进入 `paused` 并恢复；不可恢复故障进入 `failed`。会话状态由程序推进，LLM 返回提问建议，不能自行宣布状态完成或绕过时长限制。`completed` 表示对话记录已封存，报告仍可能处于 `pending` 或 `generating`。

开始时根据岗位能力、准备计划和可用经历建立问题覆盖表。优先包含自我介绍或动机、一次具体经历及与岗位有关的常见情境，不为凑足题数强行补题。题库检索提供主问题候选，LLM 可以结合学生材料改写，程序检查是否超出已知事实、是否重复和是否符合本次主题。

每次提交后先保存确认版本，再抽取回答中已出现的行动、结果与缺口。追问优先级为：澄清个人职责、补充行动或结果、解释岗位相关思考。已经说明过的信息不反复追问；回答暴露未经历的事项时，可以询问学习思路，不宣称学生拥有相关经验。LLM 输出结构包含问题文本、问题目的、所针对的回答证据及下一步建议，由模式、次数和时间策略校验后执行。

对同一轮使用提交标识和版本检查防止重复保存。打断取消当前 `generation_id`，晚到的文本与音频不能重新进入播放或正式记录。面试官已生成的完整问题与学生实际听到的片段分别记录，依据客户端播放进度处理重复题意，避免假定学生听到了尚未播放的内容。结束操作幂等，进入 `ending` 后不再生成新问题。

## 5. 接口与模块依赖

| 接口/事件 | 职责与依赖 |
|---|---|
| `POST /api/v1/sessions`、`GET /api/v1/sessions/{id}` | 创建配置/查询权威状态，检查当前用户、岗位材料和模式配置 |
| `POST /api/v1/sessions/{id}/start`、`/pause`、`/resume` | 开始、暂停和恢复；校验状态与时间预算 |
| `POST /api/v1/sessions/{id}/turns` | 提交回答或教学操作；校验确认版本和会话可写状态 |
| `PATCH /api/v1/sessions/{id}/turns/{turn_id}` | 纠正已提交文本，增加 revision，令旧报告及比较过期 |
| `POST /api/v1/sessions/{id}/finish` | 幂等结束，封存确认文本，发起报告任务 |
| `GET /api/v1/sessions/{id}/report` | 查询报告状态和结果，不阻塞结束接口 |
| `/api/v1/sessions/{id}/stream` | 实时事件；连接与重连均校验会话归属 |

实时通用事件携带 `session_id`、`turn_id`、`generation_id`、`seq`，事件定义以数据接口文档为准。`user.answer.commit` 驱动正式回答处理，`user.interrupt` 驱动取消，`session.finish` 与 HTTP 结束接口复用同一业务逻辑。文本入口和语音入口共用同一会话模块，不能出现两套追问规则。岗位模块提供来源与能力，材料模块提供确认经历，知识库提供题目，反馈模块异步消费封存会话。

## 6. 异常与边界

- 无经历材料：生成通用问题，明确提示缺少个性化依据，不补造实习或项目。
- 学生请求解释：用简短表达澄清题意，不泄露答案模板；需要即时教练时提示退出本场并进入教学练习，不静默改变模式。
- 长时间无输入：先提示继续、跳过或结束；不把沉默自动解释为焦虑、不自信或能力低。
- LLM 超时或非法输出：预算允许且无成功结果时最多有界重试一次；仍失败时保留回答并提供继续/结束入口。已经接收的回答不因模型失败被重复写入。
- 断线：暂停新生成，显示连接状态；恢复先获取服务端快照与最后确认轮次，不盲目重放旧音频。不可恢复时置为failed并保留已确认回答，通过报告重试入口请求已完成部分的报告，不将failed改为completed。
- 学生纠正误识别：保存回答新版本，取消依赖旧文本的未完成追问；已经展示的后续内容标注受到更正影响，报告使用封存的最终确认版本。

## 7. 贯穿示例

以下为纯合成案例。小林应届，目标岗位为初级产品运营，JD 涉及活动执行、基础数据和跨团队合作。小林已确认自己在读书活动中负责报名表、签到和群提醒，60 人报名、45 人到场；没有提供增长贡献或独立 SQL 经历。

主问题是“请介绍一次你参与活动执行的经历。”首次回答为“我负责组织活动，效果很好”。面试官追问“你具体负责了哪些工作，结果如何？”回答补充“我做了报名表，活动前在群里提醒，现场负责签到，60 人报名、45 人到场。”系统可以继续询问如何理解报名与到场的差异，不能问“你用 SQL 优化增长的结果是多少”。本场报告分别指出首次回答的缺口与追问后补充的信息，重练目标是“在首答中一次讲清个人动作和结果”，不把已经补充的细节继续描述为缺失，也不直接给出录用建议。

## 8. 验收条件

| 场景 | 通过条件 |
|---|---|
| 正常完成 | 保存主问题及追问关系，封存确认回答，报告异步生成 |
| 数量与时间限制 | 不超过 6 个主问题与每题 2 次追问；10 分钟收尾、12 分钟硬停止符合规则 |
| 动态追问 | 合成案例追问关联已知回答；无虚构 SQL、增长或个人职责 |
| 跳过/提前结束 | 已确认内容可报告，跳过与未观察区别于低分 |
| 重复提交/重复结束 | 同一提交只产生一个正式版本和一次对应处理，结束不创建重复报告任务 |
| 取消与断线 | 旧生成不继续播放或污染当前轮；重连恢复确认记录 |
| 输入更正 | 更正版本进入报告，旧版本可追溯且不被当作当前事实 |

测试采用确定性状态机用例、可控模型桩与合成会话，另用人工评阅确认追问相关性；详细样本与门槛见[评测计划](../evaluation-and-roadmap.md)。

## 9. 优先级与后续扩展

P0-T 为文本模拟、确认回答、动态追问、受控结束、断线/进程恢复、异步报告及重练衔接；P0-V 为首版后续阶段的语音、3D 与实时打断完整体验，不能作为可省略项；P1 为更丰富的岗位情境和面试风格。首版不加入真实企业面试官身份、招聘决策或多面试官自主辩论。扩展岗位时先增加有来源的题库和评价样例，再扩大模型自由生成范围。
