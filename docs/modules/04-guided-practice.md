# 04 教学练习：功能技术文档

> 状态：首版设计，尚未实现。采用 `Session.mode = guided`，与模拟面试的集中反馈模式区分；公共会话类型与事件见[数据与接口概要](../data-and-interfaces.md)。

## 1. 目标与用户需求

帮助应届生在较低压力下练习自我介绍、经历表达与行为问题。教练通过逐步提示、针对性追问、原文反馈和再次作答，让学生发现哪里没有讲清楚。系统应保留学生自己的表述与事实，而不是让其背诵模型编写的理想经历。

本模块允许即时指导，模拟面试则以提问追问为主、结束后集中反馈。首版目标是讲清当前材料中可观察的信息，不把语速、用词风格或一次回答映射为人格、心理状态和录用概率。

## 2. 首版范围与交互流程

1. 学生从准备计划选择主题，或直接选择自我介绍、经历表达、行为问题，并确认所用经历。
2. 系统创建 `guided` 会话，说明练习目标，给出一项明确问题。
3. 学生自由回答，支持文本；语音阶段接入后沿用同一回合逻辑。
4. 教练先引用学生回答，指出一个主要问题，再给一个提示或追问；学生可请求问题解释、进一步提示或示范。
5. 学生补充或重新作答，系统保存原回答与新回答，不覆盖历史文本。
6. 单题练习结束后展示简短总结、未澄清项与下一步建议；整场结束后异步生成 `Report`，可以转入单题重练。

提示采用逐级方式：先提醒需要补充的信息，再提供组织框架，最后按学生明确请求提供基于确认事实的示范。示范明确标为练习参考；有缺失事实时用待填写问题说明，不生成可以误认为真实履历的完整故事。

## 3. 输入输出与数据

| 对象 | 内容 | 约束 |
| --- | --- | --- |
| 练习输入 | 主题、目标岗位修订、确认经历、可选计划 | 无经历时支持通用练习，但不作个人能力断言 |
| `Session` | `mode=guided`、主题、上下文快照、状态 | 状态使用公共会话状态机 |
| `Turn` | 问题、回答、类型、提示/追问/示范、来源与时间 | 学生回答与模型示范分开记录，示范不作为学生回答证据 |
| 逐题反馈 | 回答引用、可观察问题、改进动作、待澄清项 | 引用必须存在于对应回答，未观察到不等于能力不足 |
| `Report` / `RetryComparison` | 总结或后续重练关系 | 报告独立使用 pending/generating/ready/failed 状态 |

事实分为两类：已确认经历用于个性化内容；学生当前回答用于评价“这次说了什么”。回答中新增的个人事实可以作为“本轮学生自述”被引用，但未回到材料页确认前，不进入后续会话的确认事实库，不自动成为经历更新。语音识别的 final 是转写完成，不能等同于回答已确认提交；首场默认学生手动确认，也可在明确开启自动提交后提交最终转写。

记录学生用了哪些提示，以区分独立回答和受指导回答。前后比较说明提示条件，不把获得更多提示后的表现写成独立能力提升。

## 4. 处理逻辑与技术方案

**会话控制。** 编排器管理 `draft → ready → in_progress`，支持 `paused`、`ending`、`completed` 和故障时的 `failed`。教学子步骤为“问题—自由回答—单项反馈—补充/重答—小结”；它们是回合类型，不增加或替代公共会话状态。学生结束后先完成记录，会话 `completed` 不代表报告已经 `ready`。

**教学策略。** 教练角色读取当前目标、确认事实、最近回合和教学知识检索结果。程序要求一次只提出一个主要改进目标，如说清个人职责，而不是同时列出十项缺点。首版同题默认最多三次教练追问，之后总结并提供重练或换题入口；学生始终可以结束。整场教学采用公共的 12 分钟资源上限，包含暂停时间；到达上限保存已确认内容，结束后可创建新会话继续练习。

**结构提示。** 自我介绍强调当前背景、相关经历与岗位动机；经历表达可使用背景—任务—行动—结果的组织方法，允许没有量化结果。行为题提示围绕真实事件和个人动作，不强制每句都符合模板。提示不把未提供的事实补齐，也不根据岗位 JD 直接写出“我熟练掌握”之类的个人断言。

**证据反馈。** 模型输出引用的 `Turn` 标识与原文，服务端校验原文存在。提示“缺少个人行动”只代表当前回答未说明；如果材料中已有动作，可以提醒学生补充，不能据此评价其没有执行能力。观点偏差优先通过澄清问题处理。基于 ASR 的文字若未经核对，反馈需说明依据是识别稿；准确措辞与数字由学生纠正后再评价。

**示范与新增事实。** 示范只接收已确认事实和教学目标，输出附带事实来源；没有结果就不写业绩。学生在回答中说出新数字时，教练可以请求澄清并建议稍后确认，但不自动写入 `Experience`。结构校验失败、引用不准确或出现未提供的个人事实时，拒绝展示该段示范并重试或退回结构提示。

**上下文与并发。** 保留题目、关键回答、提示使用记录及确认事实摘要；过长历史通过可追溯摘要压缩，原始回合仍保留。一次只处理当前回合，提交标识防止网络重试导致重复回答。异步模型结果携带会话与回合版本，暂停、结束或切题后丢弃过期结果。

## 5. 接口与模块依赖

| `/api/v1` 接口能力 | 输入 | 输出与依赖 |
| --- | --- | --- |
| `POST /sessions` | `mode=guided`、岗位/经历/计划主题 | 创建待开始配置，返回 draft/ready；依赖计划与身份模块，start时再校验版本并冻结快照 |
| `GET /sessions/{id}` | 会话标识 | 当前状态、回合、练习目标与提示记录 |
| `POST /sessions/{id}/turns` | 回答或教学交互类型、提交标识 | 受控回合结果；提示、解释和示范使用公共回合契约 |
| `POST /sessions/{id}/start`、`/pause`、`/resume`、`/finish` | 当前会话及受控操作 | start 请求首题，其他动作控制状态，响应包含状态与待处理回合 |
| 报告/重练能力 | 完成会话、原回答标识 | 独立报告任务和后续重练关系 |

本模块依赖教练角色、题库和教学方法 RAG、确认经历读取 Tool、回合保存 Tool、报告模块。文本与语音共享业务逻辑；语音模块提供转写与音频事件，3D 仅展示会话状态，不参与评分决策。内部工具直接调用，首版不需要 MCP。

## 6. 异常与边界

- **学生说“不会”或请求解释：** 解释问题目标、给可完成的提示，不当作失败或人格判断。
- **回答只有一句话：** 先追问个人动作或具体结果，不立即展示长篇满分示范。
- **没有可用经历：** 引导整理一个真实事件或练习自我介绍结构，不捏造项目。
- **学生纠正材料：** 当前轮保留纠正为自述，并提示确认经历更新；不会悄悄改写历史会话。
- **模型超时：** 保留回答，可重试指导或结束；未生成的反馈不显示为完成结果。
- **连续重复或无关回答：** 重新说明练习目标，达到追问上限后小结，不无限追问。
- **语音识别或播放失败：** 切换文本继续同一会话；识别错误允许纠正，不要求重开。
- **结束或切题时仍有生成任务：** 不追加过期教练回合，报告只读取已完成且校验通过的记录。

## 7. 贯穿示例

小林练习回答“请介绍一次你参与的活动”。首次回答为：“我负责组织活动，效果很好。”教练引用这句话，指出当前回答没有说明个人动作，追问：“你亲自做了哪些事？”小林补充报名表、签到和群提醒。教练再询问如何描述结果，提醒可使用已确认的 60 人报名、45 人到场。

小林改进回答：“在校园读书活动中，我负责报名表、现场签到和活动群提醒。活动有 60 人报名、45 人到场。我能用这些记录说明活动参与情况，但还不能判断提醒带来了多少新增到场。”系统评价信息更具体、个人动作更清楚；不宣称小林实现增长或具备 SQL 分析能力。若请求示范，参考文本只能使用上述确认事实，并和学生实际回答分开保存。

## 8. 验收条件

| 场景 | 可验证结果 |
| --- | --- |
| 首次回答“效果很好” | 反馈引用原句并给一个可回答的追问，没有笼统判定能力差 |
| 学生依次请求提示、结构、示范 | 提示逐级提供且标记已使用；示范未写入学生回答 |
| 缺少量化成果 | 允许定性结果或反思，不添加增长数字 |
| 本轮出现材料外的个人事实 | 作为本轮自述处理，未来确认事实视图不会自动增加 |
| 提交重试、模型延迟、暂停后返回 | 无重复回合、过期生成不覆盖当前题目 |
| 提前结束 | 已有回答保存，会话完成与报告状态独立显示 |
| ASR 纠正关键数字 | 反馈基于纠正后的回答修订，旧报告/引用可追溯 |
| 三次同题追问后仍无补充 | 小结与重练/换题入口出现，不无限继续 |

人工评阅重点检查建议是否具体、引用是否准确、是否引入虚构事实。前后回答对比必须注明提示条件；用同类新题检验学生能否独立组织事实，见[评测与迭代计划](../evaluation-and-roadmap.md)。

## 9. 优先级与后续扩展

P0-T 完成文本教学闭环、分级提示、确认事实示范、逐轮记录、结束总结、报告与单题重练；P0-V 在后续语音和 3D 阶段接入同一练习流程，仍属完整首版必需功能。P1 可优化提示策略和可选题目覆盖；专业课题、多题课程编排和个性化长期教学后续扩展，先验证通用面试表达的教学效果。
