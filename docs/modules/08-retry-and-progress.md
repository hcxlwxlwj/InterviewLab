# 08｜单题重练与进展回顾

> 版本：v0.1 · 日期：2026-10-03 · 文档性质：首版设计与验收依据，尚未实现。相关设计：[需求分析](../requirements.md)、[教学练习](04-guided-practice.md)、[反馈报告](07-feedback-report.md)、[数据与接口](../data-and-interfaces.md)。

## 1. 目标与用户需求

把报告中的建议转为下一次可执行练习。学生需要知道本次要改进什么、如何尝试，以及新回答具体增加或改变了什么。历史记录帮助学生回顾训练内容，但不能把练习次数、字数增长或模型评分增加当作真实求职能力增长。

首版重练聚焦一个题目和一个主要薄弱点，例如“讲清个人行动”或“补充结果边界”。比较的是已确认回答中的可观察变化；验证迁移能力需要同类新题与人工评阅，不能仅比较同题背诵效果。

## 2. 首版范围与交互流程

学生在反馈中选择一个重练入口，看到来源问题、原回答、一个改进目标及允许使用的事实。练习前可阅读教练提示，开始后可以重新作答，提交确认文本后获得对比和下一步建议。重练默认采用 `guided` 模式，不改写原始模拟会话。

对比页并列展示原回答与新回答，标出新增的职责、行动、结果或推理信息，再解释哪些原有问题仍然存在。不用“提升 50%”等未经验证的百分比呈现，也不保证示范表达就是标准答案。学生可再次重练，或使用同类新题测试是否能够独立应用表达方法。

历史页按时间展示岗位、模式、训练主题、完成状态和报告可用性。进展页汇总做过哪些主题、重复出现哪些信息缺口及近期已观察变化，提供下一条练习建议，不给求职竞争力排名。删除入口覆盖来源会话、派生报告和重练关联。

## 3. 输入输出与数据

重练请求关联来源 `Session`、`Turn`、`Report` 版本、目标薄弱点及岗位/经历快照。新回答属于新的 `Session` 与 `Turn`，通过 `parent_session_id`、`parent_turn_id` 关联来源；来源与目标的具体字段以[数据接口](../data-and-interfaces.md)为准。学生主动补充新事实时需要确认并注明，不以新事实出现直接证明表达技巧改善。

`RetryComparison` 包含两份确认回答版本、比较标准版本、共同观察维度、新增/保留/未解决的信息、精确引用、建议和可比性限制。不同岗位、题意、材料版本或教学提示程度会影响可比性，必须显示差异，而不是强行计算统一进步值。

历史汇总只读取当前用户的会话与可见报告。趋势依据来自确认内容与报告观察，不使用原始音频推断情绪或人格。模型和标准版本更新导致的分值变化不能合并为学生表现趋势。

## 4. 处理逻辑与技术方案

创建重练时校验来源归属、报告版本及问题仍有效，记录所需历史上下文与材料选择，开始时冻结为新会话快照。优先练报告中有明确证据的薄弱点；如果来源报告失败，允许学生从已确认回答手动选择表达目标。学生可以看原回答，也可隐藏提示练习；界面记录是否使用教学提示，以便解释比较范围。

新回答确认后，比较请求明确指定原回合、新回合和两份回答 revision；教学会话有多次重答时由学生选择，不默认比较最后一条。先抽取两份回答中的职责、行动、结果、边界与岗位判断，再生成变化说明。引用必须分别在原/新确认文本中验证。只因字数增加而无新信息的回答应显示“表达更长，但仍缺少具体行动”，数字发生变化则提示事实差异需确认，不能视为提升。

比较使用共同评价标准；原报告标准不同或材料变化显著时，可以给出信息差异比较并标记“不能直接比较分值”，不悄悄重算历史报告。学生确认新增事实后，区分“补充了事实材料”与“组织方式更清楚”。重复提交和比较任务以两份回答版本去重，失败保留新回答供重试。

进展汇总先做确定性统计，再依据可定位观察生成简短建议。统计包括完成练习次数、训练主题覆盖、重练次数和可比回答的变化类型；不得把 `not_observed` 纳入平均分。首版优先展示主题与证据变化，维度级趋势需满足相同标准及可比场景，并清楚标注观察范围。

## 5. 接口与模块依赖

| 接口 | 职责 |
|---|---|
| `POST /api/v1/sessions/{id}/retries` | 从来源会话与问题创建重练，检查归属和来源版本 |
| `POST/GET /api/v1/retry-comparisons` | 创建或查询两份确认回答的比较；过滤不可访问的来源 |
| `GET /api/v1/history` | 分页获取当前用户训练及报告状态 |
| `POST /api/v1/sessions/{id}/turns` | 保存重练回答，与其他会话共用确认逻辑 |
| `PATCH /api/v1/sessions/{id}/turns/{turn_id}` | 更正回答并增加 revision，已有比较标记过期且待更新 |

依赖报告模块提供问题和建议，教学练习模块提供提示，会话模块提供独立记录，评价模块生成证据变化，统一删除模块清理派生关系。历史页不能绕过会话权限，通过猜测 ID 访问他人原文；比较请求中的两份答案也都必须属于当前用户。

## 6. 异常与边界

- 来源被删除：停止创建重练，既有比较按统一删除策略处理，不保留悬空原文。
- 新回答与原题无关：提示此次回答难以比较，仍可保存为练习，不生成虚假进步结论。
- 来源与目标标准不同：展示信息差异与限制，不混算评分趋势。
- 学生增加经历数据：要求确认，注明资料补充；不自动认定最初遗漏就是能力缺陷。
- 比较生成失败：新回答已经保存，允许重试比较，不要求学生再次回答。
- 多次连续重练：支持查看各次记录，避免自动只挑最高分作为进展。
- 提示依赖：更好的同题回答可记录为本次表现变化，同类新题表现才支持进一步迁移判断。

## 7. 贯穿示例

纯合成小林的原回答是“我负责组织活动，效果很好”。重练目标为“说明个人职责、具体行动和结果”，提示可以让小林先列出做过的事项，但不能给他增加增长或 SQL 经历。

小林新回答为“这次读书活动，我负责报名表、现场签到和群提醒。60 人报名、45 人到场。我能说明自己完成了这些执行工作，暂时不能证明提醒单独影响了多少人到场。”对比指出新回答明确了三项动作、结果数字与归因边界。仍可提醒补充如何复盘未到场情况，不能写“运营能力提高到优秀”。再用另一道活动协调题检验是否能迁移方法，进展页保留同题重练与新题练习的区别。

## 8. 验收条件

| 场景 | 通过条件 |
|---|---|
| 来源关联 | 新会话可追溯原题和报告版本，不覆盖原回答 |
| 证据比较 | 原/新引用精确有效，变化与实际新增信息一致 |
| 内容变长 | 无新信息时不以长度判定改善 |
| 材料变化 | 新事实与表达变化分开，数据矛盾提示确认 |
| 失败恢复 | 比较失败不丢失重练回答，重试不会创建重复可见记录 |
| 趋势限制 | 不混合不同标准、场景或未观察维度计算进步 |
| 权限删除 | 跨用户比较被拒，删除同步清理相应派生数据 |

使用好转、无变化、题意改变、事实改变、标准改变及删除来源的合成样例检查比较。教学效果评价按[评测计划](../evaluation-and-roadmap.md)开展，不能由同一模型对自身建议的满意度代替。

## 9. 优先级与后续扩展

P0-T 为单题重练、两次回答证据比较、历史记录、基础主题进展汇总及可比性说明；P0-V 为语音/3D 重练入口沿用同一确认与比较逻辑；P1 为自动同类新题推荐、高级长期趋势及更长周期学习计划。同类新题迁移验证在首版评测中实施，即使尚未建设自动推荐功能。未来可研究练习频率建议与个性化目标，但首版不采用强制打卡、竞争排名或没有证据基础的能力画像。
