# 09｜内容维护与运行管理

> 版本：v0.1 · 日期：2026-10-03 · 文档性质：首版设计与验收依据，尚未实现。相关设计：[总体架构](../architecture.md)、[知识库与智能体](../knowledge-and-agent.md)、[数据与接口](../data-and-interfaces.md)、[评测计划](../evaluation-and-roadmap.md)。

## 1. 目标与用户需求

团队需要稳定维护岗位知识、教学方法、题库和评价标准，知道一次更新会影响哪些回答，并能够发现模型、语音或异步任务故障。学生则需要持续可用且依据清楚的训练内容，避免今天与明天相同回答因无记录的标准变化得到完全不同结论。

本模块为团队内部维护入口，不是教师端或班级管理系统。首版提供受限内容管理与运行检查即可，不建设复杂多级审批、学生监控或招聘后台。内容维护不能直接浏览全部学生简历和录音，运行排障默认依据脱敏标识与指标。

## 2. 首版范围与交互流程

内容维护流程为“登记来源与适用范围 → 导入或编辑 → 解析切分预览 → 检索与评价抽检 → 发布新版本”。未发布内容不进入学生检索。题目需注明适用岗位、训练主题、问题目的及追问方向；评价标准需有维度锚点、正反例和证据要求。

发布前检查来源、重复、缺失字段、可用引用与合成案例效果。发布生成可追溯版本，已有会话引用对应版本，新会话采用当前发布版本；紧急回滚仅改变后续会话选用，不破坏历史依据。下架阻止新检索，但保留旧会话所需的只读版本，涉及授权撤回或删除请求时按统一策略处理并向相关历史记录说明来源不可用。

运行页面展示会话完成、报告任务、服务调用失败、延迟、取消情况与费用用量，并提供按脱敏请求标识定位故障。运营人员可重试合规失败任务或停用有问题内容，但不能代替学生编写确认回答。

## 3. 输入输出与数据

| 内容/运行对象 | 必要信息 |
|---|---|
| 岗位与教学文档 | 来源标题/地址、获取日期、适用范围、授权说明、内容版本、发布状态 |
| 知识片段 | 文档版本、定位、岗位/主题标签、检索文本与向量版本 |
| 题库 | 题目、题意、目标维度、适用范围、追问方向及版本 |
| 评价标准 | 1～4 锚点、`not_observed`、证据规则、样例与版本 |
| 异步 job | 任务类型、关联版本、状态、尝试次数、可重试原因 |
| 调用指标 | 服务标识、模型配置、耗时、错误类别、使用量与费用估算 |

运行日志记录脱敏用户/会话标识、阶段、请求标识、状态、时间和用量，不写入原始简历、完整逐字稿、原始录音、提示词中的个人材料或完整报告。需要人工核查内容质量时优先使用合成样例；真实学生材料使用需另行获得明确授权并限定用途，不把排障权限当作研究许可。

## 4. 处理逻辑与技术方案

内容和索引保存在 PostgreSQL，文件放入受控文件存储。导入解析与向量生成通过异步 job 执行，失败任务不会发布半成品。解析结果须保留来源定位，检索片段不能只剩无法引用的文本。岗位/主题/状态过滤先限制候选，再进行关键词与向量检索，发布时以常见问法和无相关依据问法检验召回与拒绝伪造引用的行为。

内容版本、embedding 配置和评价标准版本分别记录，向量重建不静默改变原文版本。更换 embedding 时重建可切换索引并抽检，不能直接混用不兼容向量。首版参数调整基于合成评测集，确认检索与引用质量后再发布。知识库正文视为资料数据，嵌入的“忽略规则”“调用外部接口”等文本不得成为系统指令。

运营指标按阶段统计：材料解析成功率、确认提交到首段回复、音频实际开始播放、打断停止、完成率、报告成功率及每场用量。失败率需明确分母，主动取消、学生提前结束、服务超时和程序错误分别记录；不能将所有未完成会话归因为系统失败。费用基于实际服务计费项和用量汇总，未知单价或未知用量标为未知，不填为零。

报告工作进程采用可恢复 job 与领取互斥控制，避免重复消费；外部调用在预算允许且无成功结果下最多有界重试一次，仍失败则保留可定位的错误类别。预算保护在会话开始、模型调用和异步任务处执行，限制最大上下文、轮次和重试；超预算优先保护已确认记录并说明后续操作不可用，不让学生反复提交产生重复费用。

运行管理采用最小内部角色：学生只能访问自身数据，内容维护者可管理公共内容，运行维护者可查看脱敏指标和处理运行任务。维护操作记录操作者、时间、对象版本、动作与结果。密钥仅在服务端配置，替换密钥或服务提供商后使用合成冒烟测试，不在页面和日志展示密钥。

## 5. 接口与模块依赖

内部维护接口位于 `/api/v1/admin`，职责覆盖内容导入预览、审核/发布/撤回、版本回滚、索引重建、任务状态与脱敏指标查询；具体子路由随实现确定，不作为首版外部公开 API。首版也可由受权维护脚本调用相同服务逻辑，不要求完整 CMS。所有操作复用应用鉴权和审计逻辑，不提供匿名 MCP 或工具入口执行发布。

依赖知识库模块提供切分与检索、文件模块提供解析、job 模块提供异步执行、服务适配器提供用量与错误分类。学生训练 Tools 只读已发布内容，不能调用内容发布或索引重建。未来 MCP 扩展仍需保留服务端权限与来源校验，协议连接成功不等于内容可信或工具动作被授权。

## 6. 异常与边界

- 导入失败：保留草稿及失败原因，可重新解析或手动编辑；不能发布空片段。
- 来源不清或授权不明：暂不发布，团队补齐来源或使用自编材料，不伪造出处。
- 新版本错误：回滚新会话默认版本；历史报告继续引用原依据，受影响情况可提示。
- 索引损坏或检索无结果：提示资料不足，避免借模型记忆编造引用；可降级关键词检索。
- 服务持续故障：停用对应能力并降级文本/保留记录，运行页展示故障范围与可执行恢复操作。
- 任务卡住：识别超时领取并按策略重新安排，处理幂等；已经删除的数据对应任务不得复活派生报告。
- 日志缺失或用量未知：显示不可用指标，不生成看似精确的费用数字。
- 删除与备份：在线数据立即不可访问，物理清理目标为 24 小时内完成，脱敏日志与限权备份默认保留 30 天，均为可配置设计默认值，不是已实现或法律承诺。备份恢复重放删除清单，不能重新恢复已删除对象；删除细则见数据文档。

## 7. 贯穿示例

团队为初级产品运营发布活动执行知识、读书活动题目和“明确个人行动与结果边界”的评价标准。纯合成小林正在进行中的会话固定使用该版本。维护者随后增加数据复盘题和新的行为锚点，小林原会话及报告仍引用原标准；下一场采用新发布版本。

抽检发现模型把 60 人报名、45 人到场解释为小林实现增长，团队先记录合成复现样例，修订过度归因规则并跑回归验证。运营页面看到某日 TTS 失败率升高时，根据调用阶段与脱敏请求标识定位，不需要查看学生原始录音；恢复前保留文本输出与训练记录。

## 8. 验收条件

| 场景 | 通过条件 |
|---|---|
| 草稿与发布 | 未发布内容不进入学生检索；发布前完成来源、标签与抽检 |
| 历史版本 | 新发布/回滚不破坏已完成会话引用和报告依据 |
| 索引更新 | 新索引可验证后切换，重建失败保留可用内容 |
| 任务恢复 | 重复领取不重复生成结果，删除后任务不能重新写入报告 |
| 权限 | 学生不能发布内容，运营查询不能访问未授权个人原文 |
| 日志检查 | 合成个人材料、密钥与录音不出现在运行日志中 |
| 指标费用 | 指标有分母和时间范围，未知费用显式标记，不把取消当程序失败 |
| 故障降级 | 模型/语音/角色故障范围可定位，已确认记录可读取与删除 |

每次发布运行关键合成回归样例，模型或标准更新需复核引用与事实边界。部署验收另验证 HTTPS、服务端密钥、备份恢复和删除流程，不由“容器成功启动”代替训练闭环验证。

## 9. 优先级与后续扩展

P0-T 为来源与版本管理、审核发布/回滚、受限维护权限、关键日志与 job 状态、用量指标及预算保护，可先通过受权脚本提供维护能力；P0-V 为语音/角色故障监测、取消后用量和素材依据管理；P1 为完整内部维护页面、更细的内容协作和自动评测看板。首版不建设教师管理、多租户院系门户、学生实时监控或复杂商业分析。后续维护自动化必须围绕明确内容任务，保留人工发布与回滚能力。
