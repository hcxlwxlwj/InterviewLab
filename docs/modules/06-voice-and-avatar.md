# 06｜中文语音与 3D 虚拟面试官

> 版本：v0.1 · 日期：2026-10-03 · 文档性质：首版设计与验收依据，尚未实现。相关设计：[总体架构](../architecture.md)、[模拟面试](05-mock-interview.md)、[数据与接口](../data-and-interfaces.md)、[评测计划](../evaluation-and-roadmap.md)。

## 1. 目标与用户需求

语音帮助学生练习口头回答和对话节奏，3D 角色通过倾听、思考和说话状态提供可理解的互动反馈。两者服务于训练流程；角色美术质量不能替代反馈质量，也不能成为训练必须成功的技术依赖。

学生需要看到系统正在听、正在识别还是正在回答，能够纠正误识别、打断面试官、关闭声音并切换文本。首版只采集麦克风，不采集摄像头。声音特征、角色注视或沉默时长均不用于判断人格、情绪、专业能力或录用概率。

## 2. 首版范围与交互流程

进入会话后由学生主动开启麦克风，展示录音状态与文本替代入口。允许首次设备检查和短句试说，设备检查结果不进入面试记录。浏览器麦克风访问需要用户授权和安全上下文，生产部署必须提供 HTTPS；未授权、未选择权限或设备不可用时保留文本入口。[MDN getUserMedia 文档](https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/getUserMedia)

首场默认采用“说话 → 转写 → 学生纠正/确认提交 → 面试官回答”的轮次交互。局部转写实时显示，最终转写进入可编辑回答区。可提供自动提交选项，必须由学生明确开启并记录该选择，页面说明转写将作为学生回答，保留更正入口；ASR final 与确认提交在数据上仍分开。开始新问题时，学生可听语音并看字幕；打断后停止当前播放和生成，角色立即离开说话状态。

首版一位风格化半身角色，支持待机、倾听、思考、说话四种状态及音频驱动嘴型。支持隐藏 3D、静音、字幕和文本继续训练。模型、服装、动作和声音的使用授权需记录，不以工具或代码许可代替素材授权。

## 3. 输入输出与数据

| 类型 | 内容 | 保存原则 |
|---|---|---|
| 输入音频 | 麦克风音频片段、轮次标识 | 仅用于当前 ASR 处理，默认不长期保存原始录音 |
| 转写 | `transcript.partial`、`transcript.final` | partial 为临时界面数据，final 是待确认文本 |
| 确认回答 | `user.answer.commit` 文本与版本 | 作为 `Turn` 正式内容保存并用于评估 |
| 输出语音 | `audio.chunk`、音频序号与文本关联 | 按会话生成和播放，不作为学生能力数据 |
| 播放状态 | 已播放音频位置、对应文本片段 | 用于打断对齐与运行诊断，不等同完整文本已被听到 |
| 角色状态 | 当前交互阶段和音频能量 | 前端表现状态，不作为业务真相来源 |

通用事件使用 `session_id`、`turn_id`、`generation_id`、`seq`，没有轮次或生成时对应字段可为空。生成批次用于取消，序号只表示同一连接内顺序，用于去重和检测缺失；跨重连从服务器状态与已确认回合版本恢复，不能假定前端已接收事件就是最终记录。音频元信息还需明确编码、采样率和播放顺序，具体数值由适配器协商与服务商实测确定，不在立项文档中绑定未经验证的格式。

## 4. 处理逻辑与技术方案

前端采集并分片发送音频，同仓库 Node 实时网关鉴权后连接 ASR 适配器。ASR 中间结果只更新字幕；确认回答交给共同的会话编排器。LLM 文本按可读句段送入 TTS，流式音频与文本关联返回浏览器。Next.js Web 服务和实时网关可以分进程部署，但复用同一权限、会话与数据模块，首版不拆为独立微服务。

客户端维护受限音频队列，只播放当前有效生成。WebSocket 提供双向实时通信，但其常用浏览器接口不会自动提供背压控制，因此项目需自行限制发送与播放缓冲，队列积压时停止追加、提示状态或降级文本，不持续增长内存。[MDN WebSocket 文档](https://developer.mozilla.org/en-US/docs/Web/API/WebSocket)

打断流程同时执行四项操作：浏览器停止当前播放并清空队列；上报已播放进度；服务端取消对应 LLM/TTS 请求并将 `generation_id` 标为失效；晚到事件按生成标识丢弃。服务商取消失败也不能继续呈现内容。对话记录区分生成完整文本与已播放部分，后续请求“重复一下”依据实际播放进度组织，而不是把完整生成视为学生已听到。

采用 Three.js 渲染，使用 VRM 和 three-vrm 加载及控制角色；three-vrm 官方项目提供在 Three.js 中使用 VRM 的能力。[three-vrm 官方项目](https://github.com/pixiv/three-vrm) 嘴型依据正在播放的音频能量变化驱动，并平滑开闭，首版不承诺逐音素精确同步。音频未播放、暂停或取消时嘴型闭合。倾听对应麦克风采集，思考对应确认提交后的响应等待，说话对应实际音频播放，单纯收到 LLM 文本不能触发说话状态。

## 5. 接口与模块依赖

通过 `/api/v1/sessions/{id}/stream` 建立已鉴权的双向连接，生产使用 WSS；HTTP `/api/v1/sessions/{id}/turns` 和 WS `user.answer.commit` 复用确认提交逻辑。客户端发送 `audio.input`、`audio.input.end`、`user.answer.commit`、`user.interrupt`、`audio.playback.progress` 及 `session.finish`；服务端返回 `transcript.partial`、`transcript.final`、`assistant.text.delta`、`audio.chunk`、`assistant.cancelled`、`session.state`、`error`。已提交内容通过 `PATCH /api/v1/sessions/{id}/turns/{turn_id}` 纠正并增加 revision。事件名称、二进制音频承载及恢复行为以[接口概要](../data-and-interfaces.md)为准。

语音模块依赖 ASR/TTS 服务适配器，业务编排依赖会话模块；角色只依赖前端交互状态与播放分析。服务商密钥保留在服务端，不能嵌入页面或角色资源。选择服务商时使用统一中文样例比较专业词、数字、人名、噪声、首段延迟、取消表现及费用；是否支持流式和可靠取消需实测，不由品牌名称推定。

## 6. 异常与边界

- 权限被拒或设备占用：解释当前原因，允许文本继续；不重复强制弹出浏览器权限。
- 自动播放受限：通过学生主动点击启用播放，未成功播放时不显示角色持续说话。
- 识别错误：允许编辑数字、名称和专业词；更正影响正式文本，报告不评价 ASR 错误本身。
- 误判停顿：保留“继续说”和手动提交能力，短暂沉默不必自动结束。自动提交后可更正，不能把未经确认的片段直接送去评分。
- ASR 或 TTS 故障：当前已有文字保留，分别降级为键盘输入或文本输出；不必终止整个会话。
- 弱网与断线：停止新生成及音频发送，提示重连；恢复时获取确认轮次，不补播过时音频。未提交音频和草稿由学生重新确认，不默默拼接或重发全部音频。
- 3D 加载失败、性能不足：切为静态角色或文本布局；释放渲染资源，不影响问题提交和报告。
- 结束/离开页面：停止麦克风轨道、播放、网络连接和渲染循环；后台不继续录音。

## 7. 贯穿示例

纯合成学生小林在产品运营模拟中说“60 人报名，45 人到场”，ASR 显示“六十人报名，四十五人到厂”。小林在提交前改为“到场”，报告引用修正后的确认文字，不以“到厂”判断表达差。

面试官正在播放“你做了哪些工作，如何判断活动效果？”时，小林说“请慢一点”。浏览器上报已经播放到“你做了哪些工作”，清空剩余音频；服务端取消旧生成，3D 嘴型闭合。新回复缓慢重述题意，旧音频即使晚到也不播放。角色加载失败时，小林仍可看到问题、继续回答并获得报告。

## 8. 验收条件

| 验证场景 | 通过条件 |
|---|---|
| 权限与采集 | 仅在主动启用后采集音频，拒绝授权仍可训练，退出停止采集 |
| 转写与确认 | partial 不持久化评分；final 可编辑；确认版本进入正式记录 |
| 打断竞态 | 播放队列清空，旧生成晚到数据丢弃，记录依据已播放进度 |
| 状态与嘴型 | 音频播放时说话，取消/暂停时闭嘴，等待生成时不假装播放 |
| 服务降级 | ASR、TTS、角色单独失败均有文本继续路径 |
| 队列与重连 | 限制缓冲，重复和乱序事件可识别，不盲目重放旧音频 |
| 中文样例 | 测试数字、岗位术语、低音量和环境噪声，统计准确性与纠正负担 |

语音延迟和角色性能以实际目标设备测量，分别记录确认提交到首段文本、首段音频到实际播放、打断到停止播放的时延，不能用模型首 token 延迟代替学生感知时延。[评测计划](../evaluation-and-roadmap.md)集中定义初始待验证基线：安静环境中文字符错误率≤12%、关键字段正确率≥95%；指定网络条件、10 场并发及至少 200 个有效回合中，确认回答到首片文本 P95≤5 秒，语音端点确认到首段可播放音频 P95≤6 秒。未达标需定位瓶颈并评审调整目标，不作为已经实现的保证。

## 9. 优先级与后续扩展

P0-T 为文本替代和确认语义；P0-V 为中文语音、打断、流式播放、故障降级及一位3D 角色的状态和音频嘴型，属于首版后续阶段必需交付；P1 为更自然动作、更精确嘴型和扩展角色。扩展前先验证素材授权、端侧负载和教学价值。摄像头情绪识别、写实数字人和根据口音推断能力不属于首版。
