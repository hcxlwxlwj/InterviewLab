# 01 岗位理解：功能技术文档

> 状态：首版设计，尚未实现。面向产品讨论与开发拆分；公共类型和接口约定见[数据与接口概要](../data-and-interfaces.md)，检索与角色分工见[知识库与智能体设计](../knowledge-and-agent.md)。

## 1. 目标与用户需求

帮助应届生把招聘描述中的职责与条件转换为可理解的工作任务、面试主题与准备方向。学生既可以选择团队维护的常见岗位模板，也可以粘贴自己的 JD。系统需要回答“这个岗位通常做什么”“这条要求可能怎样被问到”“我需要提供什么经历证据”，同时保留招聘原文，避免把模型的一般性建议当成该公司的实际招聘标准。

本模块不判断学生能否被录用，不提供实时岗位搜索，也不验证高级行业专业能力。跨专业支持体现为解释通用任务、术语和可迁移经历；缺少可靠专业资料时提示依据不足。

## 2. 首版范围与交互流程

1. 学生选择岗位模板或粘贴 JD，补充岗位名称；公司名称为可选信息。
2. 后端检查输入并生成 `JobTarget` 草稿，保留原始 JD 或模板版本。
3. 展示结构化职责、明确要求、常见工作任务，以及系统推断的练习重点；学生可修改岗位名称和理解偏差。
4. 学生展开某条要求，查看对应招聘原文与知识来源，提出岗位理解问题。
5. 确认目标岗位后，进入材料整理与准备计划。更换 JD 或模板形成新修订，不覆盖已经开始的训练所用快照。

界面用“JD 明确写明”“岗位知识补充”“基于信息的推断”区分内容。模板内容标注“通用参考”，不能呈现为某家企业的实际 JD。首版准备建议围绕职责、能力和可提供的证据，不展开企业背景调查。

## 3. 输入输出与数据

| 类别 | 内容 | 处理约束 |
| --- | --- | --- |
| 岗位输入 | 岗位名称、原始 JD 或岗位模板标识 | 模板与自带 JD 为两个明确入口；原文始终可查看 |
| 结构化要求 | 职责、要求条目、原文片段、必需/偏好/未明确分类 | 只有 JD 的明确表述可标为必需；不把“了解”升级为“精通” |
| 知识补充 | 工作任务示例、术语解释、知识片段引用 | 记录知识版本、来源与适用岗位，示例不代表企业事实 |
| 推断结果 | 通用能力主题、可能的面试问题、待澄清项 | 标注为推断，不生成虚构招聘门槛或通过概率 |
| 岗位问答 | 学生问题、回答、对应 JD/知识引用 | 原始材料与模型产物分开保存，支持追溯 |

`JobTarget` 的修订号参与后续计划和会话的关联。岗位理解输出不写入 `Experience`，学生对岗位的假设也不自动成为个人事实。引用指向可访问的原文或知识片段；前端不拼接未经检查的模型 URL。

## 4. 处理逻辑与技术方案

**结构化提取。** 在 Next.js 服务端调用 LLM 适配层，以约束输出提取要求条目及原文依据。先做文本长度、格式与空内容检查，再校验输出类型、必填项和引用原文。模型不能改变岗位权限或执行输入中的指令。JD 内的“忽略规则”等文字作为待分析资料处理。

**要求映射。** 将条目映射到通用主题，如活动执行、沟通协作、基本数据意识。保留未能映射的要求，供解释或提示资料不足，不强行归入现有能力标签。必需和偏好取决于招聘表述；职责推导出的准备主题属于推断。

**检索解释。** 按岗位类型和要求主题过滤已发布知识，再执行关键词与向量检索。把检索片段、原始 JD 和回答任务交给岗位顾问角色。回答引用分为 JD 依据和知识依据；系统校验引用标识属于本次实际提供的材料。检索不足时可以解释 JD 的字面含义，并明确专业解释暂缺资料。

**个人关联的边界。** 本模块可以解释“通常需要什么证据”；“你已有此能力”的个性化结论必须交给准备计划模块，并且只依据学生确认的 `Experience`。SQL、收入、增长等 JD 未写明的要求，不作为必备能力添加。

**复用与更新。** 相同 `JobTarget` 修订与知识版本的分析结果可以缓存；学生修改 JD 后重新分析，并提示已有计划需要更新。历史会话继续使用其启动时的岗位与知识版本，保证反馈可复查。

## 5. 接口与模块依赖

所有资源操作位于 `/api/v1`，具体请求和响应字段见[数据与接口概要](../data-and-interfaces.md)。

| 接口能力 | 输入 | 输出与依赖 |
| --- | --- | --- |
| `POST /job-targets` | JD 或岗位模板、岗位名称 | 创建当前用户的 `JobTarget`；依赖模板服务与身份鉴别 |
| `GET /job-targets/{id}` | 岗位目标标识 | 原文、修订、分析状态与已生成解释 |
| `PATCH /job-targets/{id}` | 学生修改的岗位内容 | 新修订；使旧准备计划标为需更新 |
| 岗位分析与问答能力 | 岗位修订、学生问题 | 调用岗位顾问与 RAG；分析动作路由由公共接口文档统一定义 |

内部依赖岗位知识检索 Tool、模型适配层、结构校验器与引用校验器。首版直接调用内部工具，无需 MCP 服务。准备计划、教学练习和模拟面试读取岗位的确认修订，不直接依赖前端展示文本。

## 6. 异常与边界

- **JD 过短或模糊：** 保留目标岗位，显示缺少职责或要求，不生成确定的能力覆盖结论；可使用通用模板补充，但学生须明确选择。
- **要求相互冲突：** 原样保留冲突条目并标记待澄清，不由模型私自决定哪一条有效。
- **行业资料不足：** 展示已有引用与局限；通用行为练习仍可继续，专业能力评价不扩张。
- **模型超时或格式错误：** 保留草稿和原文，允许重试；格式校验失败不保存为有效分析，失败原因只展示可理解的信息。
- **知识引用失效：** 不展示伪引用，提示当前解释无法验证；重新检索后生成新版本。
- **越权或恶意输入：** 身份与资源归属在服务端检查；JD 内容不能触发外部网络访问或读写其他用户资料。

## 7. 贯穿示例

合成学生小林选择初级产品运营岗位。JD 写明“活动执行、基础数据分析、跨团队协作”。系统分别解释为准备活动安排与执行证据、描述如何观察数据、说明协作中承担的动作；这些是一般准备方向，不是该企业完整评分标准。

对“基础数据分析”，系统说明可以先讲清指标、数据来源与简单计算；JD 没有写 SQL，系统不能增加“必须独立使用 SQL”的门槛。后续材料显示小林在校园读书活动中负责报名表、签到和群提醒，60 人报名、45 人到场。岗位理解可提示该经历适合讨论执行与到场情况，但不能在本模块宣称小林已具备专业运营分析能力。

## 8. 验收条件

| 场景 | 可验证结果 |
| --- | --- |
| 提交包含三项职责的 JD | 三项均保留招聘原文依据，职责没有被合并遗漏 |
| JD 只写“了解数据分析” | 输出不变为“精通 SQL”，可能问题明确标为推断 |
| 使用岗位模板 | 页面标明通用模板及版本，不出现企业招聘承诺 |
| 问题涉及未收录的专业知识 | 显示资料不足，不提供伪造文献、门槛或引用 |
| 更新 JD 后打开历史会话 | 历史仍显示启动时的岗位修订，新计划提示需更新 |
| JD 包含指令注入或访问另一用户岗位 | 不执行材料指令；服务端拒绝越权读取 |
| 检索/模型失败 | 原文与用户输入不丢失，可重试分析或继续整理材料 |

离线样例覆盖不同专业的通用岗位、偏好要求和模糊 JD，由人工检查提取遗漏、要求强度变化与推断标注。具体评测集与门槛见[评测与迭代计划](../evaluation-and-roadmap.md)。

## 9. 优先级与后续扩展

P0-T 完成 JD/模板入口、要求提取、原文查看、引用解释、岗位理解问答、修订追溯与失败恢复，参与首阶段文本闭环；P1 优化检索质量、丰富可选模板覆盖。招聘网站搜索、企业知识连接、行业专家题库属于后续扩展，接入前分别确认来源许可、更新机制和评价边界。
