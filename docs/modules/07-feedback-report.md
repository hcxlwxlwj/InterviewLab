# 07｜证据反馈报告

> 版本：v0.1 · 日期：2026-10-03 · 文档性质：首版设计与验收依据，尚未实现。相关设计：[需求分析](../requirements.md)、[智能体设计](../knowledge-and-agent.md)、[数据与接口](../data-and-interfaces.md)、[重练与进展](08-retry-and-progress.md)。

## 1. 目标与用户需求

报告要回答三个问题：本次哪些地方讲清楚了、哪些信息没有说明、下一次具体怎样练。学生需要能够核对的回答证据和可执行建议，不需要缺乏依据的总体好坏判断。报告引用学生已确认文字，将观察范围限定在本次题目和回答，避免把一次练习推断为完整能力评价。

首版分别评价表达、岗位理解、经历证据三个维度，采用 1～4 的行为锚点与 `not_observed`。不计算加权总分、排名或录用概率，不把更多字数自动当作更好，不以声音、外貌、口音或背景经历数量评分。教学练习中的即时建议可以复用评价逻辑，但与完整模拟报告的呈现时机不同。

## 2. 首版范围与交互流程

会话结束后先展示“回答已保存，正在生成反馈”，允许离开并稍后从历史进入。报告依次展示本次训练范围、逐题反馈、三维度观察、优先改进项及单题重练入口。每项评价旁边可展开对应问题和引用原文，学生无需信任不可核对的总结。

逐题反馈包含一个有效表现、一个主要缺口和一个下一步动作，避免堆砌泛化建议。缺少正面证据时不强行制造优点；未回答、跳过或与某维度无关的题目采用未观察状态。报告可以展示基于已确认事实的表达示例，但必须标记为参考组织方式，并保留待学生补充之处。

学生发现识别或材料错误时返回修正入口。纠正会话回答会产生新 revision，已有报告标记过期并生成对应新版本；编辑独立经历或岗位材料只影响准备计划与新会话，过去会话保留当次冻结依据，删除的影响除外。已有报告不能悄悄改写，模型、评分标准或知识库升级也不能把历史评分直接重算成“学生进步”。

## 3. 输入输出与数据

输入包括封存的 `Session`、问题与最终确认 `Turn`、岗位及经历快照、评价标准版本和引用来源。报告只读取当前学生有权限访问的材料；不把个人材料加入共享知识库。使用哪些问题和回答版本必须写入报告的生成元信息。

输出 `Report` 包括状态、版本、训练范围、维度观察、逐题证据、建议、重练候选、知识引用及限制说明。证据引用至少关联 `turn_id` 和确认版本，并包含精确摘录与定位信息；报告生成后再次核验摘录是否存在于对应文本。完整字段以[数据接口文档](../data-and-interfaces.md)为准。

| 维度 | 评价内容 | 不应据此推断 |
|---|---|---|
| 表达 | 是否回应问题，职责、行动、结果是否易于理解 | 学生人格、整体沟通能力、说得长就更好 |
| 岗位理解 | 是否在回答中说明岗位任务、判断或取舍 | 未被问到的专业能力已经缺失 |
| 经历证据 | 是否有可追溯的个人动作、结果和边界 | 只要说出数据就已验证事实真实 |

## 4. 处理逻辑与技术方案

结束操作将报告任务写入 PostgreSQL job 表，报告状态独立为 `pending → generating → ready`，失败为 `failed`。会话完成不意味着报告就绪。工作进程读取任务，构建去除未确认草稿的上下文，并固定本次岗位、标准和回答版本。

采用“先整理证据、再评价、最后校验”流程。先定位每题中职责、行动、结果、推理及缺口；再按锚点输出结构化评价；最后以程序检查枚举、引用、建议依据和事实边界。引用不成立或输出不合法时，在预算允许且无成功结果下最多有界重试一次，仍不通过则显示生成失败及重试入口，不向学生展示未经校验的内容。短回答可整体处理，长会话逐题分析后汇总，汇总必须继承逐题证据，不能创造新事实。

维度锚点按岗位场景细化，首版共同含义如下：1 为有明确相关回答但关键内容仍模糊或未回应；2 为部分说明且存在明显缺口；3 为基本清楚并有相应证据；4 为清楚、具体且能说明边界或反思。`not_observed` 表示没有足够可评价材料，与 1 分不同。锚点是形成性反馈刻度，不是经过标准化验证的心理或职业测量。

评价学生陈述的质量与验证事实真实性需分开。“60 人报名、45 人到场”可以作为回答中的结果信息，不能证明小林独立造成活动成功。建议不得从报名人数推导不存在的收入、增长率或 SQL 技能。必要时引用岗位或教学知识帮助解释建议，并区分学生证据与外部知识来源。

异步任务以会话封存版本和报告版本去重；并发消费者不能生成互相覆盖的结果。服务超时可有限重试并记录尝试状态；修改回答后旧任务失效，新报告基于新快照生成。原始简历、录音与完整报告正文不写入运行日志。

## 5. 接口与模块依赖

`POST /api/v1/sessions/{id}/finish` 封存会话并发起报告；`GET /api/v1/sessions/{id}/report` 查询状态与可用内容，`POST /api/v1/sessions/{id}/report/retry` 请求缺失或重试失败/过期报告。failed会话有已确认回答时也通过此入口请求部分报告，保持会话失败终态，注明中断与覆盖范围；无有效回答时不评分。`PATCH /api/v1/sessions/{id}/turns/{turn_id}` 更正回答后令旧报告过期，并按新 revision 生成报告。实时连接可发送 `report.ready` 通知，但客户端仍需重新获取报告并校验权限；没有在线连接也能通过历史记录查询。

依赖会话模块提供确认版本，材料与岗位模块提供事实和要求，知识库提供已发布评价标准，LLM 适配器执行受约束生成，job 处理模块负责异步执行。报告不直接调用不受控外部工具核查学生经历，也不执行简历中的指令；内容是待分析的数据，不能改变评价系统规则。

重练入口向重练模块传递来源会话、题目、报告版本、目标薄弱点和允许使用的事实。不存在有效题目或问题已删除时，不创建悬空的重练关联。

## 6. 异常与边界

- 空会话：显示没有已确认回答，提供重新练习；不生成空泛评分。
- 提前结束：只评价已完成部分，标记岗位能力覆盖不足。
- 非题意回答：说明当前文本与题目的关联有限，不据此评定全部能力低。
- 资料矛盾：指出“回答与已确认经历存在差异，需要确认”，不直接认定作弊或自动修正事实。
- 过度归因：将“活动到场率”与“个人贡献”分开，提醒尚未说明哪些行动影响结果。
- 模型失败：报告与会话独立，学生仍能看到逐题记录和重试入口。
- 内容标准更新：保留旧报告依据，新标准只影响新任务；需要重新分析时显式生成新版本。
- 删除会话或确认经历：按照统一删除策略移除相关报告及派生任务，不保留私有快照残留。仅删除临时简历文件时保留独立确认经历，并明确告知学生。

## 7. 贯穿示例

纯合成小林首次说“我负责组织活动，效果很好”，报告引用这句话，指出“组织”和“很好”没有说明个人动作与结果，建议按“我的职责—做了什么—观察到什么”补充。报告不能写“小林缺乏运营能力”，因为一次模糊回答不足以支持这种结论。

追问后的确认回答包含报名表、签到、群提醒及 60 人报名、45 人到场。报告可肯定追问后结果更具体，同时指出尚未解释如何用这些信息复盘。岗位理解维度若没有相关回答，应显示未观察；JD 提到基础数据，也不能把小林不存在的 SQL 经历写成弱项或宣称他不会分析。下一步推荐重练活动执行题，重点是在首答中一次讲清职责、行动与数据边界，而不是无视追问中已补充的信息。

## 8. 验收条件

| 场景 | 通过条件 |
|---|---|
| 引用核对 | 每条引用能定位到对应确认版本；不存在的摘录不能进入 ready 报告 |
| 三维度区分 | 表达、岗位理解、经历证据各有依据或未观察；无加权总分 |
| 事实约束 | 合成案例不出现增长、收入、独立 SQL 或虚构个人贡献 |
| 版本更正 | 更正后报告使用新版本，旧任务不会覆盖；版本与依据可追溯 |
| 异步故障 | 会话完成独立于报告状态；任务重试不重复生成可见报告 |
| 评价限制 | 提前结束、跳过和短回答明确观察范围，缺证不强行评分 |
| 建议质量 | 建议指向具体回答缺口，包含可执行练习，不只写“加强表达” |

使用合成样例与人工双人评阅验证证据匹配、过度归因、建议可行性与标准一致性；评分相关性仅作为诊断，教学有效性采用新题和独立人工评价，见[评测计划](../evaluation-and-roadmap.md)。

## 9. 优先级与后续扩展

P0-T 为异步报告、精确引用、三维度反馈、重练入口、报告版本管理和锚点人工校准；P0-V 为语音确认与纠正后沿用相同评价边界；P1 为扩展岗位锚点及学生长期目标的更细反馈。后续能力标签必须有对应题目与证据，不能从形成性练习分数升级为职业筛选或录用决策。
