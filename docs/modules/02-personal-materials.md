# 02 个人材料：功能技术文档

> 状态：首版设计，尚未实现。公共数据约定见[数据与接口概要](../data-and-interfaces.md)；材料权限、存储和模型适配层见[总体技术架构](../architecture.md)。

## 1. 目标与用户需求

帮助应届生将简历与零散经历整理为可用于教学和追问的事实材料，减少反复输入，同时让学生掌握“系统理解了哪些事实”。简历解析只是辅助录入，不能自动证明经历真实，也不能在学生确认前成为个性化断言的依据。

本模块支持 PDF/DOCX 简历与手动填写项目、实习、校园经历。学生可以没有简历，也可以只提供一段经历。训练不要求完整个人履历，不要求填写身份证、住址或其他与训练无关的信息。

## 2. 首版范围与交互流程

1. 学生上传可提取文本的 PDF/DOCX，或选择直接填写经历。
2. 文件通过服务端类型、大小与结构检查后保存；后台提取文本并生成候选字段。
3. 页面展示候选经历与对应原文，提醒学生核对名称、时间、个人职责、行动和结果。
4. 学生修改、确认或忽略候选项；只有确认后的内容进入可供 Agent 使用的事实视图。
5. 学生补充未写入简历的经历、澄清团队成果和个人贡献，然后进入准备计划。
6. 后续可以修订、取消确认或删除经历；历史训练使用当时事实版本。删除文件与删除独立已确认经历是不同操作，按公共删除策略执行。

简历解析结果分为“待核对材料”和“已确认经历”两区。批量确认必须在学生能查看各候选项的界面完成；上传成功或模型解析成功不等于学生确认。首版不做扫描件 OCR、简历自动润色或就业资格认证。

## 3. 输入输出与数据

| 对象 | 主要内容 | 可用于训练的条件 |
| --- | --- | --- |
| `ResumeDocument` | 文件标识、类型、解析状态、文本与候选字段、原文定位 | 仅作为原始资料；未确认字段不作为事实 |
| `Experience` | 经历名称与类型、时间、背景、个人职责、行动、结果、缺失项 | 学生明确确认后进入事实视图 |
| 事实来源 | 来源类型、确认时间、经历确认版本 | 解析核对阶段可看原文；清理后回溯确认版本，不保留未确认原文片段 |
| 未确认或未知项 | 解析疑点、模糊数字、团队与个人角色不明 | 保留为待澄清，不能自动补全 |

结果字段允许定量、定性或“尚未提供”，不强制学生编造百分比。团队成果与个人贡献分开表达：团队有 45 人到场，不等于个人独立带来 45 人增长。默认建议不把联系方式传入模型；模型只接收当前任务所需的经过确认字段。

当前事实修订用于新计划和新会话；历史 `Session` 保存引用的经历版本快照。简历文件、提取文本、候选项、确认事实分开存储。上传与提取稿在完成确认或放弃后触发清理；无论是否确认，默认自上传起最长保留 24 小时。上传页面说明到期未确认需重新上传或手填；长期材料仅保留独立确认经历、来源类型、确认时间与经历版本，不另外保存未确认原文片段。文件名可在当前上传界面显示，不进入长期日志；系统不承诺可再次打开已清理的原文件。

## 4. 处理逻辑与技术方案

**文件接收。** 上传在服务端校验扩展名与实际内容类型，首版配置默认单文件上限 10 MiB，限制解析的总页数与解压后体积；具体阈值由公共配置维护。DOCX 不执行宏或内嵌对象，PDF 不执行脚本。文件放在私有存储，下载与预览必须经过资源归属检查，不能使用可猜测的公开地址。

**文本提取。** PDF 使用文本层提取，DOCX 提取段落和表格内容。任务可异步执行并记录进度，保留失败原因。多栏 PDF 可能出现顺序错位，因此展示提取结果并要求核对。没有可用文本层的扫描 PDF 直接提示首版不支持 OCR，提供手动填写入口，不让 LLM 从不存在的文本猜测经历。

**候选结构化。** LLM 按约束输出把提取文本转换为候选经历；来源片段必须在提取文本中存在。数字保留原始单位与措辞，含糊表述进入待核对项。模型不确定的字段返回缺失，不推算毕业时间、工作时长或技能熟练度。输出格式不合法时不生成可确认的错误材料。

**确认与事实视图。** 学生提交确认后，服务端保存确认人、时间和内容修订。Agent 的读取 Tool 返回当前用户已确认的经历及明确的缺口，不直接读取整个简历文件。确认代表学生认可其表述，不代表系统外部核验。取消确认后，未来训练不能再用该条经历作事实；既有会话通过快照解释其当时依据。

**材料更新与删除。** 新简历产生新的 `ResumeDocument`，与已有经历按名称、时间等提示可能重复，但不自动合并或覆盖。学生决定更新现有经历还是新增。删除文档联动处理文件、文本和未确认候选项，不自动删除独立已确认经历；入口必须说明其保留范围。删除经历先列出关联会话、准备计划和记录影响，再按用户选择级联清理会话、报告、比较、快照与相关计划，避免在历史副本中残留被删除事实。清理过程在服务端授权，并与全系统删除策略一致。

## 5. 接口与模块依赖

| `/api/v1` 接口能力 | 输入 | 输出与约束 |
| --- | --- | --- |
| `POST /resume-documents` | 文件或受控上传完成标识 | 创建解析任务，返回 `ResumeDocument` 与状态 |
| `GET /resume-documents/{id}` | 文档标识 | 解析状态、当前用户可读的候选项与来源 |
| `POST /resume-documents/{id}/confirm` | 学生核对与修改的候选内容 | 生成独立确认经历，不把剩余候选自动确认为事实 |
| `DELETE /resume-documents/{id}` | 文档标识 | 清理文件、提取稿与未确认候选，保留独立确认经历 |
| `POST /experiences` | 手动填写的经历 | 创建当前用户经历，记录明确的确认状态 |
| `GET /experiences` | 当前用户上下文、筛选条件 | 返回经历及确认状态，不跨用户检索 |
| `PATCH /experiences/{id}` | 修改、确认或取消确认 | 新修订与状态；提示相关准备计划需更新 |
| `DELETE /experiences/{id}` | 经历标识 | 按公共删除约定处理关联数据 |

依赖文件存储、后台任务、文本提取器、LLM 适配层和身份模块。准备计划、面试官与教练通过已确认经历读取 Tool 获取最小材料，不直接复用解析器。接口字段与错误格式以[数据与接口概要](../data-and-interfaces.md)为准。

## 6. 异常与边界

- **扫描 PDF 或文本乱码：** 不创建虚构候选，说明限制，保留手动填写入口；用户可删除失败文件。
- **超限、伪造扩展名或损坏文件：** 拒绝解析并显示原因，不把原始异常堆栈返回页面。
- **数字或职责不明确：** 提醒学生核对，不添加“提升 30%”之类的结果，也不把协助改为负责。
- **完全没有经历：** 可先做岗位理解与通用自我介绍训练；相关评价显示材料不足，允许稍后补充。
- **模型/任务失败：** 支持重试，幂等任务避免重复经历；学生的手动修改不能被重试结果覆盖。
- **上传内容包含指令：** 作为用户资料处理，不获得调用工具、修改确认状态或读取其他材料的权限。
- **删除中的并发任务：** 先标记删除，停止或丢弃后续解析结果；不能在删除完成后重新写回候选项。

## 7. 贯穿示例

小林上传简历，校园读书活动中写到“60 人报名，45 人到场”。提取器生成候选项后，页面要求小林填写个人职责。小林确认自己负责报名表、签到和群提醒，没有声称独立策划全部活动，也没有独立 SQL 分析经历。

系统保存这一确认版本。读书活动的到场比例可以根据 45/60 计算为 75%，但计算不能变成“活动增长了 75%”。准备计划可建议小林讲清提醒和签到如何执行；示范回答只能使用这些确认事实。若模型解析成“负责增长分析”，学生纠正后，错误候选不再进入训练上下文。

## 8. 验收条件

| 场景 | 可验证结果 |
| --- | --- |
| 正常 PDF 与含表格 DOCX | 提取主要文本，候选项能定位来源，学生可逐项修改 |
| 扫描 PDF、损坏文件、超限文件 | 有明确结果和手填入口，无编造解析内容 |
| 上传后未确认 | Agent 的个人事实视图为空或仅含其他已确认经历 |
| 学生把“协助”改为“负责报名表” | 新训练仅使用修改后的确认内容，确认版本与来源信息可追溯 |
| 两次提交同一解析任务或确认请求 | 不生成重复经历，不覆盖学生已保存的修改 |
| 访问其他用户文档或经历 | 服务端拒绝；文件地址不能绕过权限读取 |
| 删除文档时后台解析刚完成 | 删除后不恢复文件、候选项或派生记录 |
| 自上传起24小时仍未确认，或已确认/放弃 | 到期或相应清理任务清除原文件与提取稿；已有独立确认经历仍可使用 |
| 删除已被会话使用的经历 | 先显示关联影响，执行后相应会话、报告、比较与快照不残留事实 |
| 团队结果无个人贡献说明 | 系统保留缺口，不自动推断个人能力或量化成果 |

验证使用合成文件；真实用户材料不进入仓库或公开测试报告。删除、权限和事实保真检查与[评测与迭代计划](../evaluation-and-roadmap.md)衔接。

## 9. 优先级与后续扩展

P0-T 完成可提取文本的 PDF/DOCX、手填、候选核对、确认事实视图、修订和删除，支撑文本闭环；P1 优化多栏排版提取与重复材料提示。OCR、简历版本对比和更多文件格式后续单独评估，均保持学生确认这一入口。

用户需求与最小化材料原则见[需求分析](../requirements.md)，Agent 上下文权限见[知识库与智能体设计](../knowledge-and-agent.md)。
