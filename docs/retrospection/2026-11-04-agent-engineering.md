## 本次实现

1. 从既有单一内容源编译 1000 岗位、8000 原题、九类官方基础摘要、通用面试方法及原评价草案；四种用途在同一版本服务管理，评价参考不进入面试检索。新增 v2 派生索引表、断点构建、摘要复用、过滤与混合检索、预览/发布/回退。
2. 锁定 LangChain 模型集成与 LangGraph；简历、规划、单轮使用三条有界图。保留旧策略与 Agent，业务库及任务仍是权威。新默认关闭，既有会话冻结运行时与知识；报告和比较保留原语义并按源快照选择适配。
3. 结构化简历分析、原句锚点、版本复用、删除防护与独立准备队列；创建面试后持久等待依赖，再规划观察目标。新增准备状态、重试、显式简化和同一开始门槛。
4. 文字、语音、视频沿用回答/SSE/WS/续答/TTS 协议；准备不计时、不开媒体，视频不新增上传或分析。准备提示移到共享顶部，避免语音折叠区遮挡。
5. 追加 0007 迁移与 Drizzle 定义/快照；HTTP schema、共享 DTO、通用客户端及 OpenAPI 同步。文档按老师五目录拆分主题、补充 Mermaid、保留旧入口与原需求编号。

## 待验收与决策

独立人工 90% 问题审查、严重虚构率评审、全量正式真实向量发布、专业细分覆盖、跨岗负例校准、真实麦克风/ASR/TTS/摄像头与分段媒体延迟尚未完成。九条相似摘要自查询不是召回质量基准；固定回答对照也不是自然用户对话实验。

补充真实完整闭环初次在 interviews.advance 输出校验失败；随后真实逐题报告成功，但汇总一次违反原评分证据规则、第二次超时。旧运行时的同一报告脚本亦因固定“总分为空”断言与当前六维报告合同不符而失败；脚本已改为现有 nullable 百分制及无代码不评分检查，不改变应用评分规则。随后 --reports-only 真实复测通过：原报告逐题/总结、固定题重练报告及比较均 ready，日志 real-graph-reports-recheck.log；仍不抹除此前失败。

从[合成响应抓取](evidence/background-validation-20261104.json)定位到旧正则未识别“我只负责”，误将已知职责当缺失；“包含哪些功能模块”也未覆盖。补齐表达识别与正反例后，真实完整闭环最终通过（real-graph-closed-loop-final.log），包含准备、提问、报告、固定题重练和比较；报告汇总仍发生首次无效输出并在任务重试后成功，不能抹除重试代价。

简历上下文进一步收紧为只填补能由项目/实习原句证明的缺口；教育字段不能跳过项目背景，否认经历或切换项目不被旧简历覆盖，且不伪造回答证据。

因此保留 `INTERVIEW_AGENT_RUNTIME=legacy` 默认。graph 可在本机显式启用，不能宣称计划全部效果门槛已通过。发生回归先关闭新入口默认切换，保留数据，按运行指南恢复原知识指针；不删表、不改写已应用迁移、不清除现场。

## 手动试用反馈：岗位与阶段联动

用户选择 AI产品设计师后出现“岗位或阶段不可用”。该岗位 ai-designer 的原始发布阶段只有 campus，配置页却沿用 internship，并在岗位元数据加载完成前请求面试类型。已将配置表单延后到岗位读取完成后初始化；切换岗位时保留仍支持的阶段，否则选择该岗位的有效阶段，只呈现支持的阶段选项。没有扩大或伪造岗位适用阶段，后端过滤保持不变。

新增三项回归：AI 产品设计师默认校招、切换保留有效阶段及其他设置、全部 1000 岗位从两种初始阶段进入后均能读取五种面试类型。仓库检查共 196 项测试通过，配置页开发编译和公开岗位接口检查通过。浏览器自动实测被工具中止，原因是无法可靠识别 Windows 当前页面地址；本轮不宣称已完成修复后的浏览器交互验收，待用户刷新原页面确认。

## 手动试用反馈：语音显示在听但无输入结果

用户已允许麦克风，但讲话后没有可见转写。只读检查显示语音连接建立、播报回执存在，没有保存的语音回答；这些记录不能证明浏览器实际采集到了人声，也不能据此认定麦克风故障。真实供应商固定合成句 TTS → ASR 检查通过，且结束包之前已有流式转写；本轮最终联通耗时 9302ms，是合成音频传输检查耗时，不是端到端接话延迟。

原界面把服务端 ready 当成正在听，缺少采集帧检查和输入设备反馈。已增加许可完成后恢复 AudioContext、实际设备选择和本机音量条、5 秒无采集帧检测、处理器/上下文失败处理，以及直接可见的实时转写。文字、语音、视频共用输入控制；视频补充单独挂断语音入口以便更换设备，不结束面试或修改摄像头链路。

新增三项受控回归覆盖指定设备、权限后恢复上下文、首帧就绪、静音、处理器错误及无帧超时。仓库检查 199 项通过；真实浏览器所选设备、实际人声输入和修复后的多轮语音仍待用户复测，未确认的根因不写成已定位。

用户随后确认是麦克风选错，并要求恢复简洁页面。已撤掉新增设备下拉框、音量条、诊断文案、直接转写区和为更换设备新增的视频挂断入口，删除对应设备枚举与音量计算；设备仍由系统/浏览器选择，转写按原界面保留在折叠记录。底层首帧检测、上下文恢复与错误清理继续保留，测试同步改为验证沿用浏览器输入而不指定设备。用户的设备原因反馈不等于三模式多轮体验已全部验收。
