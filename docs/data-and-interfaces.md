# 数据与接口概要

版本：v0.1 · 日期：2026-10-03 · 状态：设计基线；逻辑模型与接口意图，不是已实现 API 或完整 OpenAPI 合同。

## 1. 数据边界与共用约定

业务记录使用服务端生成的不透明 ID，时间存储为 UTC，界面按用户时区显示。`owner_id` 来自已验证身份，不能接受模型或客户端传入值决定归属。学生只能读写自己的材料和记录；维护接口使用单独维护权限。

用户资料不进入共享向量知识库。个人材料的提取草稿、学生确认经历、会话快照与回答是不同对象；模型生成的描述不自动成为学生事实。`version/revision` 表示对象变更，所有报告引用明确版本。

## 2. 逻辑实体与关系

| 实体 | 最小必要信息 | 关系与用途 |
| --- | --- | --- |
| User/Profile | 用户ID、登录身份、显示名、语言、时区、偏好 | 一个学生拥有多个岗位目标和训练记录；不强制采集学号/身份证 |
| JobTarget | 模板ID/版本或JD文本、岗位名、提取职责/要求、来源定位、学生确认状态、版本 | 一个用户可以有多个目标；模板与自带JD分别标来源 |
| ResumeDocument | 私有存储定位、格式、大小、解析状态、提取草稿、确认/清理时间 | 临时上传与解析对象；确认内容写入独立 Experience/Profile |
| Experience | 类型、背景、个人职责、行动、结果、confirmed状态、来源类型、确认时间、版本 | 可来自简历确认或手填；缺少结果时允许为空，取消确认后不能进入新会话 |
| PreparationPlan | 岗位目标版本、经历版本、能力与证据关联、材料缺口、训练主题 | 是建议计划，不是雇佣匹配分数；修改材料后标记待更新 |
| KnowledgeDocument/Chunk | 类型、来源、授权、适用岗位、发布时间/审核时间、版本、片段与位置、嵌入模型版本 | 只检索已发布知识；撤回保留来源定位而不继续召回 |
| Question/Rubric | 题目、目标能力、适用模式、难度、追问提示、评分锚点、版本 | 与知识来源关联；评分版本在会话开始时冻结 |
| Session | 用户、mode、status、岗位与经历私有快照、目标、预算、题目覆盖、时间、版本 | 一个会话多个回合；可用parent_session_id/parent_turn_id关联重练 |
| Turn | 顺序、说话者、问题目标、问题文本、生成ID、实际播放进度、转写草稿、确认文本、revision | 引用只基于确认回答；同一主问题有多次追问/回答 |
| Report | 会话、报告状态、回答版本摘要、三维反馈、证据引用、建议、标准/模型/提示版本 | 一个会话可有多个报告版本，只有匹配当前回答的ready版本为有效 |
| RetryComparison | 原会话/回合/报告版本、重练会话、目标、两次回答引用、变化、不可比原因 | 不覆盖原回答；涉及已删除记录时同步删除比较 |
| Job | 类型、唯一任务键、状态、尝试次数、下次执行时间、错误类别 | 解析/报告/比较/入库任务持久化；过期或删除对象不得再发布 |
| Invocation/Audit | request_id、任务/会话引用、操作、提供商、版本、用量、耗时、错误、时间 | 默认无原始简历/逐字稿/音频；用于排障、费用和变更审计 |

核心关系：`User → JobTarget/Experience/Session`；`Session → Turn/Report`；`Session → 重练Session → RetryComparison`；`KnowledgeDocument → Chunk`；题目与评分标准可引用知识。所有私有快照仍属于学生数据，并纳入删除。

结构示意（字段为概要，不要求把此 JSON 原样建表）：

```json
{
  "session_id": "session_demo",
  "mode": "mock",
  "status": "completed",
  "job_target_version": "job_demo:v1",
  "experience_versions": ["experience_demo:v1"],
  "rubric_version": "rubric:v1",
  "report_status": "pending"
}
```

## 3. 状态与版本

### 材料与知识

材料解析：`uploaded → parsing → needs_confirmation → confirmed`，任一步可 `failed`；手填无需伪造解析成功。确认指学生明确接受/编辑提取内容。文件清理后保留不含原文的任务状态，确认经历独立存在。

知识发布：`draft → reviewed → published → retired`。发布版本不可原地改写；修改产生新版本。内容撤回后不再进入新检索，旧引用保留出处/版本和撤回标记；不得因此公开用户会话。

### 会话

| 状态 | 含义 | 允许进入的下一状态 |
| --- | --- | --- |
| draft | 模式、目标等未完成 | ready；用户也可删除 |
| ready | 已确定可用目标与材料；无简历可通用训练 | in_progress；尚未开始可回draft重新配置 |
| in_progress | 正在训练，提交回答和生成问题 | paused、ending；不可恢复故障可failed |
| paused | 停止生成/播放，保留确认回合 | in_progress、ending；不可恢复故障可failed |
| ending | 正在取消活动任务和保存最后有效回合 | completed；持久保存失败可failed |
| completed | 会话结束，报告可能仍生成中 | 不重开；重练创建新会话 |
| failed | 无法继续，保留已保存回答与原因 | 不重开；可从有效材料开始新会话 |

可恢复的提供商失败优先提示重试/转文本，不直接将整个会话置为failed。用户离开页面不意味着成功完成；重连读取服务端状态，再决定恢复或结束。

failed保持会话终态，但有已确认回答时允许独立请求部分报告，明确标记中断原因与观察范围；通过报告重试入口请求任务，不将失败会话改为completed。没有已确认回答时只展示恢复/重练入口，不生成能力评分。

模拟模式目标5～10分钟，最多6个主问题、每主问题最多2次追问。10分钟提示收尾，不截断正在回答；12分钟到达安全上限时取消生成/录音并保存已确认内容。总经过时间含暂停，以避免无限占用。教学模式也使用12分钟资源上限，可结束后继续新会话；主问题覆盖上限不强制用于单题分步指导。

报告：`pending → generating → ready/failed`，重试先回pending。回答纠正产生新revision，旧报告保留版本但标记已过期，异步生成新报告。生成器提交前检查版本摘要与删除状态，过期任务不得覆盖较新报告。

### 转写与实际播放

ASR `partial` 只用于临时字幕，`final` 也不自动等同用户确认。首场默认学生确认后提交；如学生明确开启自动提交，记录该选择并允许纠正。关闭录音或收到final时，未提交内容不纳入评分。

问题记录保存完整生成文本，并单独记录实际播放字符/分段进度。用户在半句话处打断时，后续上下文说明实际播放边界；生成后未播放的问题不计为已覆盖题目。

## 4. 关键业务接口

前缀 `/api/v1`。下表说明责任与主要输入输出，分页、完整错误枚举、字段长度等在实现时补充 API 合同。异步操作返回任务ID或对象pending状态，不让浏览器保持长时间普通请求。

| 方法与路径 | 用途 | 主要输入 → 输出 |
| --- | --- | --- |
| GET /job-templates | 列出已发布岗位模板 | 筛选 → 模板概要与版本 |
| POST /job-targets | 保存模板选择或JD草稿并请求解读 | 模板ID或JD → 岗位目标ID、解读任务 |
| GET/PATCH /job-targets/{id} | 查看/确认/修改岗位目标 | 学生修订与version → 当前目标；变更标记计划待更新 |
| POST /job-targets/{id}/questions | 岗位解释问答 | 问题、目标版本 → 回答、知识/JD引用或资料不足说明 |
| POST /resume-documents | 上传私有简历并解析 | PDF/DOCX → 文档ID、解析状态 |
| GET /resume-documents/{id} | 获取提取草稿 | 文档ID → 草稿与歧义项 |
| POST /resume-documents/{id}/confirm | 确认/编辑材料 | 认可字段与revision → 已确认档案/经历ID |
| DELETE /resume-documents/{id} | 删除文件与提取稿 | 文档ID → 清理任务；独立确认经历保留并提示 |
| GET/POST /experiences | 查看/手填经历 | 确认事实 → 经历ID、版本 |
| PATCH/DELETE /experiences/{id} | 修改、确认、取消确认或删除经历 | version/确认状态/删除影响确认 → 更新或关联删除任务 |
| POST /preparation-plans | 请求准备建议 | 岗位目标、经历选择 → 计划ID、任务状态 |
| GET /preparation-plans/{id} | 查看准备重点 | 计划ID → 能力关联、缺口、主题 |
| PATCH /preparation-plans/{id} | 保存学生选择的重点与顺序 | 主题选择、version → 更新偏好；不修改生成依据或确认事实 |
| POST /sessions | 创建待开始配置 | mode、目标、主题、材料版本 → 会话ID、draft/ready |
| PATCH /sessions/{id} | 开始前修改配置 | mode、主题、材料选择、version → 更新配置；已开始会话不允许改模式/材料 |
| GET /sessions/{id} | 查看当前状态 | 会话ID → 状态、已确认回合、版本和报告状态 |
| POST /sessions/{id}/start | 校验选定版本、冻结材料并请求首题 | 幂等键 → in_progress；选定材料已变更先要求确认更新 |
| POST /sessions/{id}/pause、/resume | 暂停/恢复 | 当前版本 → 新状态，暂停时取消活动代 |
| POST /sessions/{id}/turns | 提交已确认回答或教学操作 | 文本、问题/回合ID、操作类型、幂等键 → 已保存回合及后续任务 |
| PATCH /sessions/{id}/turns/{turn_id} | 纠正转写/回答文本 | 新文本、revision → 新revision，报告/比较待更新 |
| POST /sessions/{id}/finish | 正常或提前结束 | reason、幂等键 → completed与报告pending状态 |
| GET /sessions/{id}/report | 读取当前报告 | 会话ID → pending/generating/ready/failed，ready时含证据与版本；未请求任务时说明无报告 |
| POST /sessions/{id}/report/retry | 请求缺失、失败、过期或中断会话的部分报告 | 会话与当前回答版本 → 新任务；不重跑面试，零有效回答不评分 |
| POST /sessions/{id}/retries | 从一个问题开始重练 | 原turn_id、目标、报告版本 → 新guided会话ID |
| POST/GET /retry-comparisons | 请求/获取重练比较 | 原turn_id、new_turn_id、两份回答revision及重练会话ID → 比较状态/结果；不默认选择最后一条回答 |
| GET /history | 查询学生历史 | 分页、主题、模式 → 会话列表与比较摘要 |
| DELETE /sessions/{id} | 删除一次训练及派生记录 | 删除影响确认 → 清理任务状态 |
| DELETE /me/data | 删除当前学生全部个人材料与训练 | 显式删除确认 → 清理任务状态；身份是否注销另行提示 |

教学操作类型最少包含`answer`、`request_hint`、`request_explanation`、`skip`；模拟模式拒绝request_hint，允许解释题意或跳过。客户端不能通过mode字段绕过当前服务端模式。选定版本在ready阶段等待开始，start成功后才形成不可随个人编辑改变的私有快照；开始前配置可修改，已开始会话换模式需新建关联会话。

维护接口单独置于 `/api/v1/admin`：内容导入/审核/发布/撤回、任务与版本查看、用量/故障汇总。学生端不可调用；首版可以由受权维护脚本触发同一服务模块，不要求完整后台 CMS。

## 5. 实时接口与事件

WebSocket：`/api/v1/sessions/{id}/stream`，公网使用WSS，通过同源认证或短时会话凭证鉴权；不将长期密钥放入URL。文本也可使用同一事件连接，连接失败可用HTTP提交及状态轮询。

事件信封含 `type、session_id、turn_id（有回合时）、generation_id（涉及生成时）、seq、payload`。seq仅定义同一连接内顺序；跨重连以服务端保存的回合版本为准，不推定所有帧已重放。音频二进制帧在适配层约定采样率/编码/分段ID；本文不锁定供应商格式。

| 方向 | 事件 | 含义 |
| --- | --- | --- |
| 客户端→服务端 | user.answer.commit | 提交确认文本；与HTTP提交走同一权限/幂等逻辑 |
| 客户端→服务端 | user.interrupt | 取消活动generation并停止播放；不自动提交回答 |
| 客户端→服务端 | audio.input、audio.input.end | 音频输入/结束；均不代表已确认回答 |
| 客户端→服务端 | audio.playback.progress | 客户端实际播放分段进度，辅助记录已听内容 |
| 客户端→服务端 | session.finish | 结束；与HTTP finish复用同一服务 |
| 服务端→客户端 | transcript.partial、transcript.final | 临时/最终转写，最终稿仍可纠正 |
| 服务端→客户端 | assistant.text.delta | 当前代生成文本增量 |
| 服务端→客户端 | audio.chunk | 当前代可播放音频分段，客户端按顺序排队 |
| 服务端→客户端 | assistant.cancelled | 当前代取消；客户端清队列和嘴型 |
| 服务端→客户端 | session.state | 权威状态/当前回合版本 |
| 服务端→客户端 | report.ready | 报告生成完毕，可重新读取；不是唯一通知机制 |
| 服务端→客户端 | error | 业务错误及可否重试/转文本 |

浏览器先响应用户打断停止本地播放，再通知网关；网关取消模型与TTS并阻止旧代输出。客户端同样丢弃取消代的迟到事件。角色说话由音频实际播放驱动，不能由text.delta驱动。

断线后重新鉴权，读取会话状态和最后确认回合。未提交音频/草稿由学生重新确认；不默默重发所有帧。重连/finish竞态和取消后的迟到帧见[语音与3D](modules/06-voice-and-avatar.md)。

## 6. 幂等、校验与错误

创建会话、提交回答、finish和报告任务使用用户作用域幂等键；重复操作返回同一业务结果，不重复计回合。客户端只请求动作，服务端校验状态、归属、版本与限额。写工具使用同一事务和权限逻辑，模型无法绕过。

错误概要：`{code, message, retryable, request_id}`。最少区分未授权、输入不支持、版本冲突、当前状态不允许、资料不足、提供商超时、预算达到和任务失败。用户提示不暴露供应商密钥/内部栈；引用不足是内容结果，不一定是HTTP故障。

异步任务使用`对象ID+输入版本+任务类型`作为唯一键；删除、版本更新后旧任务必须失效。外部调用最多一次有界重试，仅在仍有预算且无已成功结果时；重试不能扩大用户事实或生成第二份矛盾报告。

## 7. 安全、保存与删除

受邀账号通过成熟认证组件提供服务端会话，浏览器使用HttpOnly/Secure cookie；生产支持会话过期与退出。写接口检查同源/CSRF，连接鉴权也检查会话归属。所有读取、下载与修改均检查owner，不只在历史列表过滤。

原型上传限制建议10 MiB，只支持可提取文本的PDF/DOCX；校验扩展名、类型与解析结果，禁止执行宏、外链加载和嵌入内容，拒绝密码文件及异常压缩文件。解析在受限任务进程中进行，超时返回手填入口。OCR属后续扩展。

建议默认保存策略（产品/运维配置，不是法律期限）：

| 数据 | 默认保存 | 删除行为 |
| --- | --- | --- |
| 原始简历/提取草稿 | 确认/放弃后触发清理；无论是否确认，自上传起最长24小时 | 清除文件、草稿、缓存，保留不含正文的处理状态；到期未确认需重新上传或手填 |
| 原始音频 | 仅实时处理，不长期持久化 | 结束/取消/断线丢弃临时缓冲 |
| 确认经历/训练历史/私有快照 | 保存至学生主动删除 | 服务数据不可访问立即生效；物理清理任务目标24小时内完成 |
| 运行日志 | 脱敏元数据30天 | 不以日志备份全文；私有对象引用按删除规则移除/去关联 |
| 备份 | 限权轮换，最长30天 | 不恢复已删除对象；恢复时重放删除清单，页面说明备份清除窗口 |

删除简历文件不会默默删除已确认经历，入口明确说明。删除经历先列出相关会话、报告、比较与准备计划，让学生确认级联影响，然后删除对应派生私有数据。删除会话覆盖回合、报告、相关比较、快照、任务与私有缓存。任务提交前再次检查删除标记，避免清理后重新写入。

界面不宣称点击删除即所有备份立即抹除；提供清理状态与实际窗口。真实用户材料不进入git或默认评测集，外部模型只接收必要字段；供应商数据处理条件在试用前核验。

## 8. 接口与数据验收场景

- 同一提交重试两次只生成一个回答回合，同一finish只产生一个当前输入版本报告任务。
- 用户A不能读取用户B的简历、经历、报告或实时流，维护权限亦不由模型内容授予。
- 会话completed且报告pending时，界面显示等待而非空白成功；报告失败可以独立重试。
- failed会话有已确认回答时可请求部分报告，保持失败终态并标明范围；零回答不评分。
- 教学会话多次重答时，比较请求明确选择两个回合及revision，不随“最新回答”漂移。
- 改正转写后报告引用新版本，旧报告和旧任务不能覆盖；比较亦标记过期并重算。
- 修改个人经历不改写过去会话；删除经历却必须覆盖私有快照和关联派生数据。
- 取消代音频迟到不播放，重连不重复提交回答，未听完的问题不被当成完整已问。
- 原始文件/音频按策略清理；数据库备份恢复演练重放删除清单。

有关三维锚点、工具权限和离线评测分别见[知识库与智能体](knowledge-and-agent.md)、[评测与迭代](evaluation-and-roadmap.md)。
