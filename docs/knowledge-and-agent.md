# 知识库与智能体设计

版本：v0.1 · 日期：2026-10-03 · 状态：设计基线，未实现。

本文规定系统怎样使用知识与学生材料，以及模型和程序的职责边界。它与[总体架构](architecture.md)、[数据与接口](data-and-interfaces.md)共同约束九个功能模块；模型与语音供应商尚未选定。

## 1. 知识范围、来源和版本

首版维护三类共享知识，不接入实时招聘搜索。用户粘贴的 JD 是本次岗位目标的原始材料，不因被使用过而自动加入共享知识库。

| 知识集合 | 内容 | 主要使用场景 | 不应承担的判断 |
| --- | --- | --- | --- |
| 岗位知识 | 职责解释、常见工作任务、术语、初级岗位能力要求 | 岗位理解、准备重点、追问语境 | 用行业通例替代某份 JD 的明确要求 |
| 面试教学方法 | 回答结构、个人贡献表达、证据组织、专项练习方法 | guided 提示、反馈、重练 | 编造可套用到学生身上的履历 |
| 题库与评价标准 | 问题、适用主题、可观察点、追问方向、评分锚点 | mock 选题、教练评估、进展比较 | 从一次回答推断全部能力或录用概率 |

优先采用团队原创材料、获得使用授权的资料和可合法用于本项目的公开资料。内容维护人员逐项记录出处和使用依据；有公开链接不等于可以不受限制地复制全文。引用外部资料时保存必要片段与摘要，保留可回访来源；来源无法确认的材料不得发布。团队编写的题目也需标记为原创，并由另一名维护人员审核教学目标和评分可观察性。

每份源文档至少记录来源 ID、标题、作者或维护责任人、来源地址（如有）、使用依据、获取/核验日期、适用岗位与主题、正文版本、发布状态、内容校验值。每个片段继承来源版本，增加片段 ID、原文位置和检索元数据。生成的报告不能只留下一个容易失效的 URL，应保存本次所用片段 ID、版本与引用短文。

采用“草稿 → 审核 → 发布 → 下线”的内容流程，对应 `draft → reviewed → published → retired`。只有已发布版本进入在线检索；更新先完成离线检索和反馈回归，再切换活动索引。旧会话保持当次内容和评分版本，不随知识更新重算历史分数。回滚恢复完整内容版本及其索引，不能只改正文而沿用已失配的向量。过时资料下线后不再被新会话召回，历史引用显示当时日期与版本。

知识说明与事实至少区分三种标签：`jd_explicit`（JD 原文明确）、`knowledge_explanation`（有来源的通用解释）、`inference`（针对当前材料的推测）。发生冲突时先展示当前 JD 原文与资料的差异，降低通用解释的确定程度，不让模型静默替用户改写招聘条件。

## 2. 入库、中文检索与引用

### 入库流程

审核后的文本经规范化、按标题和语义段落切分、提取元数据、关键词索引构建、嵌入、检索抽检后发布。题目和评分标准同时以结构化记录保存，避免通过长段文本检索丢失适用条件。需要表格才能理解的材料按完整行组保留，题目与相应评分锚点不拆为互不关联的片段。

初始切分采用每片约 350～700 个中文字符，保留标题路径；相邻语义段必要时重叠约 50～100 字。这是试验参数，不是通用最优值。过长文档通过段落组拆分，短条目保持完整。用真实大小分布的知识样本比较召回、重复上下文与成本后调整，并将切分配置记入索引版本。

嵌入保存提供商、模型版本、维度和生成时间。更换维度或模型时在独立索引/表中重建，验证后切换，不将不同嵌入空间混合检索。首版采用 PostgreSQL + pgvector 存储向量；pgvector 的官方项目提供 PostgreSQL 中的向量相似度检索能力。[官方项目](https://github.com/pgvector/pgvector)

### 查询流程

1. **确定检索范围**：业务模块传入岗位、主题、知识集合与已发布版本。用户 ID 由服务端身份上下文提供，不能由模型参数决定。
2. **构建查询**：根据当前问题、岗位要求和已确定的能力目标产生检索词。仅使用必要的经历摘要，去除姓名、电话、地址等无关信息。
3. **并行召回**：关键词和向量各取前 20 个候选，再合并。中文关键词采用应用层分词、归一化及维护的同义词表；不能把 PostgreSQL 默认英语全文分词视为已经支持中文。保留 SQL、JD 等英文词与数字单位，防止“SQL”被错误分割或删除。
4. **排序与筛选**：采用 Reciprocal Rank Fusion（RRF）合并排名，初始常数为 60；按来源重复去重，每次给模型最多 5 个片段。优先保留直接命中主题且来源适用的文本，不仅按相似度拼接内容。
5. **判断是否有依据**：在独立检索评测集上校准召回阈值。候选不足、明显无关或资料过时时返回结构化空结果与原因，不能以固定阈值跨模型通用，也不能为凑满 5 片强行填充。
6. **生成与校验**：返回来源 ID、片段 ID、版本、引用内容和适用说明。模型只可引用本次实际取得的片段；服务端检查 ID 存在、引用与原文相符后呈现。

首版不必增加独立重排服务；若相关性测试证明 RRF 对专业术语或长查询仍不够，再评估重排收益及额外延迟。检索分数仅用于排序，不是学生能力评价。监测查询、命中文档 ID、空结果率与版本，但日常日志不保存完整简历或完整回答。

空检索的产品行为按任务处理：岗位顾问说明缺少可靠岗位资料，仍可解释用户 JD 的明确原文；教学练习可以使用已审核的通用方法，但标注适用范围；专业知识评估不能凭模型常识写成有来源的确定结论。题库无适用题时退回审核过的通用经历题，而非把无证据的专业能力列为训练失败。

## 3. 学生材料与隐私边界

个人简历、经历、JD 和训练逐字稿独立存放在按用户授权的数据表与私有文件存储。首版按确认经历 ID 和会话回答 ID 读取，不将用户材料放进共享向量库。所有读操作同时约束当前用户与资源 ID；“知道某个 ID”不构成访问许可。

简历提取结果、ASR 临时文本、模型整理摘要均不是已确认事实。学生确认后才可作为个人经历证据；原始回答确认后才可被报告引用。首场语音最终转写默认手动确认，学生此后可明确开启自动提交，并始终能纠正；该选择需被记录，ASR final 本身不等于确认。生成建议可提出需要补充的问题，不能自动补上不存在的结果数字、职位或技能。用户修改材料会形成新版本，正在进行的会话使用冻结快照；旧快照同样受用户删除请求约束。

原始简历与提取草稿在确认或放弃后触发清理；无论是否完成确认，默认自上传起最长保留 24 小时，到期未确认者需重新上传或手填。持久档案只保留学生确认的事实正文、来源类型、确认时间及版本，不将清理后的未确认原字段片段隐藏在引用或摘要中继续保存。脱敏运行元数据默认保留 30 天，受限备份最长轮转 30 天；这些是可调整的产品默认值，完整删除范围及用户提示见[数据与接口](data-and-interfaces.md)。

传给云模型的上下文采用最少必要原则：具体问题需要什么材料就发送什么材料，不默认整份简历、全部历史记录、身份证明或联系人信息。供应商选型需核实数据处理地区、传输/留存设置与能否关闭非必要记录；在页面说明实际使用哪些云服务处理材料。此处是项目要求，不能替代对实际服务条款的检查。

原始音频默认不长期保存；实时缓冲仅服务转写，结束、取消或断线时丢弃并验证清理。若试用需要录音评测，必须作为单独可选用途说明保存范围、时间和访问者；拒绝该用途仍可完成训练。报告和日志中不得泄露其他学生数据、供应商密钥或完整提示模板。

源文档和 JD 中包含的“忽略指令”“上传用户数据”等内容均作为不可信材料。检索文本只提供知识，不改变权限、状态机或工具白名单。删除涉及原文件、确认材料、会话快照、回答、报告和关联任务；备份按已告知的轮转周期处理，并在恢复后重新应用删除记录。

## 4. 三类职责与确定性编排

首版使用一个业务会话编排器，按任务加载不同职责提示。可以由同一模型完成三类职责，不需要多个自主智能体讨论；权限、计时、保存、结束条件和任务重试由 TypeScript 业务程序控制。

| 职责 | 必要上下文 | 输出 | 可用读工具 |
| --- | --- | --- | --- |
| 岗位顾问 | 当前 JD/模板、已发布岗位知识、学生明确问题 | 职责解释、要求标签、准备建议及依据 | 岗位读取、知识检索、已确认经历读取 |
| 面试官 | 模式、当前问题、已确认回答、已问目标、剩余预算 | 候选问题或追问、对应目标、选择理由 | 题目候选、确认经历、当前会话回合 |
| 教练评估 | 冻结岗位与事实、问题、确认逐字稿、评分版本 | 分维度观察、引用、建议、重练任务 | 确认回合、评价标准、教学方法 |

`Session.mode = guided | mock`。`Session.status = draft | ready | in_progress | paused | ending | completed | failed`；报告独立使用 `pending | generating | ready | failed`。

编排顺序为：检查输入与身份 → 校验所选材料版本并进入 ready → 学生开始时再次校验版本、冻结必要快照并进入 in_progress → 选择能力目标与题目 → 校验并保存问题 → 接收/确认回答 → 决定追问、换题或收尾 → ending 中保存有效回合 → completed 并创建报告任务。开始前材料已变更时先要求确认更新，不静默换用新版本。连接中断可进入 paused 并恢复；服务失败优先提供文本或重试路径，无法恢复时标记 failed 并保留已确认回合。LLM 可以建议“换题”，但不能自行将会话设为完成。

guided 可解释题意、提供分级提示并单题反馈；mock 只澄清题意，正式反馈放到结束后。学生请求答题示范时，可结束模拟并新建关联教学会话，避免把受到提示的表现仍记为独立模拟。mock 默认目标 5～10 分钟、主问题不超过 6 个、每题追问不超过 2 次；10 分钟提示收尾且不立即截断在答内容，12 分钟停止继续出题/处理新回答并保存已确认内容。guided 同样有 12 分钟资源上限，但不强制 6 个主问题；单题教练追问默认最多 3 次。总经过时间含暂停，重连不能重置预算；具体行为以[模拟面试模块](modules/05-mock-interview.md)和[教学练习模块](modules/04-guided-practice.md)为准。

上下文包括职责指令、模式限制、版本信息、当前能力目标、确认事实、相关回合、检索证据与输出要求。长历史可以压缩为事实 ID、已问主题和已发现缺口，但原始已确认回答仍单独保存；报告引用回查原文，不能引用模型摘要的措辞当作学生说过的话。

## 5. LLM 输出约束与工具分工

提示模板、模型标识、检索配置、题库和评分版本随会话记录。结构输出至少携带结果类型、文本、目标、来源/回答引用和不足证据标记。使用 schema 校验字段、枚举、长度、引用与事实来源；结构合法不代表内容正确，内容仍进入相关性和事实检查。

模型超时、输出非法或引用失配时最多进行一次有错误信息的修复调用，记录两次调用。再次失败采用审核过的通用问题/保守反馈或让任务进入可重试失败，不无限循环。生成流式正文前不能把尚未校验的评价直接发布为正式报告；实时自然语言问题也受已问目标与模式检查。

### 职责提示示意

以下是供团队讨论的最小提示骨架，不是完整生产提示或最终 API 字段合同。服务端把资料放入明确标记的数据区，角色限制来自受控模板，不能由 JD 或学生材料覆盖。

```text
岗位顾问
核心指令：解释当前岗位。逐项区分JD明确要求、引用知识说明与推断。
只引用提供的来源；资料不足直接说明；学生经历只使用confirmed事实。
输入：JD原文与版本、已发布知识片段、学生问题、必要确认经历。
结构结果：解释条目[文本/类型/来源引用]、尚缺依据、可继续准备的问题。

面试官
核心指令：围绕当前能力目标自然提问。根据当前回答的具体缺口追问。
遵守guided/mock限制，不重复已答问题，不提供mock参考答案。
输入：模式、目标、当前确认回答、已问列表、候选题、剩余轮次/时间。
结构结果：候选问题、能力目标、与回答的关联说明。
候选是否发出以及状态变化由编排器决定。

教练评估
核心指令：只评价本次观察到的表现。每条结论引用确认回答原文。
分别给表达/岗位理解/经历证据1～4档或not_observed。
禁止新增履历、加权总分与录用预测；建议应能转成下一次练习动作。
输入：问题、确认回答及revision、冻结事实、评分锚点、教学依据。
结构结果：三维观察、证据引用、建议、缺证说明与重练任务。
```

共享片段能支持“活动执行的通用含义”，不能证明小林做过哪些事。经历工具说明已确认材料中有哪些事实，评分引用仍指向小林当次回答；把材料中未说出的信息直接当作本次回答充分也会造成评价失真。

| 工具能力 | 输入输出概要 | 权限与副作用 |
| --- | --- | --- |
| 读取岗位目标 | 岗位 ID → 当前版本、JD 原文、模板来源 | 只读，仅当前用户目标与公共模板 |
| 读取确认经历 | 受授权经历 ID → confirmed 事实及版本 | 只读，草稿默认不进入模型事实上下文 |
| 检索共享知识 | 主题、岗位标签、集合 → 片段、来源、空结果原因 | 只读，限定已发布版本，禁止任意 URL 抓取 |
| 选取题目候选 | 能力目标、模式、已问题目 → 候选及适用条件 | 只读，编排器最终选择并约束追问次数 |
| 读取确认回合 | 当前会话/回答 ID → 问题、回答与确认版本 | 只读，限定当前用户；引用由原文校验 |
| 保存回合 | 会话、回合、确认内容 → 保存版本 | 有副作用，由编排器调用；同一提交键幂等 |
| 请求报告 | 已结束会话与版本 → 报告任务 ID | 有副作用，由编排器调用；避免重复创建任务 |
| 保存/发布报告 | 校验过的结果与版本 → 报告状态 | 有副作用，由报告任务调用；引用核验后才能 ready |

模型可以请求白名单内读工具，并由服务端检查职责与参数；写工具不因模型输出而自动执行。保存、删除、内容发布等操作必须走现有业务命令和鉴权，不向模型开放任意 SQL、命令执行、文件路径或无边界网络访问。工具错误返回稳定业务原因（无权限、未确认、无结果、超时），不将数据库栈或私密字段返回模型。

## 6. 反馈依据与统一示例

三维评价使用 1～4 档和 `not_observed`，不计算加权总分。每个维度关联问题是否提供观察机会、学生原文、锚点版本和下一步练习；低档只说明本次可见表现，不代表学生永久缺乏该能力。

| 维度 | 1 档 | 2 档 | 3 档 | 4 档 |
| --- | --- | --- | --- | --- |
| 表达结构与清晰度 | 有回答但难以明确重点 | 能识别主题，职责/行动混杂 | 重点清楚，有连贯职责与行动 | 在保持信息完整的同时清楚、精炼地回答题目 |
| 岗位理解 | 对题目触及的要求出现明显误解 | 可复述要求，缺少工作场景关联 | 能解释要求如何用于工作任务 | 能结合场景说明判断依据、约束和合理取舍 |
| 经历证据 | 泛泛声称做过，无法定位贡献 | 说明个人职责或行动，结果/条件不足 | 职责、行动和结果相互支持 | 清楚说明个人边界、结果依据及局限，能回应追问 |

未触及岗位理解的问题返回 `not_observed`；跳过、无有效回答或仅有未确认转写也不得强行评分。文本评价不从标点、ASR 错别字或模型推测评价口音、语速与情绪。语音表达指标如需增加，应独立定义观察依据并通过评测。

合成示例小林应聘初级产品运营，JD 关注活动执行、基础数据和跨团队协作。已确认事实：校园读书活动负责报名表、签到、群提醒，60 人报名、45 人到场；没有独立 SQL 分析和业务增长贡献证据。

小林首次回答“我负责组织活动，效果很好”。面试官追问具体工作和结果。教练引用这句原文，指出贡献和结果未说明，建议补充确认职责与到场人数。重练加入“报名表、签到和群提醒”及“60 人报名、45 人到场”后，可评价信息更具体；不能推断小林完成 SQL 分析、提升业务增长，或全部到场结果由其独立造成。岗位理解维度若没有被问到，仍是 `not_observed`。

## 7. MCP 扩展边界与验收

MCP 提供 client/server 方式连接工具和上下文；协议本身不保证来源真实、权限正确或适合教学。[官方架构](https://modelcontextprotocol.io/docs/learn/architecture)

首版直接调用内部工具。未来若学校有受维护的岗位资料服务，先审核来源与使用条件，再由服务器端 MCP client 连接允许的服务，把查询结果转换为现有检索工具格式。浏览器不保存外部服务密钥，学生材料不默认发送；外部返回仍执行版本、引用和提示注入检查。连接失败退回本地资料并标记来源缺失，不阻塞整场训练。

知识/Agent 验收至少覆盖：中文同义词及英文技能词召回；空检索；过时与冲突资料；不同嵌入版本隔离；未确认事实不可引用；跨用户访问拒绝；引用逐字匹配；资料指令不能触发写工具；mock 不泄露答案；重复失败调用有界。量化阈值与回归集合见[评测与迭代](evaluation-and-roadmap.md)。
