# 结构化简历与个人画像

本轮基于 2026-11-04 拉取的 main（eb42446），兼容语音、报告改动。旧个人模块 PR 未合入，因此先移植基础实现，再扩展。

## 当前流程

PDF/TXT 导入→提取文本→按标题识别候选字段→本人核对标准模板→确认保存版本→面试配置选择已确认版本→开始面试冻结材料→模型上下文读取冻结材料。

模板字段：姓名、电话、邮箱、城市、教育、技能、项目、实习、荣誉、自我介绍。目前教育和经历等按文本分区保存，尚未拆为逐条学校/项目数组。规则识别不会推断未提供事实，无明确标签的信息需要手动补充。也可以完全手填，无需原始文件。

原始文件不持久化；PDF 最大5MB/30页，扫描件不支持OCR。当前不是大模型智能抽取，没有配置模型密钥也能完成导入和核对。

## 个人中心

个人资料和画像：显示名、简介、城市、求职阶段、优势、学习目标；目标岗位方向；偏好：时长、作答方式、风格、默认简历。概览仅展示本人填写及已确认简历，不推断人格或自动生成能力评分。目标岗位入口维护求职方向，尚未实现个人JD/收藏岗位业务。面试配置读取默认简历、风格、作答方式，时长映射为现有5/10分钟。

## 数据与边界

accounts拥有设置；resumes拥有材料和版本；面试编排通过材料服务读取本人已确认的指定版本，冻结在现有InterviewSnapshot.personal_material。历史面试不会随简历编辑漂移。v1与v3提问输入均包含该材料。未配置模型时不得宣称真实提问成功。

JSON字段扩展保存structure，既有文本材料仍可编辑。迁移0006_personal_materials避开主分支0005语音迁移；使用IF NOT EXISTS兼容此前本地个人模块预览库。新表仍需后续补齐Drizzle schema快照。软删除不等于物理清除历史快照，完整关联清理仍待完善。

## 运行与验证

本机Docker服务使用compose.personal.yaml，随机认证密钥位于忽略的.env.personal。开发代码已同步至容器。181项单元/接口回归、类型检查和后端构建通过；额外用合成账号验证结构化材料、版本、画像、岗位方向及偏好持久化。真实模型简历追问未验收，需要配置LLM与worker。页面访问 /me、/me/resumes、/me/preferences、/me/saved-jobs、/interview/setup。
