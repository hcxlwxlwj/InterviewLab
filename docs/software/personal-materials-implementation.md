# 结构化简历与个人画像

更新：2026-11-05。在原结构化材料实现上增加版本化事实分析和面前准备；保留原导入、个人设置与核对流程。

## 当前流程

PDF/TXT 导入→提取文本→按标题识别候选字段→本人核对标准模板→确认保存版本→后台事实分析→配置选择版本→冻结材料与知识并规划→准备就绪后开始面试。

模板字段：姓名、电话、邮箱、城市、教育、技能、项目、实习、荣誉、自我介绍。目前教育和经历等按文本分区保存，尚未拆为逐条学校/项目数组。规则识别不会推断未提供事实，无明确标签的信息需要手动补充。也可以完全手填，无需原始文件。

原始文件不持久化；PDF 最大5MB/30页，扫描件不支持OCR。导入和字段初步识别仍采用确定性规则，无模型密钥也能完成核对；确认后的面试事实分析是独立模型任务，失败不撤销已保存简历。

## 个人中心

个人资料和画像：显示名、简介、城市、求职阶段、优势、学习目标；目标岗位方向；偏好：时长、作答方式、风格、默认简历。概览仅展示本人填写及已确认简历，不推断人格或自动生成能力评分。目标岗位入口维护求职方向，尚未实现个人JD/收藏岗位业务。面试配置读取默认简历、风格、作答方式，时长映射为现有5/10分钟。

## 数据与边界

当前工作流下确认保存后在同一事务登记分析任务和 Outbox，失败不撤销已经保存的材料。材料列表按指定版本读取 pending/ready/failed/unavailable 状态；页面提供补分析/重试，待处理时轮询。确认后的简历自动分析；失败可显式重试。

`POST /materials/{id}/analysis` 需 version 与幂等键，仅本人确认简历可用。同用户、同版本、同摘要/模型/分析版本并发复用；更新材料重新分析，旧任务不写入新版本。后台 preparation 队列默认并发 1，与实时出题队列隔离。

删除先校验归属，再取消对应分析任务、清理派生分析并执行原材料删除。发布阶段再次复核材料是否仍可用，不允许迟到结果复活。已冻结历史面试按其原记录保留规则处理；删除材料不等于自动删除既有面试，删除面试是独立操作。
