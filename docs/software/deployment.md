# 部署与发布检查

本地运行命令见[运行指南](development.md)。当前证据覆盖本地启动及 CI 中的 API、worker、数据库和生产 Web 代理。共享环境的发布、备份恢复演练和远程媒体联调待验证。历史执行结果见[清退记录](../retrospection/2026-11-05-runtime-cleanup.md)。

| 阶段 | 检查项 |
| --- | --- |
| 发布前 | 记录目标环境、Git 提交及构建产物，使用锁文件构建。核对数据库目标、认证密钥、公开入口、API 与 worker 配置。远程语音使用 HTTPS，并检查代理是否支持 SSE 和 WebSocket Upgrade。 |
| 迁移前 | 审阅目标库尚未应用的迁移，在隔离库验证。评估锁表、执行时间和新旧代码兼容性。备份已有数据并验证能在隔离环境恢复。 |
| 发布后 | 检查 API 的 `/health` 和 `/health/ready`，确认 worker 已注册所需任务。以合成账号走完登录、面试准备、作答和报告，观察任务失败与耗时。启用语音时另验实际设备和降级。 |
| 故障恢复 | 保留发布版本、错误码和任务日志。核心流程持续失败时回退兼容的 Web、API 和 worker 版本；涉及数据库变更时，按实际备份和迁移兼容性决定恢复或补偿。知识版本可按运行指南独立回退。 |

历史迁移 [0007_reset_report_scoring.sql](../../code/backend/drizzle/0007_reset_report_scoring.sql) 会删除旧派生报告、对应评分任务和报告幂等记录，保留面试原回答。已有库初次跨越该版本时，需要把该影响纳入迁移前检查。发布记录应写明迁移起点、备份位置、恢复验证结果和执行人。
