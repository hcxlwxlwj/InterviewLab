# 面试官 v3：知识检索、私有记忆与流式对话

更新：2026-11-05。全岗位动态面试，旧快照只读兼容，不再执行 v1/v2。保留原面试页面；不扩展账号和报告。

## 本机运行

统一启动 API、worker 和 Web，使用正常账号及准备流程。模型仍为 ecnu-plus，向量维度保持 1024；不提供 dev:interview 免登录启动器。完整操作仅在[运行指南](development.md)维护。

旧 frontend-agent 草案和岗位专用命令已清退。当前由 1000 岗位、8000 原创问题及有限专业资料编译同源索引；发布须新 release 和实际审核署名，不能将搜索索引记录升级成已阅读/已审核正文。

## 数据与执行路径

全岗位知识运行时为 knowledge/all-roles.ts，结构化内容源继续支持岗位页面。检索先执行 release、岗位、阶段、面试类型及目标过滤，评价参考从实时召回排除，再进行关键词/向量融合；方法和参数统一见[知识与智能体](../algorithm/knowledge_and_agent.md)。预取为进程内有界缓存，包含冻结版本等条件，不保存私有简历或回答查询。

回答与任务先保存，Outbox 唤醒 worker。一次流式模型请求返回紧凑动作、目标、证据、来源和材料下标，程序恢复真实引用。单轮不额外调用规划或评价模型；面前规划在独立准备任务完成。

私有记忆保留关注目标、覆盖状态、原文陈述、拒绝话题和已问意图。简历事实可填补尚未说明的背景，但不能覆盖职责修正或否认；材料与回答引用分开。问题、记忆和实际检索上下文通过输入摘要、generation、任务及状态检查后共同发布；SSE 预览可撤回，TTS 仅朗读正式题。

## HTTP 与流式事件

- `GET /api/v1/interview-profiles?job=frontend&career_stage=internship` 返回真实入口可用类型。新增 `business_scenario`，不修改演示类型。
- 原回答接口继续返回 `202` 和面试DTO，其中包含 task_id/generation_id。
- `GET /api/v1/interviews/{id}/events?generation_id={generation}` 使用同源Cookie身份，返回SSE。
- 事件包括 status、question_delta、committed、failed、invalidated。question_delta 携带当前预览全文（不是必须追加的字符片段）；重连可以替换预览。
- 模型JSON按字段增量解析，动作和原文引用有效后，只发送经过短句/词边界检查的题目。内部字段、模型分析、能力观察和参考答案不发送给页面。
- 预览每秒最多更新5次，写私有短期记录；LISTEN/NOTIFY 仅广播资源ID。最终完成/失败/取消/删除后清理，异常记录最多15分钟。
- 预览不构成正式问题，生成时不能作答。最终完整校验失败会清除预览，保留原回答，显示重试。
- 页面通过现有Next同源rewrite接收事件，不新建认证或token客户端。事件连接正常时停止HTTP轮询，连接失败时恢复权威状态轮询。

## 验证与边界

### 当前模型适配与执行入口

agent.ts 构建唯一 LangGraph 推进；streaming-agent.ts 生成受限动作和流式问题；model.ts 提供 LangChain 传输；model-analysis.ts 保留当前报告及比较能力。旧非流式规划/推进和 runtime 开关已删除。无当前运行时快照的历史记录不会调用旧模型，原记录仍可读取。

```powershell
npm run check
npm run build:backend
npm run build
npx tsx tests/support/run-database-checks.ts
npx tsx tests/support/run-database-checks.ts test:process
npm run knowledge:all -- coverage
npm run test:llm -- --cases=18
```

数据库检查只使用独立 interviewlab_test* 数据库。受控测试覆盖30条两轮记忆/引用案例、流式解析边界、截断、暂停/删除与迟到结果、私有字段隔离和跨用户读取；这些不代替人工语义质量评审。

真实模型结果输出到 `tests/artifacts/realtime-<时间>-<轮数>.json`，知识检索结果输出到 `tests/artifacts/knowledge-results.json`。指标从提交开始计算，加载提示不算有效响应；失败和自动修复不能从统计中隐藏。首字、完整问题和保存确认分别统计，流式预览可能因校验失败被撤回。

`tests/artifacts/` 是本机生成且已忽略的运行产物；提交保留评测脚本、合成案例、下文汇总和文档截图，不提交反复生成的逐轮文件。

目标为保存P95≤500ms、首内容P50≤2s/P95≤4s、完整问题P95≤6s。实际模型波动及失败重试可能超出目标，以本机结果为准；供应商HTTP成功、短探测快或测试替身通过均不代表目标达成。当前为前端试点和未人工审核内容，专业质量与长期稳定性尚需独立验收。

## 2026-10-26：先建立真实项目背景

修复“只说一个3D小游戏，马上被要求假设多人同步”的问题。服务端从指定回答版本恢复项目描述与本人职责的原文证据，信息不足时进入经历澄清，暂不把专业RAG片段送给模型。每轮只补一个缺口；背景刚补齐后至少先进入一次真实实现追问，再考虑结束或假设扩展。

假设题须满足真实背景已建立、已有实际交流且当前回答已讲清，或用户主动要求情境题。简短回答不是没有经历，没有实习也不是没有课程项目。假设门槛和澄清意图在流式预览前检查；状态写入私有记忆，不增加模型调用或修改页面。

新增8项回归，覆盖裸项目名、仅玩法/仅职责、无经历、主动要求情境题、切换项目、证据定位及流式拦截。真实ecnu-plus四轮：很多项目→请介绍一个项目；3D小游戏→问本人负责部分；补充玩法→继续问尚未说明的职责；补充角色移动/碰撞/关卡职责→问碰撞检测实现。该次首内容中位数1319ms、P95 2259ms，完整问题P95 3156ms，仅代表这组四轮样本，不能替代前述32轮基线。

## 对话准备与无项目背景的修复

“你好”“好的”和仅姓名不视为已完成自我介绍，下一问自然邀请学习背景，显示为自我介绍阶段。仅否定前端项目不再等同于无任何相关经历或请求情境题，先了解课程、练习或其他领域的经历；只回答“有”时继续问具体内容。已明确学习HTML/CSS则围绕相关基础或练习过程；零基础则从岗位动机/了解开始，不循环索取不存在的项目，也不强加性能优化指标。

程序显式区分 introduction、alternative_experience、project_discovery、learning_basics、motivation、interview。准备阶段的问题完成意图检查后才展示；不调用额外模型，暂停专业RAG以避免无关题目推动话题。没有项目本身不授权假设，只有主动要求情境或充分交流后的扩展才允许。

真实ecnu-plus分别在专业面和业务面复测“你好→没有前端项目→学过HTML/CSS”：先邀请介绍，再问课程/其他学习实践，最后沿静态页面练习询问内容，没有跳到性能指标。性能沿用前述实测限制，本次未重跑32轮基线。

## 接受话题边界并主动转场

“不方便”属于拒绝当前话题，不能当成已提供学习背景、能力不足或继续征求许可的理由。私有记忆增加带回答版本和原文引用的 conversation 状态，区分打招呼、确认、拒绝、不会和实质回答。拒绝个人背景后直接转向未被拒绝的岗位内容，后续轮次保留边界；候选人主动重新开放话题时解除。拒绝一个技术问题默认只跳过该题，不封禁整个技术交流。

状态由已有回答恢复，兼容旧记录；不新增公开字段、迁移或模型调用。项目字段尚未补齐也不能覆盖拒绝意图。转场问题经过完整检查后才能预览；拒绝与“不知道”不写成已掌握知识或负面能力证据。模型保持礼貌但直接的面试官语气，不反复使用“如果方便”试探，单题选择一个观察点。

新增回归后仓库检查117项、独立数据库35项和后端构建通过。真实 ecnu-plus 三轮：“你好”→邀请介绍；“不方便”→“好，这部分跳过。你熟悉哪些前端技术？”；“我学过HTML和CSS”→块级/行内元素区别。无生成失败，保存P95 15ms、首内容P50 1750ms/P95 2977ms、完整问题P95 3725ms。这只验证该三轮分支，不代表整体延迟或语义质量验收通过。

## 参与意愿与异常对话验证

v3 增加“提醒 → 确认是否继续 → 仍不参与则封存”的程序策略，原页面复用现有弹窗。首次问候正常接待；连续仅问候或明确的“随便/无所谓”回复进入提醒。明确表示不参与或直接辱骂先提醒，不立即结束。只有在已呈现提醒和继续确认之后再次出现同类行为，才封存为 `participation:<原因>`。明确要求结束面试则尊重用户意愿直接封存。

不会、简短有效回答、不同意面试官、隐私/保密拒绝和跳过题目不作为不参与信号。恢复有效回答、说明不会或同意继续时清除升级状态。当前使用保守的完整短句规则，不依据含糊反讽、一般负面情绪或人格推断判定。后台不生成“态度差”、招聘淘汰或情绪分数。

公开 Interview DTO 新增可选 `participation`（level/reason/turn_id/message），从已保存回答、程序检查点和封存原因恢复；不新增表或迁移，不暴露内部记忆。检查点作为有界回合保存，遵守现有6主问题、每题2追问上限；先用剩余追问位置。保存、检查点创建和封存同事务，沿用版本、幂等与取消检查。提醒路径不调用模型，正常交流恢复后走原模型任务。该段为当时兼容策略；当前 v1/v2 执行链已清退，历史记录保持可读。

仓库检查124项、独立数据库37项、前后端构建通过。数据库验证包括幂等重放、暂停恢复、原回答保留、删除后重放不可访问、终态不可恢复和恢复正常模型路径。浏览器验证完整三级弹窗、刷新后保持结束，以及有效回答后清除提醒并恢复真实模型交流；[确认弹窗截图](prototype/screenshots/interview-participation-confirmation.png)。该验证不代表含糊自然语言的语义识别已经全面覆盖。

复测命令 `npm run test:realtime -- --rounds=2 --types=technical_qa --participation`：首轮明确不参与在17ms返回程序提醒；第二轮补充个人网页经历后，ecnu-plus追问HTML内容区域的实际组织方式，首有效内容1141ms、完整问题1445ms，实际使用非空预取知识。程序提醒不是模型生成，首轮不计入模型首内容统计；该两轮样本不替代整体延迟基线。顺带修复省略“我”的“自己负责…”漏记本人职责问题，防止重复追问已说明的分工。
