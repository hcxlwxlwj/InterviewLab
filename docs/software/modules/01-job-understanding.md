# 01｜岗位理解

版本：v0.2 · 日期：2026-10-15 · 状态：待实现、待验证。首版覆盖计算机技术岗位，作为首页与配置页的能力，不另设必修学习页。

## 1. 目标与交互

把前端、后端、算法、测试等岗位 JD 转成可核对的职责、技术要求与可能的面试主题，帮助学生选择可讨论的真实项目。系统不输出录用概率，不把所有学生都假定为缺少实习，也不把某公司的 JD 扩写成通用招聘标准。

首页选岗位、难度与面试类型；配置页可使用团队发布的通用模板或粘贴JD。展示原文、结构化要求及解释，学生确认或修正后直接开始实时口头模拟，文本替代仍可独立完成。岗位解释可展开查看，不强制完成岗位问答或材料整理课程。

内容区分“JD 明确写明”“岗位知识补充”“系统推断”。模板标通用参考及版本；“了解”不能升级为“精通”，“优先”不能升级为必需。面试主题建议不等同于该企业真实题库或能力权重。

## 2. 数据与处理

输入为岗位名、JD 或模板 ID/版本及当前用户上下文，输出 `JobTarget` 的职责、要求、来源片段、待澄清项与确认版本。个人经历不在本模块创建；“这个要求可用项目解释”不等于“学生已具备该能力”。

服务端校验空内容和长度，LLM 约束提取后核对原文片段，再按岗位/技术主题检索已发布知识。原 JD 与知识引用分别保留；检索不足可解释字面含义，不能伪造来源、企业规定或专业结论。JD 中的命令视为待分析数据，不获得工具或网络权限。

映射优先考虑学生可提供的经历证据：功能实现、技术取舍、测试或实验、协作分工。商业化指标、海量并发、真实用户规模仅在 JD 与经历确有相关依据时讨论，不要求课设编造生产指标。

相同目标修订与知识版本可复用分析；修订 JD 使未开始配置提示更新，但不能改写历史会话快照。缓存隔离当前用户，不通过模型 URL 直接读取外部页面。

## 3. 接口与依赖

| `/api/v1` 接口 | 输入与输出 |
| --- | --- |
| `GET /job-templates` | 岗位筛选 → 发布模板、版本和通用标记 |
| `POST /job-targets` | JD/模板 → 目标草稿、分析任务 |
| `GET/PATCH /job-targets/{id}` | 查看或确认/修订、version → 原文、解释、确认版本 |
| `POST /job-targets/{id}/questions` | 学生问题、目标版本 → 带依据解释或资料不足说明 |

依赖身份、知识检索、模型适配和结构/引用校验；配置模块读取确认目标，面试官使用启动快照。公共幂等、错误、版本和权限遵循[数据与接口](../data_and_interfaces.md)。

## 4. 边界与失败

- JD 过短或冲突：保留原文与未知项，可显式改选模板；不能自动添加缺失要求。
- 未覆盖专业：说明资料不足，允许通用问答，专业评分只在有实际可判断回答时观察。
- 模型超时/结构错误：保存用户输入，允许有界重试或直接使用模板；错误结果不当有效分析。
- 版本变化：开始前要求重新确认所选目标；旧会话继续显示冻结版本。
- 越权、指令注入、无效引用：服务端拒绝或丢弃，不开放任意 URL、SQL 或他人目标。

## 5. 合成例与验收

合成后端实习 JD 写“了解缓存，熟悉基础测试”。学生的课设包含 Redis，但只负责查询接口。系统可建议讨论缓存用途和测试，不能生成“独立设计高并发架构”的履历，也不能把没有线上流量记为缺陷。

| 场景 | 通过条件 |
| --- | --- |
| 需求强度 | “了解/优先”被准确保留，要求带真实原文依据 |
| 个人关联 | 只提出可讨论方向，不从技术关键词推断个人贡献 |
| 版本/权限 | 更新不改历史；跨用户目标和缓存不可读 |
| 空检索/失败 | 不编造引用，原文和配置可恢复 |

## 6. 优先级

阶段 A：模板/JD、要求提取、确认、引用解释及版本恢复。阶段 C 以技术岗位合成 JD 和学生材料检查提取、追问关联及过度推断；扩大岗位覆盖为后续。关联：[需求](../../requirements/functional_spec.md) · [配置](03-interview-configuration.md) · [知识与 Agent](../../algorithm/knowledge_and_agent.md)。
