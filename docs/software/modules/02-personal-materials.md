# 02｜多简历与已确认经历

版本：v0.2 · 日期：2026-10-15 · 状态：待实现、待验证。

## 1. 目标与交互

让学生针对技术岗位维护不同简历，并把课程项目、比赛、科研、毕设或少量实习中的真实行动用于个性化追问。解析只是辅助录入；上传成功、解析成功和学生确认分别记录，均不构成系统对经历真实性的认证。

个人中心提供多简历上传、命名、预览、下载、删除、设默认。配置页先选择已有简历，也能临时上传或手填一段经历。补充材料不要求上传完整代码仓库、商业数据或全部履历；无简历仍能直接进入实时口头通用模拟，文本替代同样可独立完成。

流程为“校验与私有保存 → 异步提取 → 原文与候选核对 → 逐项确认 → 选择本次重点经历”。学生可确认一部分并忽略其余项，批量确认仅在能查看每项内容时提供。切换简历只列该版本已确认经历；其他简历和独立手填经历必须明确另选。

## 2. 数据与保存

`ResumeDocument` 包含 `name/version/is_default/storage_scope/parse_status`。`storage_scope=library|temporary`；`parse_status=uploaded|parsing|needs_confirmation|confirmed|failed`。仅 library+confirmed 当前版本可设默认，同一用户至多一份默认；删除默认后清空，不自动另选。

| 范围 | 保存与选择规则 |
| --- | --- |
| library | 私有保存至主动删除，可再次预览和下载，不受临时 24 小时清理影响 |
| temporary | 配置页上传默认值，不自动入库；自上传起最长 24 小时，已确认不等于入库 |
| 显式转入库 | 有效期内执行 save-to-library，改 scope 并清除 expires_at；已清理文件不可恢复 |

文件替换产生新版本并重新核对，不能覆盖历史快照；解析失败也可删除文件或转为手填。暂存到期后独立确认经历与必要会话快照按各自策略保留，源原文显示已不可用。

`Experience` 保存 `kind/personal_role/actions/technical_decisions/results/evidence_refs/confirmed/version`，来源关联简历 ID 与版本；独立手填来源可为空。kind 包含课设、比赛、科研、毕设、实习及其他。缺少量化结果允许写产物、测试、实验或未知；团队结果与本人行动分开，参考表达不能新增“独立完成”“增长 X%”等未确认事实。

## 3. 处理逻辑与安全

默认文件上限 10 MiB，只接收有文本层 PDF/DOCX。服务端同时校验扩展名、实际类型、压缩展开体积与解析结果；拒绝密码、损坏或异常压缩文件。解析/预览使用受限任务，不执行宏、脚本、嵌入对象或外链。OCR 为后续扩展，扫描件给手填入口，不从空文本猜经历。

LLM 候选须有存在于提取文本中的来源；数字保留单位与原措辞，模糊职责标待澄清。用户确认时保存内容、时间与版本，模型/解析重试不能覆盖用户修改；重复确认使用幂等键避免重复经历。Agent 的事实读取 Tool 只拿本次选中的已确认字段，默认不发送联系方式。

上传材料、代码片段和原文中的指令视为资料，不获得读写工具权限。每次预览、下载、详情、经历读取检查归属，私有存储不提供可猜测的公开地址。

文件删除清除原文件、草稿、预览及缓存，保留独立确认经历并解除源文件引用，入口须说明。若学生要删除经历事实，先列相关会话、报告、比较及快照影响，再级联清理。删除标记即时禁止访问，异步任务提交前再次检查，防止解析迟到复活材料。

## 4. 接口与依赖

| `/api/v1` 接口 | 作用 |
| --- | --- |
| `GET/POST /resume-documents` | 查询私有简历库，或上传并声明 scope/name |
| `GET/PATCH /resume-documents/{id}` | 状态/候选/元数据，命名或替换成新文件版本 |
| `POST /resume-documents/{id}/confirm` | 核对候选 revision，生成确认经历 |
| `POST /resume-documents/{id}/save-to-library` | 显式将有效 temporary 转入库 |
| `POST /resume-documents/{id}/set-default` | 原子设置合法默认 |
| `GET /resume-documents/{id}/preview`、`/download` | 归属检查后的私有预览/原文件下载 |
| `DELETE /resume-documents/{id}` | 删除文件/草稿及缓存，说明确认经历保留 |
| `GET/POST /experiences`、`PATCH/DELETE /experiences/{id}` | 来源筛选、手填、修订/确认与经历级联删除 |

依赖身份、私有文件、持久 job、提取器和模型适配；配置、面试和报告只消费受权的确认数据。版本、错误、下载授权及删除期限见[数据与接口](../data_and_interfaces.md)。

## 5. 合成例与边界

合成学生小周有“后端实习版”和“算法比赛版”。后端版写团队用了 Redis，小周确认本人负责查询接口，缓存失效由队友实现。选择后端版时可追问接口如何使用缓存，不能假定他负责一致性方案；切到比赛版后不自动保留后端经历。比赛获奖是团队结果，系统可询问小周实际实现的模块与实验。

模型把“协助测试”提成“负责系统压测”时，学生纠正后只用确认版本。原文件到期、无文本层、数字不清、职责冲突分别显示状态或缺口，均不生成虚构能力分。

## 6. 验收与优先级

- 两份简历隔离、默认限制正确，切换不混选；名称和文件版本可追溯。
- library 持久下载可用，temporary 最长 24 小时且显式入库；不把所有文件都自动清理。
- 未确认候选不能进入面试；确认幂等且不会被迟到解析覆盖。
- 课设无商业指标仍可使用，团队成果不改写成个人成果；确认不标“真实性已认证”。
- 越权、损坏/扫描文件、删除/解析竞态有可恢复结果，无原材料泄露或复活。
