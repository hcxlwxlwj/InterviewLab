# 03｜面试配置

版本：v0.3 · 更新：2026-10-19 · 状态：模块目标设计；原型已覆盖部分交互，真实服务待实现、待验证。替代原准备重点/教学入口，允许直接模拟。

当前演示能力以[扩展实现说明](../prototype/library-expansion.md)为准；代码位置见[工程目录与职责](../repository_structure.md)。

## 1. 目标与交互

将首页意向和学生材料变为一场明确、可开始的模拟面试，不要求先完成经历整理课程或长期准备计划。首页预选岗位、难度、面试类型，点击开始后进入配置；配置页确认 JD、时长、代码考核、面试官风格、输入方式和本次使用的简历/经历。

简历区优先下拉/卡片选择个人中心的库内版本，显示名称、版本、默认标记及确认状态。可临时上传、显式入库或直接手填一段经历；“本次重点经历”只需轻量勾选。项目说明、本人职责及少量关键代码/材料为可选补充，无材料可通用问答。

开始按钮前展示本次目标、已选经历和资料缺口；提示缺口不拦截通用模拟，也不以“必须量化成果”要求编造数据。不设置教学/模拟切换，不提供实时评分开关，评分在面后集中展示。

## 2. 配置合同

| 项目 | 首版约定 |
| --- | --- |
| 模式/面试类型 | mode 仅 mock；technical_qa / project_deep_dive / hr / mixed |
| 岗位 | 前端、后端、算法、测试等技术方向；JD 或明确标注的通用模板 |
| 时长 | 5 或 10 分钟，默认 10；目标时长收尾，12 分钟含暂停安全上限 |
| 问题预算 | 最多 6 主问题、各最多 2 追问，实际数取决于回答与时间 |
| 简历与重点经历 | 所选简历 ID/版本、其已确认经历；手填/其他来源需显式选择 |
| 代码考核 | 默认关闭，可在配置开启；能力可用时嵌入面试，语言 C++/Python/Java |
| 风格 | 可选支持、平衡、深入追问等措辞风格，不改变事实边界、评分标准或轮次上限 |
| 交互模式 | interaction_mode 默认 realtime_voice，主动授权后直接说、端点自动提交；text_fallback 可独立完成且明确标注 |
| 可选镜头 | camera_enabled 默认 false；当场授权后采集，只作描述性面后复盘，不影响四维专业分 |
| 复盘媒体 | review_media_enabled 默认 false；分别说明音频/视频授权、私有保存及自采集起最长24小时，不保存也能获得可用派生观测 |

偏好只提供新配置的初值，学生可覆盖；不能悄悄改变进行中的会话。更改简历时重算候选并清理已失效选择，独立手填若仍保留必须清楚列出，不能混用其他简历的个人经历。

## 3. 数据流与开始事务

`POST /sessions` 创建 draft/ready，关联 `JobTarget`、`ResumeDocument`、`focus_experience_ids` 及所选版本。ready 只表示配置齐备；`start` 再校验归属、确认状态、版本和预算，事务内冻结材料、JD、知识/题目/标准/提示版本，进入 in_progress 后请求首题。

开始前资料变化返回版本冲突，展示差异要求重新确认；不能自动取最新材料继续。开始后不能换简历、类型或代码开关，需结束后新建会话。重练配置关联 `parent_session_id/parent_turn_id`，同样 mode=mock，不复活教学模式。

临时文件允许确认并用于本次会话，默认不入库。到期前已确认经历可独立保留；文件到期不伪装仍可预览。无可用材料时配置和会话明确标“通用问答，个性化有限”，不生成个人事实。

## 4. 接口与依赖

| `/api/v1` 接口 | 配置职责 |
| --- | --- |
| `GET /job-templates`、`GET/PATCH /job-targets/{id}` | 获取/确认岗位依据 |
| `GET /resume-documents`、`GET /experiences` | 按简历版本筛选确认材料 |
| `POST /resume-documents`、`/{id}/confirm`、`/{id}/save-to-library` | 临时补充、确认与显式入库 |
| `GET /me/preferences` | 新配置默认值，不自动修改当前选择 |
| `POST /sessions`、`PATCH /sessions/{id}` | 创建/修订开始前配置，幂等与 version 检查 |
| `POST /sessions/{id}/start` | 原子冻结并进入会话，重复点击返回同一结果 |

依赖岗位、材料、偏好、会话状态和服务能力检查。任务异步与错误合同见[数据与接口](../data_and_interfaces.md)，布局见软件目录的原型文档。

## 5. 边界与合成例

简历正在解析时可等待、选另一份或通用开始，不以未确认候选出题；默认简历被删除时显示未选择，不自动另选。真实代码服务不可用应说明能力不可用并允许关闭代码后开始；原型可使用标记模拟的代码演示，不能让用户误认真实评测。

合成学生选择算法比赛版简历和“比赛路径规划”经历，时长 5 分钟、项目深挖、不启代码。系统可问本人负责的启发式选择和验证，不要求先完成算法课程、不假定商业部署。学生开始前把经历从“独立实现”改为“参与实验”，start 要求确认新版本后再冻结。

## 6. 验收与优先级

- 首页 → 配置 → 直接面试链路无教学前置，跳过材料可通用开始。
- 多简历选择及手填来源清楚，未确认/取消确认/变化版本不能被隐式使用。
- 默认 10 分钟、可选 5 分钟、代码可选、无实时评分；风格不改变评价规则。
- 重复 start 只有一次会话启动；开始后配置不可漂移，历史依据可复查。
- 解析/服务失败保留输入与选项，可降级继续，不生成虚假能力状态。

阶段 A 交付配置和材料选择的文本联调作为过渡，阶段 B 交付实时语音设备检查、可选镜头与复盘保存授权，阶段 C 试用检验学生能否快速明确“本场用哪段经历”。关联：[模拟会话](05-mock-interview.md) · [材料](02-personal-materials.md) · [需求](../../requirements/functional_spec.md)。
