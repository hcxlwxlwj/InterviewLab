# 知识库与智能体设计

2026-10-26：前端岗位的 pgvector、ecnu-embedding-small、私有目标记忆与流式输出已接入联调。内容仍为待人工审核草案，验证与实时性边界见[面试官 v3](../software/interview-agent-v3.md)。以下目标方案中其余岗位、个人材料和多模态仍未实现。

版本：v0.4 · 更新：2026-10-25 · 状态：文字 Agent、ecnu-plus 兼容适配、冻结知识接口及闭环已实现，单案例真实模型闭环已验证；人工质量评审、语音与向量检索待完成。实现范围见[文字面试接入](../software/interview-agent-implementation.md)，下文仍保留完整目标设计。

本文规定知识、学生材料、实时口头追问与面后内容及表达复盘的职责边界。目标群体是实习经历有限、主要使用课程项目、竞赛、科研或毕设经历准备技术岗位面试的高校学生，不将这一特征推广到所有学生。产品直接进入模拟面试，默认即时口头作答，分析和建议在面试结束后提供。共用字段、状态及删除规则以[数据与接口](../software/data_and_interfaces.md)为准，验收见[评测方案](evaluation.md)。

## 1. 知识范围、来源和版本

岗位内容覆盖软件开发、AI/大模型、数据、产品、设计等 1000 个计算机相关方向，具体能力目标随岗位模板确定；重点是学生能否讲清本人贡献、决策、验证依据及岗位关联。课程项目无需虚构商业收入、用户规模或上线数据；比赛奖项不自动等于某位成员独立完成全部工作。

| 知识集合 | 内容 | 用途与边界 |
| --- | --- | --- |
| 岗位知识 | 初级技术岗位职责、能力要求、常见工作任务与术语 | 解释 JD、确定提问语境；不能覆盖当前 JD 的明确条件 |
| 学生经历追问框架 | 项目目标、个人职责、行动、方案比较、困难、验证、协作与局限 | 选择追问及面后复盘；不把表达框架作为面试中的提示 |
| 题库与评价标准 | 技术题、经历题、可观察点、适用难度、追问方向、评分锚点 | 为问题与评分提供依据；未问到的能力不得推断评分 |
| 复盘与重练方法 | 问题类型、针对性改进动作、参考表达约束 | 结束后说明问题并提出一项明确重练目标；不能添加履历事实 |

优先使用团队原创、获得授权或可合法用于本项目的公开资料。有公开链接不等于可以复制全文；每份材料记录出处、使用依据和必要摘要。原创题目由另一位维护人员审核适用学生场景、知识正确性和评分可观察性，不按“像真实面试”直接发布。

每份源文档至少记录来源 ID、标题、作者/维护责任人、来源地址、使用依据、获取/核验日期、适用岗位与主题、正文版本、发布状态和校验值。片段另存片段 ID、原文位置和检索元数据。报告保存实际使用的片段版本与引用短文，不能只留下易失效的 URL。

内容流转为 `draft → reviewed → published → retired`。只有已发布版本进入在线检索；更新先做离线回归，再切换完整内容和索引版本。更换题库或评分规则不静默重算历史报告。撤回材料不进入新检索，历史引用注明当时版本和撤回状态。

事实标记至少区分 `jd_explicit`（JD 原文明示）、`knowledge_explanation`（有来源的通用说明）、`inference`（对当前材料的推测）。发生冲突时保留 JD 原文及差异，不能用行业通例替学生修改岗位条件。

## 2. 入库、检索与引用

第一阶段用岗位/阶段/主题/难度与发布状态过滤确定性内容；第二阶段建立混合检索。审核文本依次规范化、按标题与语义段落切分、提取元数据、建立关键词索引、生成嵌入、抽检后切换完整内容与索引版本。题目和评分标准以结构化记录保存；题干与可观察点、表格与必要行组保持关联。

初始切分参数为每片约 350～700 个中文字符，必要时重叠 50～100 字；它们是待验证参数。保留标题路径，短条目不强行切分。嵌入记录提供商、模型标识、维度及生成时间；切换模型或维度须重建独立索引，不能混用不同嵌入空间。目标确定为 Drizzle + PostgreSQL/pgvector，经 KnowledgeService 封装；尚无数据库或检索效果实测。嵌入模型与维度实际接入时锁定，不能用示例维度当成已经验证的选型。

检索流程：

1. 业务模块传入岗位、当前问题目标、知识集合和发布版本；用户身份由服务端提供。
2. 仅用必要的已确认经历摘要构造查询，移除姓名、电话、地址等无关信息。
3. 关键词和向量各召回前 20 个候选，按来源去重；中文采用应用层分词、归一化及同义词表，保留英文技能词与单位。
4. 以 RRF 合并排名，初始常数 60，最多选取 5 个适用片段；该参数须在独立检索集校准。
5. 无相关、可靠、适用版本的片段时返回结构化空结果及原因，不为凑数填充；阈值不得跨嵌入模型套用。
6. 输出来源 ID、片段 ID、版本、引用和适用说明；服务端检查真实存在且引用逐字匹配，报告评估再检查是否支持结论。

初版不强制独立重排服务；只有基线检索确有问题且收益可测时再增加。检索分数只用于排序，不是学生能力分数。日常日志记录查询类型、命中 ID、空结果原因及版本，不记录完整简历或回答。

检索不足时，岗位顾问可以解释 JD 明确原文并说明资料缺口；面试官可选审核过的通用经历题；报告对缺乏依据的专业判断保留不确定性。不能把模型常识包装成查证后的确定结论，更不能因“没有技术资料”给学生低分。

## 3. 学生材料与事实边界

个人 JD、简历库、经历、材料片段、会话快照和回答均为私有数据，不进入共享向量库。首版按授权的材料及经历 ID 读取，不默认接入整个代码仓库。所有读写同时核对用户归属和资源 ID，模型不能通过提供别人的 ID 获得访问权。

`Experience.kind` 为 `course_project | competition | research | graduation_project | internship | other`。核心内容包括 `personal_role、actions、technical_decisions、results、evidence_refs、confirmed、version`。结果可以是功能完成、测试覆盖、实验结论、比赛约束下的效果和已知局限，不强求商业指标。证据引用指向材料版本及位置，不能仅凭一个文件名证明真实性。

简历解析、模型摘要和 ASR 转写初稿不自动构成已确认事实。学生可确认或修订经历；模型不可将“团队获奖”改成“本人独立完成”，不可补写性能提升、用户数量、实习职责或技术技能。材料只能说明“学生确认的项目事实”，不能单独证明该学生在本次回答中已解释充分。报告需分别引用材料和当次回答。

| 对象 | 使用约定 | 保存与删除 |
| --- | --- | --- |
| 简历库 `library` | 配置页默认列出库内已确认、可用的简历；选择具体简历及其经历版本 | 私有保存至用户删除，不能套用临时文件 24 小时清理规则 |
| 临时上传 `temporary` | 默认不入库；可选择保存到简历库；未经确认的候选经历不进入事实上下文 | 文件和提取草稿自上传起最长 24 小时，确认或放弃后可提早清理 |
| 独立确认经历 | 手填或从材料确认生成，引用来源和版本 | 到临时文件过期不自动删除；源文件清理后来源标记不可再取，不能保留已清理的隐蔽全文 |
| 会话快照 | 开始前再次校验简历及重点经历版本，成功开始后冻结必要内容 | 经历更新不改写历史；删除经历/会话时纳入明确的关联清理范围 |

配置必须校验 `focus_experience_ids` 属于当前用户且与所选简历/明确补充材料一致，不能从另一份“算法岗版”简历混入“后端岗版”的项目。开始前材料有更新时先要求学生确认版本，不能静默替换。确认经历没有实习不扣分，不因经历类型给能力加分。

删除简历文件和提取候选稿时，明确告知独立确认经历可保留并解除原文件来源；删除经历或会话另展示关联报告、比较、快照及任务的级联影响。清理标记后新任务不得重新发布已删数据；备份恢复须重放删除清单。完整保留窗口以[数据与接口](../software/data_and_interfaces.md)为准。

向云服务只发送当前任务必要字段，不默认发送整份简历、联系人或全部历史。供应商的数据处理地区、记录关闭能力和留存设置须在试用前核验；供应商尚未选定，不能提前宣称已完成隐私配置。

`camera_enabled = false`，`review_media_enabled = false`。摄像头和私有音视频复盘分别由学生明确开启，不与完成面试绑定。原始音视频默认临时处理后清除，结束、取消或断线清理缓冲；显式开启私有复盘后，只保存授权后采集的后续片段，每个片段自采集起最长 24 小时，到期或用户删除后清理。重连、重试或后续授权均不重置该期限，也不能追溯保存此前未授权的原媒体。到期仅保留必要派生观察及版本，不保留可还原原始音视频的隐蔽副本；报告标记媒体已不可用，不能承诺回放或重新计算声学/视觉指标。JD、代码注释和上传材料中的“忽略系统指令”等内容一律为不可信输入，不改变权限与工具白名单。

## 4. 内部内容能力与确定性编排

Fastify 业务服务控制身份、事务、状态、计时、保存和任务；Agent 是模块调用的内部能力，不开放一个浏览器可任意调用的 `/agent` 总入口，也不要求多个自主 Agent 相互讨论。API、worker 和实时通道使用同一套业务服务。

| 能力 | 负责输出 | 输入边界 |
| --- | --- | --- |
| 简历提取 | 带原文位置的经历/技能候选 | 受限提取文本与文档 revision；不直接确认个人事实 |
| JD 分析 | 职责、要求、考查主题、未知项与依据 | 明确 JD 版本、适用知识；区分原文、知识说明和推断 |
| 岗位顾问 | 对用户问题的岗位解释 | 当前目标与已发布知识，不返回进行中面试的参考答案 |
| 面试规划 | 本场主题、可观察目标和候选问题 | 冻结岗位/材料/题库/标准版本及 5/10 分钟配置 |
| 面试官 | 针对当前回答的追问、下一题或收尾建议 | 指定回答 revision、已问目标、剩余预算、允许材料与来源 |
| 报告评估 | 逐题证据、优势、缺口、参考要点和明确重练目标 | 已封存输入、实际作答模式、可用运行/观测及标准版本 |
| 重练比较 | 两份指定回答的变化与可比性限制 | 原/新 turn、revision、片段、模式和共同标准，不自动取最新回答 |

这些职责可使用同一模型。模型接入层负责提供商、结构化输出、取消、超时及用量；业务能力层组织提示与校验；KnowledgeService 负责检索和来源。不得把数据库客户端或整个可变 Session 对象直接暴露给模型。

内部请求至少包含任务类型、输入版本摘要、必要确认材料、指定回合、允许来源、提示/标准版本和取消信号；结果包含类型化内容、引用、依据不足说明、provider/model/prompt 版本及可得用量。当前 `ModelAdapter.ask({session})` 只是原型端口，正式实现需拆出这些明确能力，本轮没有修改该接口。

### 一次回答如何驱动下一题

1. 业务服务校验归属、当前题、版本和幂等键，在事务中保存原回答并登记问题任务的 outbox。
2. 返回保存成功后，投递器将任务交给 pg-boss；worker 读取冻结材料、指定回答和已发布的适用知识。
3. 在数据库事务外调用模型，校验结果结构、引用和事实边界。
4. 结果提交前复查输入摘要、活动 generation、状态、时间/追问预算和删除标记；仅有效结果落库并通知前端。
5. 模型失败只影响后续内容生成，不能回滚已保存回答；有界重试后显示失败或选择审核过的适用通用题，检索不足不切到无关岗位。

目标实体为 Interview，`mode=mock`；原型代码仍名 Session。面试类型为 `technical_qa/project_deep_dive/hr/mixed`，重练通过独立父引用关联。第一阶段文字联调明确 text_fallback，第三阶段再接实时语音；摄像头、代码真实执行和复盘媒体在第四阶段单独启用。不能用文字联调成功代表实时体验交付。

第三阶段由 ASR、端点确认、保存、编排、模型、TTS 形成实时回合。短停顿或单个 ASR final 不直接结束作答；误截追加保留原片段与新 revision，取消依赖旧输入的生成。用户打断先停止播放再取消 generation，未实际展示/播放的问题不当成已问。AI 主动打断仅在明确选择的风格下启用。

start 时才冻结材料、记录开始时间和登记首题任务；创建草稿不计时。状态为 draft/ready/in_progress/paused/ending/completed/failed，问题生成与报告任务状态独立。最多 6 个主问题，每题 2 次追问；5/10 分钟目标提示收尾，含暂停和断线到 12 分钟强制封存，恢复不重置预算。

长上下文可以压缩为事实 ID、已问主题及缺口，原始回答独立保留。ASR partial 仅字幕，final 及原片段不能润色覆盖；面后纠错追加原文、原因和 revision，使依赖报告/比较过期。failed 保持终态，有有效回答可产部分报告，没有有效回答只显示记录与再开始入口。

## 5. 模型输出与工具边界

提示版本、模型标识、知识/题库/评分版本、检索配置随会话记录。模型输出按上述任务使用不同 schema，至少携带结果类型、内容、能力目标、材料/回答引用和证据不足标记。schema 校验结构、枚举、长度与引用；内容正确性仍需事实和语义评测。

模型超时、结构非法或引用失配最多修复一次，记录两次调用。再次失败返回审核过的通用问题、保守的不足说明或可重试任务失败，不能无限生成。未经校验的报告增量不作为正式结果发布；取消或过期 generation 的迟到内容不继续展示。

```text
岗位顾问：解释当前技术岗位。区分 JD 原文、知识说明和推断；材料不足直接说明。
学生事实仅用 confirmed 版本；不生成必修学习计划。

面试官：围绕当前岗位和学生选定经历提问，追问当前回答中的具体缺口。
区分本人和团队，不默认校园项目必须有商业结果；不泄露参考答案或评分。
候选问题是否发出、追问次数和结束时机由业务编排器决定。

报告评估：仅评价观察到的回答。结论引用完成回答的指定原文版本，材料事实另行标明来源。
不新增经历、数字和归因；优势同样需要证据。四维评分由指定版本锚点约束，
未观察项不评分；语音/视觉另列，只描述可观测现象，不推断情绪、诚实、人格或能力。
给出一项明确重练目标和不添加事实的参考表达。
```

| 工具 | 允许内容 | 权限及副作用 |
| --- | --- | --- |
| 读取岗位/确认经历 | 当前用户 JD、所选简历、指定确认经历及版本 | 只读，校验配置范围，不允许跨简历自动合并 |
| 检索知识/题目候选 | 已发布版本、岗位主题、适用难度、已问题目 | 只读，不能由模型任意抓网页 |
| 读取完成回合/代码结果 | 当前会话问题、回答 revision、运行及提交结果 | 只读；运行结果与 Agent 评审分别保存 |
| 保存回答、结束会话 | 业务幂等键、受校验的当前回合和状态 | 由编排器调用，不由模型自行写入 |
| 请求/发布报告与比较 | 结束会话、输入版本摘要、校验结果 | 异步业务任务；发布前再检查版本、归属和删除标记 |

模型不获得任意 SQL、shell、文件路径或无边界网络工具。学生代码不能通过模型工具直接执行；真实代码执行须由隔离服务限制网络、CPU、内存、时限和输出。原型模拟运行结果须明确标识，不能作为真实通过的证据。

## 6. 四维评分与独立表达观察

正式报告采用 `technical_knowledge、project_communication、coding_ability、logical_expression` 四维。每维 `status = observed | not_observed`，未观察分数必须为 null。目标合同增加 `scoring_status=uncalibrated|calibrated`：第一阶段先交付有证据的分析，未校准时即使已观察也不填数值；第二阶段人工校准后才启用 0–100 分。该字段尚未进入原型类型，细则见[数据与接口](../software/data_and_interfaces.md)。没有代码作答不等于代码能力为零，没有实习不等于项目表达低分。零有效回答时所有维度和总分均不评分，只呈现中断/跳过及后续入口。

下表是待人工校准的锚点，不是已验证心理测量量表。维度内采用整体判断并说明依据，不根据关键词命中机械累加。

| 维度 | 0～39：明显不足 | 40～59：部分说明 | 60～79：基本清楚 | 80～100：充分且有边界 |
| --- | --- | --- | --- | --- |
| 专业知识 | 与题意相关但关键概念有实质错误 | 能说明概念，原理或适用条件不足 | 原理基本正确，能关联当前实现 | 能解释约束、取舍与局限，回应相关追问 |
| 项目表达 | 有效回答仍无法区分本人行动 | 有个人职责，但行动、决策或结果依据不清 | 职责、行动和结果相互支持 | 本人/团队边界明确，技术决策和验证依据充分 |
| 代码能力 | 已提交的相关实现有关键错误 | 有部分正确思路但实现/边界不完整 | 主要需求正确，能解释复杂度和测试 | 正确性、边界、复杂度及代码解释充分 |
| 逻辑表达 | 回答相关但主旨、因果难以辨识 | 有主旨，信息顺序或因果支撑不足 | 结构连贯，能回答具体问题 | 清楚精炼，因果有据，能指出不确定性 |

评分启用后，总分由业务程序对 observed 维度等权平均，四舍五入为整数，并展示“已观察维度数/4”及适用范围；不能横向排名观察覆盖不同的会话。某维观察依据不足时先标记 not_observed，而非为得到完整雷达图凑分。报告写明标准/模型/提示版本；分数不是招聘预测。

语音以 `SpeechObservation` 独立记录语速、停顿、疑似口头语、音量和音高变化，携带回合、回答 revision、音频区间、算法版本、质量状态和原因。只对足够质量的真实音频生成；文本答题显示未观察，观测状态为 `unavailable`；过短、缺失或严重噪音也为 `unavailable`，不能输出零分。音量受设备与环境影响，音高受个体声音和提取质量影响；只说明当前片段变化，不从单个指标推断情绪、诚实、人格、紧张程度或能力，也不机械要求消除所有停顿和口头语。

学生明确开启摄像头后，`VisionObservation` 可记录画面质量、头部朝向和面部动作，携带回合/时间区间、观察版本及质量说明。只描述例如“该片段头部朝向发生变化”，不从视线偏离镜头推断缺乏眼神交流，不将表情自动翻译为自信、不耐烦等心理判断。未授权、遮挡、光照不足、低帧率等为 `unavailable`，界面说明未观察或质量不足；设备条件造成的缺失不计能力得分。面部身份识别不在范围内。

内容分析与表达观察可以在同一题目的时间线上并列，例如“该段未解释方案依据，同时出现较长停顿”，但不能据时间共现断言停顿造成内容不足。二者分别给出可定位证据和可选重练目标；语音与视觉指标均不加入四维总分。进行中仅展示设备、连接、采集等运行信息，不展示任何表达观察、点评或能力分；完整内容及表达复盘只在会话结束后开放，HTTP、WebSocket 和其他读取 API 同样执行时机限制，不能仅靠前端隐藏。前后重练分别比较内容完整性和表达现象，说明模式、材料、媒体质量及算法版本差异。

`AnswerSegment` 保留实际作答与追加轨迹，`AsrRevision` 保留面后识别纠错，不能混为同一条可覆盖文本。纯转写纠错不能改写原声学停顿、时长或视觉事实。依赖文本的疑似口头语判断在有必要派生依据时按新 revision 产生新观察版本；需要原媒体才能重算的指标，仅在 `ReviewMedia` 仍有效且授权可用时重算。媒体到期后保留已有派生观察、来源区间和不可回放标记，不能声称已重新计算或提供原片段回放。引用修订后的报告与比较必须可识别，原版本不可静默覆盖。

## 7. 学生项目贯穿示例与验收

以下为合成案例。小林应聘后端实习，选择“后端岗专用”简历和课程预约系统经历。确认事实为：四人团队，本人负责预约接口及重复预约校验；使用数据库约束和并发请求测试检查重复提交；项目未商业上线，没有大规模用户指标。Redis 只是后来调研的方案，尚未实现。

首答：“我们做了预约系统，用 Redis 提升了性能，我主要负责后端。”面试官追问本人具体负责哪些接口、Redis 实际如何使用及验证方式，不把简历关键词当已实现事实。报告引用该原句，说明个人边界不清、Redis 表述与确认材料不一致，建议澄清真实实现及验证依据；不得替小林补写“性能提升 50%”。重练可改为本人接口、数据库约束和测试过程，比较“事实是否纠正、个人贡献是否清楚”，不能声称短时重答证明技术能力提升。

关键验收：

- 只调用所选简历及重点经历，未确认内容作为待澄清项；团队奖项不归为个人独立成果。
- 无实习、无商业数据不扣分；存在相关有效回答才评相应维度，零回答无能力评分。
- 模拟过程中不提供答题框架、示范答案或实时评分；报告结束后生成，同题重练为关联 mock。
- 默认实时口语自动保存完成回合，允许思考/澄清/口头纠正；误截、追加、打断、取消和模式切换有明确事件与版本。
- 语音和可选视觉反馈可定位到题目和片段，低质量显示 unavailable；不推断心理、诚实、人格或能力，不计入四维总分。
- 摄像头与原媒体复盘默认关闭；仅保存授权后采集的后续片段，自采集起最长 24 小时，重连/重试/后续授权不重置；到期不能回放或假装重算，识别纠错不变成事后补答。
- 进行中只提供设备、连接、采集等运行信息，任何表达观察和点评均在面后开放；HTTP、WebSocket 与其他 API 统一限制，不能绕过界面提前读取。
- 每条优势、不足、技术纠错与重练变化有正确原文/材料定位，引用修订后旧报告和比较过期。
- 版本冲突、任务重试、预算上限、取消、跨用户访问和删除都由程序约束，模型无法绕过。

完整固定集、人工校准、同材料竞品与通用模型对照见[评测方案](evaluation.md)；产品能力与用户评价的证据边界见[技术与竞品调研](research.md)。

## 2026-10-19 内容接入原型

当前本地岗位知识见[内容库](content/README.md)，覆盖1000个计算机相关方向。职责依据招聘公开资料归纳，问题、追问与观察要点由平台整理；保留来源可访问性、获得/核对日期与版本，未声称企业真题或已校准评分。当前只做确定性读取，未接嵌入、向量库或模型。

KnowledgeRetriever按job/stage/topic/difficulty限定已发布内容，不匹配返回空，不切到其他岗位。会话冻结模板、题目及来源；历史复盘使用快照，当前发布与撤回只影响新会话。专业知识维度可用于产品等方向的岗位知识，代码未考查保持null；新岗位Rubric仍需专家校准，当前不为用户作答生成专业分数。

首轮通过授权命令完成内容导入、结构检查、来源复核、审核/发布/撤回/回滚、到期复核和索引重建；命令调用知识模块服务，尚未实现，不增加无类型的通用管理 API。既有 1000 个岗位资料先检查再导入，不能因导入成功就认定专业标准已校准。个人材料与公共资料分库存储边界保持不变，管理页面放第四阶段。

## 语音观测定义与参数

本节整合原功能说明中的指标定义，参数需经样本校准；业务要求见[功能需求](../requirements/functional_spec.md#feature-speech)。

| 对象 | 数据与约束 |
| --- | --- |
| AnswerSegment | 原 ASR、片段时间/序号、来源模式、端点、误截追加关系与断流缺口；原轨迹不可润色替换 |
| AsrRevision | 仅面后更正识别错误；保留原识别、更正原因和 revision，不新增观点或事实冒充原话 |
| SpeechObservation | 回答 revision、独立 version、ASR/算法/阈值、metrics、alignment、quality、覆盖与状态 |
| VisionObservation | 对应回答版本、时间区间、画面质量、头部朝向、面部动作、置信与算法版本；质量不足 unavailable |
| ReviewMedia | 分别授权音频/视频、私有定位、授权/媒体版本、到期/删除状态；默认不保留，显式开启自采集起最长 24 小时 |
| 播放进度 | 问题生成代、实际展示文本、音频位置；生成完成不代表学生听到全部问题 |

基础指标采用以下可解释定义，阈值和效果待样本校准：

- **语速：**有效中文字符数/有效发声分钟，排除标点；展示单位、有效时长、排除规则及 ASR 质量，中英混读另检验。
- **停顿：**发声段间候选静音区间、阈值、次数与时长；设备/断线缺口单列，不能据此推断紧张或逻辑差。
- **疑似口头语：**标注“嗯、呃”等及重复连接词的文本/时间位置；“就是、然后”不能无条件判为问题。
- **音量/音高变化：**描述相对变化与时间位置，注明设备增益、距离、环境噪声和清浊音限制；不据此判断情绪、自信或人格。
- **可选镜头表现：**描述可见画面、头部朝向和面部动作候选；缺脸、遮挡、光照差或置信不足标 unavailable，不推断目光动机、诚实、人格、情绪或技术能力。

观测独立于专业知识、项目表达、代码能力、逻辑表达四维总分。纯文本、关摄像头或低质量不会被记零分。建议关联具体回答片段与质量限制，不能把某个动作或单一阈值解释成能力结论。
