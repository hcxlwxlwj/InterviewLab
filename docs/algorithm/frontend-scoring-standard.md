# 前端实习岗位行为锚定评分标准

版本：frontend-internship-bars-v1；更新：2026-11-03；状态：平台草案，尚未专家审核、人工校准或效度验证。

## 适用范围与方法

适用于前端实习岗位的面试文字回答及最终语音转写。只描述本场已观察表现，不推断人格、情绪、诚实、职业潜力或录用结论。项目事实来自用户陈述，不能当作已经核实的履历。

| 参考框架 | 实际用途 | 边界 |
| --- | --- | --- |
| OPM 结构化面试方法 | 建立岗位能力、问题、观察指标与统一评价规则的对应关系 | 借鉴方法，不宣称机构认证；动态追问并非标准化选拔测验 |
| BARS 行为锚定方法 | 每项指标有 0–4 档可观察表现和示例，判断关联回答证据 | 锚点由平台编写，尚未经过关键事件访谈及专家一致性审查，不能称为已验证量表 |
| SFIA | 辅助梳理软件知识、责任范围与复杂程度 | 不把 SFIA 等级换算成百分制；不按高级岗位要求评价实习生 |
| O*NET | 后续岗位扩展的任务与技能分类参考 | 不进入当前打分提示或评分公式 |
| STAR | 提示用户组织背景、任务、行动与结果 | 不按是否采用 STAR 固定格式打分 |

官方方法入口：[OPM 结构化面试](https://www.opm.gov/policy-data-oversight/assessment-and-selection/structured-interviews/)、[OPM 实施指南](https://www.opm.gov/policy-data-oversight/assessment-and-selection/structured-interviews/guide.pdf)、[SFIA 编程与软件开发](https://sfia-online.org/en/sfia-9/skills/programming-software-development)、[O*NET Web Developers](https://www.onetonline.org/link/summary/15-1254.00)。链接提供出处，不表示这些机构认可本平台锚点。OPM 方法页和 O*NET 岗位页已核对可访问；SFIA 页面本机访问受限，不宣称本轮完成其内容审读。

## 指标与问题映射

| 指标 | 所属维度 | 适用条件 |
| --- | --- | --- |
| 专业原理与正确性 | 专业知识 | 技术阶段，且封存题目有对应专业参考 |
| 方案推理与取舍 | 专业知识 | 技术或业务阶段，明确询问原因、比较、取舍、方案或设计，且有对应专业参考 |
| 个人职责与行动 | 项目表达 | 经历阶段，明确询问本人职责、行动或处理过程 |
| 结果验证与局限 | 项目表达 | 经历阶段，明确询问验证、测试、结果、对比或复盘 |
| 切题与范围 | 逻辑表达 | 有效回答；模型仍可因材料不足标记未观察 |
| 组织与论据连接 | 逻辑表达 | 有可判断的观点与说明；过短或拒绝披露不能强行评分 |

自我介绍只开放两项逻辑表达指标。代码能力本版不评分。题目适用条件由程序结合题目文本、阶段和封存专业参考保守匹配，不由模型根据回答流利程度扩大考察范围。当前动态题目匹配仍是启发式规则；遇到复杂措辞可能漏掉指标，优先不评分，后续应以人工审核过的题目指标映射替代。封存专业参考当前也是草案，不能因有参考就宣称技术判断已被专家校准。

完整五档描述、适用条件和六个合成示例由代码的 `REPORT_INDICATORS` 统一维护，后端提示、网页及 PDF 使用同一版本，避免文档、页面和程序各有一套标准。报告“评分标准与行为锚点”可以展开查看全部内容。示例是教学示意，不是人工标注数据或验证结果。

通用档位含义：0 档需要明确错误、矛盾或偏题证据；1 档为相关但关键内容未回应；2 档为基本回应且有明显缺口；3 档为清楚、有依据且边界基本明确；4 档为本题范围内充分、能够说明限制或替代解释。最终必须用具体指标自身锚点判断，不能只套通用描述。

## 证据、不适用与聚合

每个本题适用指标恰好返回一次：

- `scored`：0–4 整数档，简短理由，1–2 条当前回合和 revision 的真实原文证据。
- `not_observed`：level 为 null，解释未观察原因，无证据数组。不补零，不计入均值。

模型只选择原文片段编号，程序还原原文并核对回答版本。禁止跨回合冒充证据、重复指标、超出本题指标集合或虚构引用。机械校验保证结构和引用存在，不能证明评价语义正确；仍需人工核查。

同一指标的所有已观察回合档位先取均值，再乘以 25。维度内已观察指标等权平均后四舍五入为维度百分制分数；总分为已评分维度等权平均后四舍五入。重复追问只增加同一指标的观察次数，不增加该指标在维度中的权重。没有代码考核、不问结果、不提供相关专业参考均不补零。不同覆盖范围的总分不能作为直接排名或进步幅度。

新标准的评分由逐题指标直接聚合，不依赖整场总结成功，也不再让总结模型第二次自由打分。历史综合分与新标准分不得混合。旧报告 GET 不会触发模型或改分；用户选择“按行为锚定标准重新评分”后，以 scope=rubric 创建新报告版本，重新评价保存的原回答。原回答与 revision 不变；在途任务仍做版本、归属和删除检查。当前不提供完整历史评分版本浏览，升级会替换当前派生结果。

## 人工校准与发布门槛

本轮只完成程序和示例，以下工作均尚未完成，不标记为已通过：

1. 由至少两名熟悉前端实习要求的评审者核对岗位能力和每项档位；收集关键事件，检查锚点是否具体、可区分，是否暗含商业规模或学历偏见。
2. 按指标、档位、题型和回答长度准备独立样本；使用合成或获授权且去标识的材料，不把本机真实回答自动纳入评测。
3. 评审者独立评分，再讨论分歧并形成裁定依据；保留未观察样本，不强行给档位。
4. 分别报告人际一致性、AI 与人工的逐指标档位误差、精确一致率、相差不超过一档比例和加权 Kappa；不要只报告总分相关性。
5. 对相同回答多次运行，记录档位波动、未观察判断、引用有效率和失败率；单独核查口语化、保密拒答、无商业经历、短回答及提示注入材料。
6. 开发样本和留出验证样本分开。评审团队先定义可接受标准，再用留出集检验；不能在看到结果后临时调门槛或用单次真实跑通证明可靠性。
7. 审核记录应包含标准版本、模型与提示版本、样本来源、评审者角色、分歧与适用范围。变更锚点或聚合方法必须更新版本并重新验证。

未完成这些步骤前，页面保持“草案、尚未人工校准”，不得改成“可靠量表”“招聘胜任度”或承诺分数预测招聘结果。
