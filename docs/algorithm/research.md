# 技术与竞品调研

版本：v0.2 · 日期：2026-10-15 · 状态：公开资料调研及待验证方案；不是实现结果、真实用户访谈或市场份额统计。

## 1. 调研问题与记录规则

本项目拟服务实习经历有限、主要以课程项目、竞赛、科研或毕设经历准备技术岗位求职的高校学生。设计重点是围绕真实项目经历开展实时口头模拟面试，在面后关联回答内容、语音节奏和可选镜头表现，再针对具体题目与片段重练。调研用于核对能力边界、交互条件和可验证问题，不把“面向学生”“实时语音”或“表情反馈”直接等同于独有能力。

调研分别记录三种证据：

| 类别 | 可以支持什么 | 不能支持什么 |
| --- | --- | --- |
| 官方事实 | 产品明确介绍的目标用户、功能与服务方式 | 实际效果优于竞品、所有用户都满意、未介绍即不存在 |
| 用户自述 | 某个版本、模块和场景下的个人体验线索 | 普遍缺陷、当前版本一定仍有该问题、因果效果 |
| 机会假设 | 值得通过访谈、原型及对照验证的设计重点 | 市场空白、独有功能或已成立的竞争优势 |

核验日期统一为 **2026-10-15**。本轮是非系统性公开页面小样本检索，没有绕过登录、付费墙或批量抓取用户数据。下文以转述和短摘要记录，保留原链接。页面未给出的版本、使用者身份和样本量不补写；无法复核的内容不作为结论依据。

### 3.1 本轮用户单次体验线索

2026-10-15，用户自述试用面试鸭模拟面试后认可其表现，并观察到本次流程可以先组织或编辑内容再发送；用户也指出可以选择直接口头回答。该线索来自单次使用交流，账号套餐、设备、设置与模块版本没有完整复现实测记录，不能据此写成“面试鸭全部模式不实时”或“缺乏即兴面试能力”。用户希望本项目默认即时口头作答，是本轮产品交互选择，不是已验证的竞品缺陷或效果结论。

用户提供的个人报告仅作为私下讨论材料，不把其项目、回答、简历及评价全文复制到调研正文或评测集。后续若需要对照，应另征授权，使用脱敏或合成同材料任务，记录实际可编辑程度、自动回合、时间约束和退出条件。

## 4. 机会假设与产品选择

现有公开证据不能支持“多数模拟面试产品只服务企业招聘”“学生项目表达尚无人覆盖”或“只有本项目提供实时/视觉反馈”。InterviewLab 将学生项目经历、实时口头交互、内容与表达复盘及定向重练作为完整流程的设计重点，价值与质量需通过试用验证。

| 待验证假设 | 首版设计回应 | 如何证伪或检验 |
| --- | --- | --- |
| 部分学生难区分团队成果和本人贡献 | 轻量选择重点经历，基于确认职责、行动与材料追问 | 用同一项目比较是否追到本人决策；若竞品已解决且体验相当，不宣称优势 |
| 通用项目话术难体现真实技术理解 | 追问当前实现、技术选择、失败处理和验证方法 | 人工标注问题是否与材料和前答相关，是否只替换技术关键词 |
| 即时口头回答可能暴露编辑后文本未呈现的组织与承接问题 | 默认实时语音，端点自动保存与自然接话；允许思考、口头纠正、澄清和打断 AI | 明确实时口语/可编辑文本条件，比较完成负担、误截、接话延迟及实际感受；不预设实时更优 |
| 泛泛反馈不能指导下一次回答 | 结论定位原句/代码/材料，给一项明确缺口和重练目标 | 观察学生是否能解释并完成改进，审查建议是否准确而非堆砌术语 |
| 学生可能难以察觉某次回答中的节奏及镜头现象 | 面后将语速/停顿/疑似口头语/音量与音高变化和可选画面质量/头部朝向/面部动作关联具体片段 | 人工核对可定位性、误报、低质量处理及行动可执行性；不输出情绪、诚实、人格或能力推断，不计四维总分 |
| 学生需要识别有事实支撑的岗位优势 | 将个人行动、结果依据与 JD 要求关联 | 专家检查是否夸大履历；无依据时必须显示待补充而非生成亮点 |
| 同题重答更好不等于能独立迁移 | 首版展示原答与重答、变化依据及可比条件 | 后续用同类新题人工检验，不把模型分数升高直接当作能力增长 |

“没有实习”“没有商业用户”不是缺陷标签。系统按实际项目约束评价解释是否清楚、证据是否合理，允许学生说明没有测量或未上线，并建议如何补证。不能诱导学生编造指标来得到更高分。

本轮先修订文档。后续先用约 5 位目标学生做探索性痛点观察，记录其使用现有工具后的具体困难；再决定原型优先级。该人数用于发现线索，不是市场验证完成或统计代表性结论。完整比较方案见[评测与迭代](evaluation.md)。

## 5. 技术方案与选型待办

技术选择服务上述任务，尚未完成实现或供应商质量比较。

| 子系统 | 当前拟定方案 | 验证重点 |
| --- | --- | --- |
| Web 与业务层 | Next.js + TypeScript，模块化单体及独立异步任务职责 | 状态/版本一致性、端点回合/追加/取消、自动保存、权限和任务幂等；未来前端先 Mock 原型，本轮不写前端 |
| 结构化与检索数据 | PostgreSQL，pgvector 向量检索，中文关键词与向量融合 | 重点经历精确读取优先；用户材料不进入共享库；模型切换需重建索引 |
| 智能任务 | 岗位顾问、面试官、报告评估三职责，由业务编排器调用 | 事实约束、追问相关性、面后报告、原句引用、未观察项及有限重试 |
| LLM/ASR/TTS/嵌入 | 各设适配层，供应商未选定 | 固定材料对照质量、中文技能词、端点误截/漏截、接话延迟、打断与取消恢复、费用及数据处理设置 |
| 代码考核 | 编辑/运行/提交分开；真实执行另用受限隔离服务 | 运行结果与模型评价独立，网络与资源限制；Mock 结果不得伪装为执行成功 |
| 实时口头交互 | interaction_mode 默认 realtime_voice，text_fallback 用于降级/文本联调；端点后自动固化，不编辑确认后发送 | 允许思考、口头纠正和澄清；误截可追加并保留轨迹，AI 主动打断仅可选风格；面后识别纠错不变补答 |
| 语音观测 | 首版语速、停顿、疑似口头语、音量和音高变化，带区间、质量与版本 | 仅描述现象，音量/音高受设备与个体影响；低质量 unavailable，与四维总分独立 |
| 可选视觉观测 | camera_enabled 默认 false；明确开启后记录画面质量、头部朝向、面部动作 | 不以偏离镜头等同无眼神交流；不推断情绪、诚实、人格或能力；拒绝/质量不足不影响内容评分 |
| 复盘媒体 | review_media_enabled 默认 false，原音视频默认临时处理后清除；显式开启私有复盘也最长 24 小时 | 检验真实清理、撤回、到期与任务竞态；媒体到期只保留派生观察，不提供回放或假装重算 |

这些是项目设计取舍，不是对特定框架或供应商性能的保证。保留服务商适配、内容版本和评测记录，后续根据实际质量、时延、费用及数据处理条件决定选型，不以新功能数量作为竞争力的替代指标。

实施顺序为阶段 A 基础闭环与文本联调、阶段 B 首版核心实时语音与基础多模态、阶段 C 对照评测与学生试用。A 的过渡文本链路不能被描述为目标实时体验已完成，B 的可选摄像头也不变成学生必须开启的条件。自动同类新题与 3D 角色另列后续范围。
