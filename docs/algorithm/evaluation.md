# 评测、成本与迭代计划

版本：v0.3 · 更新：2026-10-19 · 状态：独立后端的验收与试用目标；已有文字原型，真实后端、模型及效果实测未完成。

本文把[功能需求](../requirements/functional_spec.md)转为验证步骤，重点验证学生能否在实时口头面试中讲清项目贡献、技术选择，并根据内容及表达复盘进行定向重练。系统必须先模拟、结束后分析、再重练；没有教学前置流程。目标默认实时语音，文本为降级与阶段 1 的真实闭环入口；不能用文本链路可用代替实时验收。共用状态、字段和保存规则见[数据与接口](../software/data_and_interfaces.md)，评分和 Agent 边界见[知识库与智能体](knowledge_and_agent.md)。

## 1. 评测记录与样本边界

分开验证完整产品流程、AI 单任务、实时回合、语音/可选视觉观察、代码执行和数据权限；界面可用不等于追问有效，模型给出的更高分也不等于学生能力提高。语音与视觉观察独立于四维能力总分，不依据表情、音高或停顿推断情绪、诚实、人格或能力。

每次记录样例及版本、合成/授权来源、知识/题库/评分版本、提示与模型标识、检索配置、输入输出、错误类型、时间、用量和费用；另记录 interaction_mode、作答是否可编辑、回合/追加事件、ASR 纠错版本、摄像头与原媒体保存授权、媒体质量和到期状态。真实简历、回答和音视频不得进入公共仓库或默认评测集；使用真实材料须明确用途、授权和访问范围。日常开发优先使用合成材料，不为了评测复制全部学生数据。

固定 AI 样例至少运行 3 次，报告全部通过数、严重错误数和变化范围，不挑最好的一次。业务异常、服务失败与取消失败计入故障；学生主动跳过/结束单独记录。延迟分别从浏览器与服务端计量，报告样本量、环境及 P50/P95；失败不得从成功延迟分布中消失而不计故障。小样本分位数注明探索性质。

开发调参集与最终回归集分开，期望行为、允许的不确定输出和禁止断言预先固定。验收集不得在看到一次结果后反复改成容易通过。

## 2. 固定评测集与学生经历案例

以下规模是可操作的起始目标，不是已经收集的样本，也不能代表所有学生、技术栈或口音。

| 集合 | 起始规模 | 重点 |
| --- | --- | --- |
| 岗位与配置 | 20 份合成岗位 JD，至少包含软件、AI/大模型、数据、产品和设计等方向 | 明确要求/通用说明/推断；岗位、难度、简历、重点经历与可选代码考核一致 |
| 材料与简历库 | 15 份合成 PDF/DOCX 或手填样本，多简历和各经历类型交叉 | 多栏、歧义、缺失结果、扫描/密码文件、库内持久保存、临时到期、错误简历混用 |
| 知识检索 | 60 条查询，其中至少 15 条没有有效资料 | 中文同义词、英文技能词、版本、范围过滤、空检索和过时资料 |
| 面试追问 | 30 组问题/回答 | 个人/团队边界、空泛成果、技术选择、验证、跑题、已答信息、跳过与缺材料 |
| 报告与重练 | 30 组回答及前后对 | 四维锚点、not_observed、原文定位、参考表达事实、同题可比性及版本修订 |
| 权限与对抗 | 至少 20 个场景 | 跨用户 ID、恶意 JD/代码注释、引用虚构、删除中的任务和过期结果 |
| 语音与实时回合 | 30 段合成或授权音频，加实时故障/打断场景 | 技术词、数字、否定词、思考停顿、口头纠正、端点误截/漏截、音量/音高变化、噪音、字幕纠错及质量不足 |
| 可选视觉与媒体 | 至少 15 段合成或授权受控视频，加拒绝/到期/删除场景 | 画面质量、头部朝向、面部动作、遮挡/光照/帧率、片段定位、不作心理推断及媒体期限 |
| 可选代码 | 按 C++/Python/Java 各至少 3 个受控用例 | 正常、边界、超时与执行失败；真实运行和模型评论区分 |

贯穿合成案例：

| 场景 | 已知事实与回答问题 | 期望行为与禁止结论 |
| --- | --- | --- |
| 课程预约系统 | 四人团队；本人负责预约接口、数据库约束和并发测试；未用 Redis、未上线。回答却说“用 Redis 提升了性能” | 澄清个人职责与实现；指出回答和确认材料不一致。不补写性能数据，不因无线上用户扣分 |
| 团队算法比赛 | 团队获奖；本人做数据清洗和错误分析，队友负责主要模型；仅有离线指标 | 问清个人行动与验证划分，不能把获奖/全部模型工作归本人，不能将离线结果当线上收益 |
| 科研复现实验 | 本人复现公开方法并记录不一致结果；未发表论文，无新算法主张 | 追问环境、变量、对照与局限；不能推断论文、原创突破或“没有正结果所以失败” |
| 毕设前端项目 | 本人完成界面和可用性试测；没有业务增长指标 | 依据目标与试测证据评价，不要求编造转化率；专业问题须匹配实际负责部分 |
| 少量实习 | 本人只实现一个接口并参与测试；性能优化归团队，代码不可上传 | 尊重材料限制，允许文字说明；不夸大 owner 身份，不把实习类型自动加分 |

每个案例增加“回答不完整”“已说清”“只有临时 ASR”“口头纠正”“误截后追加”“全跳过”“更换简历”“来源材料删除”变体。最终集不得只围绕贯穿示例编题，以免系统记住样例。

## 3. 产品、AI 与安全验收

### 独立后端与新合同的工程验收

- 通过统一入口分别访问 Next.js 与 Fastify，Cookie 登录及 WebSocket 同源鉴权生效；原型当前仍由 Next.js 承载，不能在文档验收中宣称已切换。
- 生成 OpenAPI 与实际路由逐项对应，验证分页、错误体、version、幂等键、202/任务查询；另测实时事件类型。旧 /sessions、/resume-documents、/history 的客户端整体迁移，无第二套私有业务。
- 在 PostgreSQL 集成环境验证迁移、唯一收藏、默认简历、版本、归属及多表事务。两份简历 → 切换经历 → 收藏/个人 JD → 配置 → 面试 → 报告 → 重练比较 → 记录回看可完成。
- 注入“业务事务已提交但队列投递失败”、outbox 重扫、重复领取、worker 重启及旧任务提交：回答保持已保存，业务结果不重复，输入过期/删除后不发布。
- 注入首题/追问/报告模型失败，检查只有对应任务失败，不能回滚已保存回答或将完成面试改成失败报告；无凭证返回能力不可用。
- 第一阶段验收有证据的分析，未校准时四维/总分为空；第二阶段人工校准后再启用数值评分及下面的评分样例，不能用固定合成分数通过真实 Agent 验收。

### 完整流程和异常路径

| 场景 | 通过条件 |
| --- | --- |
| 实时主链路 | 首页 → 配置选简历/重点经历 → 双栏即时口头模拟 → 面后内容及表达报告 → 单题重练 → 个人中心记录完成；自动保存完成回合，版本/片段关联正确，无编辑确认发送步骤 |
| 文本联调与降级 | interaction_mode 明确为 text_fallback；可输入发送并完成基础闭环；显示模式差别，切换时保留原回合，不把文字作答视为已观察语音/视觉表现 |
| 无材料或解析失败 | 可手填、跳过或进行通用面试；明确个性化范围，草稿不作为已确认事实，不强迫经历整理课程 |
| 简历库/临时上传 | 库内已确认版本可选、默认项正确；临时默认不入库，最长 24 小时清文件/草稿；不删除独立确认经历和历史快照 |
| 选错/混用材料 | 不跨用户、跨所选简历自动混入经历；开始前材料更新要确认，开始后冻结快照，修改个人材料不改历史 |
| 面试边界 | mode 只接受 mock；澄清题意可用，不提供示范答案/答题框架/实时评分；进行中仅设备、连接、采集等运行信息，任何表达观察/点评都在面后开放，HTTP/WS/API 同样限制；重练也不变教学模式 |
| 时间与次数 | 5/10 分钟可选、默认 10；最多 6 主问题、每题 2 次追问；目标时间提示收尾，含暂停 12 分钟安全上限，重连不重置 |
| 保存、断线与重复请求 | 完成回答和追加片段自动持久保存；重连依服务端状态继续；同幂等键不重复计回合/创建报告，任务重启不丢完成回答 |
| 结束和报告失败 | 提前结束保存有效回合；completed 和报告 pending 分开显示，报告可独立重试；failed 有有效回答可出部分报告且不改终态 |
| 重练比较 | 明确选中原题、目标、时间片段及两份回答 revision；保留原答，不自动选最新回合；内容和表达分开比较，模式、材料、题意、媒体质量或规则变化说明可比限制 |
| 实时回合与打断 | 思考/口头纠正不会立即截断；误截可追加并保留事件；漏截有手动完成恢复；取消旧生成/播放后迟到内容不重现；AI 主动打断仅在明确选择的风格启用 |
| 识别纠错 | 临时字幕不评分；面后更正只改识别错误，保留原文、原因、版本及原 AnswerSegment，不用补答或润色替换当时表现；相关报告/比较标记过期 |
| 摄像头与原媒体 | 两项开关分别默认 false；拒绝或撤回不阻塞面试；临时处理后清除；仅保存明确授权后采集的后续片段，每片段自采集起最长 24 小时，重连/重试/后续授权不重置；到期无回放、无假重算，必要派生观察可保留 |
| 表达反馈边界 | 每项观察有题目/时间片段、来源版本和质量；缺失或低质量为 unavailable，不加能力零分；不从语音、表情或偏离镜头推断心理、诚实、人格和能力；进行中 HTTP/WS/API 仅返回设备/连接/采集等运行信息，不能提前读取表达观察/点评 |
| 删除与导出 | 简历文件删除不静默删除独立确认经历；删除经历/会话说明级联并清派生任务；导出 PDF 与当前报告版本、未观察项及覆盖范围一致 |

P0 业务及数据约束须全部通过。跨用户访问、丢失完成回答、事实编造被发布、未经授权的媒体保存或无界调用阻止进入试用，不能通过平均分掩盖。

### AI 质量及评分校准

| 指标 | 计算/检查方法 | 待验证门槛 |
| --- | --- | --- |
| 检索有效召回 | 人工标注有依据查询中，前 5 片含有效片段比例 | ≥85%，报告各岗位和术语子组 |
| 空检索处理 | 无依据时不虚构来源，说明资料不足 | 固定回归集全部通过 |
| 追问相关性 | 人工判断与岗位、选定经历及当前回答缺口有具体关系 | ≥90%；只替换关键词、重复已答内容判无效 |
| 面试与预算约束 | 状态/次数/时间自动检查，人工检查答案泄露 | 固定回归集全部通过 |
| 引用有效性 | ID、revision 及逐字引用程序检查；结论支持关系人工检查 | 程序全部通过，语义支持率≥95% |
| 学生事实边界 | 不新增本人职责、数字、技术实现、奖项归因或商业成果 | 固定集无此类错误，发现错误的报告不发布 |
| 反馈可执行性 | 建议是否有明确缺口、依据及可完成的动作 | ≥85%，保留失败示例 |
| 观察范围 | 未触及维度 null/not_observed，零有效回答不评分；无实习不扣分；中断原因未知不推断作答意愿 | 固定集全部通过 |
| 多模态依据 | 观察可定位到实际回合/时间片段，音视频质量不足明确不可用，不输出情绪、诚实、人格或能力推断 | 固定集全部通过；失败单列，不以平均准确率掩盖 |
| 分数计算 | observed 四维等权平均、四舍五入，覆盖数正确 | 确定性用例全部通过 |

以上百分比是设计目标，尚未测得。分母为可判定样例，同时报告不可判定、服务失败与缺失数量；不能只统计成功输出。

评分维度为专业知识、项目表达、代码能力和逻辑表达，0～100 分或未观察。至少抽取 20 份覆盖不同经历与观察范围的报告，由两名评阅者独立标注，记录每维分差、是否跨锚点档、引用错误和 not_observed 分歧。分差超过 15 分或观察状态不一致时复核原因；这是复核触发值，不是已验证的信度标准。先修改锚点、题目与提示再回归，不能通过改权重掩盖分歧。报告呈现人工一致性和局限，不将 LLM 自评视为真值。

### 数据、隐私与可选代码

账号 A/B 覆盖列表、详情、下载、预览、实时流及报告导出，替换资源 ID 一律不能越权。恶意 JD、上传材料和代码注释不能改变工具权限、发起任意网络请求或输出密钥。浏览器包、错误、日志不得含长期供应商密钥或完整私有正文。

验证删除中仍运行的解析/报告/多模态任务、服务重启任务重放和备份恢复；删除标记后不得重新发布。检查真实临时文件、音视频缓冲和到期原媒体的清理，不能只验证页面文案。确认 camera_enabled 和 review_media_enabled 默认 false，保存授权不与面试绑定；只保存授权后采集的后续片段，每片段自采集起最长 24 小时，重连、重试或后续授权不延长期限。到期后回放链接失效、需要原媒体的重算拒绝并说明原因；补授权不得恢复或追存原先未授权的媒体。供应商处理与留存设置未核实前，不用真实学生材料做云端试用。

代码考核可关闭；关闭时不阻塞主流程、代码维度不观察。真实执行测试超时、内存、输出上限、禁网和错误恢复，执行环境不能读应用密钥。运行失败不得伪造通过；Agent 判断正确不覆盖测试失败，测试通过也不自动等于所有边界正确。未来 Mock 原型的模拟结果有清晰标识。

## 4. 实时交互、多模态与性能试验

ASR 用人工标注音频计算中文字符错误率，并单独检查数字、否定词及英文技能词。初始服务比较目标为安静环境字符错误率≤12%、关键字段正确率≥95%；不是所有口音或噪音条件保证。临时/回合最终字幕有区别；默认端点判定后自动保存和自然接话，不要求编辑或确认后发送。面后识别纠错须保留原文、原因、AsrRevision 与 AnswerSegment 轨迹；覆盖技术词误识别与口头自我纠正，防止把事后新补充的内容冒充纠错。

语音观测另与人工区间标注比较：语速须公开时长、计数单位和静音处理规则；停顿阈值通过标注校准；疑似口头语需排除语义必要的用词；音量和音高变化要记录设备条件及提取质量。报告区间误差、误报/漏报及质量不足数，不用单一“表达分”合并，也不计入四维总分。首轮先人工检查 30 段标注样本再制定数值阈值，不能在无数据时宣称准确率。

视觉仅在明确开启摄像头后采集，检查画面质量、头部朝向与面部动作的可定位性；遮挡、低光、过低帧率等低质量设为 unavailable。人工核对观察是否与对应片段一致、是否把偏离镜头误写成“缺乏眼神交流”。构造相同内容但不同声音/面部动作的样例，检查内容评分是否被无依据改变。禁止输出情绪、自信、诚实、人格和能力推断；语音与视觉分别展示，均不计四维总分。

转写纠正后，原声学时长/停顿和视觉事实不变，文本相关观察在必要派生依据存在时生成新版本；需原媒体的重算必须核对 ReviewMedia 状态与授权。验证到期后不能回放或声称重算完成，只保留有版本的派生观察和不可用说明。无音频、音频过短、噪音严重时显示未观察或 unavailable，不从标点推断声音表现。摄像头拒绝、撤回或设备不可用不阻塞语音面试，麦克风不可用可转文本。

实时测试包括思考停顿、尾句拖长、连续说话、口头纠正、端点误截/漏截、误截后追加、说话中打断 TTS、生成中打断、迟到事件、连续打断、麦克风/摄像头拒绝、设备变化、浏览器播放限制和弱网重连。端点由人工标注实际意图判断，报告误截率、漏截率和延迟；首轮 30 段标注后制定阈值，不把一次短暂停顿都当回答结束。取消后旧 generation 不继续播放；问题保存生成文本和实际播放进度，未听到的后半句不当成已问。AI 主动打断仅覆盖明确开启的风格条件；语音失败转文本并保留完成回合与切换事件。

在目标网络 RTT≤100 ms、丢包率<1%、10 场并发下，采集至少 200 个有效回合，初始目标为完成回答到首片文本 P95≤5 秒、语音端点确认到首段可播放音频 P95≤6 秒。另报告从人工标注的学生实际说完到 AI 可听接话的延迟，避免只降低端点后耗时却等待过长。分别计量端点检测、检索、LLM、TTS 和浏览器排队；未达标先定位慢段，再由团队评审调整目标，保留失败与慢样本。本轮没有性能实测。

## 5. 同材料对照与学生试用

先邀请约 5 位符合目标条件的学生，观察其使用现有工具后仍讲不清的具体内容，征得授权后记录脱敏问题；不将公开评论冒充用户访谈。若主要需求已被现有工具解决，允许缩小投入或调整切口，不能预设必须证实差异化。

后续对照包括本系统、可访问的现有陪练产品，以及认真设计面试提示词的通用 LLM。通用模型基线提供相同 JD、确认经历、关键材料、时间预算和面后反馈要求，不能故意不给上下文或使用明显弱提示来制造优势。

| 控制/记录项 | 方法 |
| --- | --- |
| 材料与任务 | 同一份简历、确认经历、可公开关键材料及岗位；限定为相同可观察目标 |
| 交互条件 | 明确实时口语、录音后提交或可编辑文本；记录是否允许整理/改写、思考时间、打断风格及辅助提示。不把不同条件的差异直接归于产品质量，不预设实时方式更优 |
| 媒体与表达 | 摄像头选择、设备/环境、原媒体保存授权与到期状态分别记录；拒绝摄像头仍可纳入内容比较，不用媒体缺失补零分 |
| 时间和次数 | 统一练习时长、重答机会和是否可补充事实；顺序平衡，避免熟悉材料的一方固定后测 |
| 模型和套餐 | 能控制则用同模型/参数；商业产品未知或不同供应商时如实记录，不能把差异只归于设计 |
| 人工评价 | 两名熟悉技术面试的评阅者盲评脱敏输出，统一锚点；隐藏产品及前后标签，记录分歧 |
| 质量指标 | 追问对经历与前答的相关性、反馈准确性、事实编造、可执行性、学生能否说明并完成改进 |
| 负担与成本 | 配置耗时、材料确认负担、完成率、等待、重练选择及实际费用分别报告 |

首版产品提供同题定向重练：前后原文、明确缺口、原题/时间片段与变化依据。内容改善和表达现象分别比较，说明交互模式、可编辑程度、媒体质量及观察版本是否一致；还须说明是否新增材料或事实、是否看过参考表达、题意和评分版本是否相同。同题分数上升不能证明迁移，语速变化也不自动等于表达改善。新题检验在首版可由评测人员人工安排，自动生成同类新题属于后续产品扩展。

流程稳定后可进行约 12～20 名目标学生的探索性可用性试用，覆盖课程项目、比赛、科研/毕设及少量实习背景。用不同但同类、难度近似的问题检查迁移，条件允许再做约一周延迟观察。记录前后回答、练习次数、参考答案暴露和新事实，报告配对变化、缺失与不确定性。人数是探索建议，不是正式统计功效结论；没有合适对照不作因果归因，不宣称统计显著、Offer 提升或普遍招聘效果。正式研究另立方案和样本量分析。

## 6. 供应商、费用与阶段门槛

LLM、ASR、TTS、嵌入分别通过适配层比较，尚未指定供应商。先核验目标网络可用性、数据处理地区及留存设置，再用固定材料比较；先过事实、引用与权限门槛，再比较延迟和费用。评测者尽量不知道供应商名称，备选适配器同样需验证。切换模型记录版本，不静默混入历史比较。

`C_session = LLM 输入/输出实际用量费用 + ASR 费用 + TTS 费用 + 嵌入/解析费用 + 语音/视觉处理费用 + 可变存储/网络/代码执行费用`

单独计固定服务器、数据库、备份与开发成本。费用包括失败、修复、重试、报告及重练；入库嵌入按内容版本计算，不能每场重复算同一入库成本。ASR 按输入、连接还是静音时长收费，TTS 按字符、token 还是音频计费，均待核验实际条款。没有报价不写单场承诺；发布前用至少 50 场代表性会话核对应用记录和账单，再给出 P50/P95、失败费用和限额。
