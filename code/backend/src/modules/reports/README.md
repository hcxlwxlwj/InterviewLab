# 文字面试复盘报告

本模块处理已结束文字面试的复盘。一场面试对应一份报告；逐题分析、整场总结与重练比较通过现有 worker 异步执行。真实模型的专业质量仍需人工验收，自动测试使用受控输出。

## 已实现内容

- 逐题亮点、缺口、参考要点、练习目标及回答原文引用。
- 同一主问题的上下文辅助追问分析，引用仍严格限定当前回答版本。
- 已成功题目在其他题目分析中即可读取，进度区分成功、待处理和最终失败。
- 整场总结、最多三个优先目标，引用必须来自已校验逐题评价；优势不使用缺口证据，目标复用对应题目的原有练习目标。
- 缺失逐题分析与整场总结分别重试；总结失败保留逐题结果。
- 原题重练及前后比较沿用已有接口。
- 零回答不调用分析模型；无代码考核不观察代码能力；未观察维度保持 null。已观察且有对应证据的维度可生成 AI 参考评分。
- 旧报告可读取，GET 不触发模型；用户显式请求后才生成历史报告总结。

## 启动与接入

从仓库根目录执行。先按[后端说明](../../../README.md)配置开发数据库、模型和受邀登录账号；数据库及模型凭证只保存在本机环境。

```bash
npm run db:migrate
npm run dev:api
```

另开终端分别运行 `npm run dev:worker` 和 `npm run dev`，登录后完成文字面试，从结束页或面试记录进入 `/reports/{interview_id}`。

需要应用新增迁移 `0004_text_report_summary.sql`，为报告添加 summary_task_id 与 summary_input_digest。应先部署迁移，再同时更新 API 与 worker，旧 worker 不认识新任务类型。

`npm run dev:interview` 是面试模块专用联调：其 onFinalize 明确不生成报告，不能用它验收自动报告闭环。报告联调使用上述完整组合；已有专用联调记录也可以在具备相同身份的完整组合中显式请求报告。

## HTTP 合同

路径前缀为 `/api/v1`，需要共享 Cookie 身份和资源归属校验；写请求还需要同源 Origin 与 Idempotency-Key。

| 方法 | 路径 | 输入与行为 |
| --- | --- | --- |
| GET | /interviews/:id/report | 当前报告、逐题结果、分析进度及总结子状态 |
| POST | /interviews/:id/report | `{version, scope?: "missing" \| "summary"}`；缺省 missing 兼容旧客户端 |

pending/generating 返回 202，终态返回 200。报告不存在时首次请求使用 version=1；进行中面试返回 409，越权与不存在返回 404，过期版本返回 409 version_conflict。

scope=missing 只补失败或缺失题目，复用成功结果，再生成对应总结；scope=summary 只重试失败或未请求的总结，不重跑逐题分析。有效总结、无有效回答和已在生成中的相同版本请求复用当前状态。重试递增版本，同一幂等键的不同输入冲突。

新增可选字段 analysis_progress、summary_status、summary、analysis_metadata；可选是为了兼容旧报告。旧总结状态为 not_requested，无回答/无可用评价依据时为 not_applicable。报告 ready 不保证完整，需同时检查 is_partial、missing_turn_ids 和 summary_status。

## 任务与一致性

- reports.evaluate.v1：绑定报告版本、回答 revision 与封存输入摘要。
- reports.summarize.v1：绑定报告版本、封存输入及逐题结果摘要。
- comparisons.generate.v1：沿用原答与单题重练比较。

模型在事务外运行；结果通过 TaskOutcome.commit 与任务成功同事务提交。提交前重检来源、归属、版本及摘要；删除或过期结果不可发布。总结任务引用保存在数据库列，正文保存在现有 JSONB，不新增一套任务表。version 目前不提供完整历史版本浏览。

工程检查：`npm run check`、`npm run build:backend`、`npm run openapi:generate`、前端构建。

使用独立 interviewlab_test* 数据库运行 `npm run test:db`、`npm run test:process` 和 `npm run test:web`。数据库测试会清理测试表，不得使用开发或生产库。

本轮未接入语音和 PDF 导出。数值评分是未经人工校准的 AI 参考评分，不是经过验证的招聘能力量表。后续语音应提供最终转写及 revision、输入方式、质量与片段关联；声学观察独立展示，更正转写后重新生成受影响分析。

## 参考评分与展示更新

报告顶部展示总分、维度分、简短理由和进度条，引用默认折叠去重，原回答在逐题区域按需展开，避免同一段文字重复占据评分卡片。

模型按固定锚点选择 0–4 档，程序将档位乘 25 得到百分制维度分，总分为已评分维度等权平均并四舍五入。专业知识侧重原理和推理，项目表达侧重个人职责和行动，逻辑表达侧重切题与组织；没有证据的维度不评分，不补零。每个档位必须关联对应维度已有的逐题证据。当前 scoring_status 为 experimental，评分规则版本 text-evidence-levels-v1，尚未经人工校准。

旧报告不会在 GET 时补造分数。已完成但缺少评分的报告可通过 scope=summary 显式升级，仅重新生成总结与维度评估，不重新执行成功的逐题分析。新增字段保存在现有 JSONB，沿用旧报告兼容，不新增数据库迁移。

为降低长输出造成的超时，逐题分析限制亮点/缺口数量、引用长度和参考要点数量；失败仍按已有有限重试处理。不能保证外部模型不再超时。

本轮体验更新验证：138 项普通测试、43 项隔离数据库测试通过；后端构建及临时副本中的前端 webpack 生产构建通过。已在本机真实模型链路验证历史部分报告升级为 experimental 评分；部分缺失题目仍明确保留失败状态，不计入已分析覆盖。总结模型选择证据编号，程序还原引用；维度分依据限定在对应维度的既有逐题评价，防止模型改写引用或混用来源。评分证据默认折叠，不再把长回答直接铺满能力卡片。

## 前端演示专业参考

`docs/algorithm/content/frontend-report-reference.json` 提供八个主题的专业要点、可接受替代方案、常见错误、适用边界和参考链接：闭包、状态管理、异步竞态、渲染性能、HTTP 缓存、弹窗可访问性、组件设计和表单测试。当前版本为 `frontend-report-reference-v1`，属于未经专家审核的演示草案，链接不代表本次已逐页核验，不是官方评分量表。

本地前端岗位题目和独立知识库的匹配题目，在读取时按显式主题附加 `KnowledgeQuestion.report_reference`。该可选字段随面试知识快照保存，报告逐题分析把相关题目及其参考一并传给模型。其他岗位、未知主题和历史快照保持原行为；不按回答关键词猜测关联专业标准。现有总结继续使用已校验的逐题分析，不重复读取最新文件。

更新后重启 API 和 worker，再新建前端面试即可使用，无需导入独立知识库或新增数据库迁移。旧面试的快照不会自动补充本次参考；演示应创建新面试。报告使用者仍需检查专业判断质量，参考清单不是本题必答清单，不因未主动提及扩展点扣分。后续扩展时增加主题与经过审核的参考，并为同义主题补充显式映射；内容变更递增 version。

## 前端实习行为锚定标准

`frontend-internship-bars-v1` 为平台编写的评分草案，借鉴 OPM 的岗位—问题—评价规则映射与 BARS 行为锚点方法。专业正确性、方案取舍、个人职责、结果验证、切题、组织六项指标按本题阶段、明确提问和封存专业参考选择适用范围。指标档位、解释和当前回答证据保存在逐题结果；程序按指标、维度聚合，不依赖总结模型再次打分。无证据、未问或未考代码保持未观察，不补零。

共享定义在 core 的 `report-rubric.ts`。报告 DTO 新增可选 `scoring_rubric_version`、`indicator_assessments`，保存在既有 JSONB，无新迁移。POST 报告增加 `scope=rubric`，仅适用于前端实习，显式重新评价保存的回答；替换旧任务时清空旧评价，避免运行中的新版本误读旧结果。沿用同源、身份、幂等、版本和删除检查。旧 GET 不静默升级。

页面与浏览器 PDF 导出显示标准版本、每项档位及对应行为锚点。PDF 使用本机浏览器打印并“另存为 PDF”，并非云端导出服务；个人报告不为导出上传第三方。专家审核和人工校准未完成，详见[标准与校准计划](../../../../../docs/algorithm/frontend-scoring-standard.md)。

## 六维反馈模板（interview-feedback-v1）

根据用户提供的《面试反馈模板》的正式维度评分表，新增可选 `summary.feedback_template`，历史记录保持可读，不将旧四维分数转换成新六维。维度为专业基础与知识深度（25）、项目/经历理解与复盘（25）、问题拆解与逻辑思维（25）、表达与沟通（15）、岗位/方向匹配与动机（5）、综合素质（5）。示例页的五项分值与评分表冲突，以六维评分表为准。共享定义在 `code/core_engine/src/feedback-template.ts`。

新总结提示版本为 text-review-v6，使用已校验逐题引用生成六维百分分、分阶段行动与验收方式、下一步期待。专业评分只引用有专业评估依据的题目；综合素质仅描述本场明确的主动与反思行为，不推断人格、抗压或长期稳定，不输出录用结论。模型结构兼容旧适配器未返回模板的输出；前端明确显示未评价并提供显式重新生成入口，不伪造数据。

各维贡献为百分分乘权重；未评价保持 null，综合参考分按已评价维度权重归一化，并显示覆盖权重，避免把未评价项算作零分。新字段存于现有报告 JSONB，总结服务、HTTP schema 与 PDF 导出同步支持，无新增数据库列。scope=summary 可显式升级缺少此模板的历史 ready 总结；GET 不触发模型。逐题行为锚定评分继续保留为底层依据，不与新模板混算。前端六维雷达与逐题覆盖图横向并排，位于六段反馈正文之前。

## 报告生成延迟优化

回答保存及语音补充回答时，在同一事务创建逐题分析任务，面试继续进行时由 worker 提前分析。
报告草稿使用内部 draft 状态，不参与终态报告维护扫描，也不对进行中的面试开放读取。结束时复用有效分析，不重复调用模型；最后一个分析发布后
直接入队总评，维护循环仍负责失败任务收敛和兜底。零回答面试不调用分析模型。

逐题任务以回答内容、revision、主问题及此前回答上下文、冻结快照和分析版本生成摘要；新回答
不会使前题失效，语音补充会替换任务并阻止旧结果发布。已有旧格式任务保留整场摘要校验。
复用现有报告与逐题表，无新增数据库迁移或公共 DTO。

新报告和比较任务投递至独立的 interviewlab-reports-v1 队列；实时出题继续使用原队列，已投递的
旧报告任务仍可消费。WORKER_CONCURRENCY 和 WORKER_REPORT_CONCURRENCY 分别控制每个 worker
两条队列的并发，默认各 3，范围 1–32。多实例并发会累加，应按模型限额调整。更新时 API 与
worker 应使用同一版本，并重启 worker；使用自定义 onFinalize 的纯面试组合不启用提前分析。

## 六维证据识别 v7

六维总评逐段检查已成功分析且 revision 一致的原回答，允许同一原文支持多维，
不再因题目类别、旧维度标签或没有专门问动机而排除逻辑思维、岗位匹配度等维度。
岗位匹配度评价回答展现的岗位相关知识和做事方式，不等同录用结论；综合素质仅观察
学习、主动验证与反思。专业基础直接评价已核对原文中的概念、原理、技术取舍和边界；题库参考仅辅助判断，不作为准入条件。不因技术名词出现就自动给分。
原回答引用按 turn_id、revision 和连续原文校验，仅六维模板可使用新增原文编号；
总结优缺点与练习目标继续使用已校验逐题证据。无证据维度仍返回 null，不补零或默认分。
历史报告保留，用户可点“更新六维分析”仅重生成总评，不重复逐题分析。

专业基础规则修订为 v8，旧六维报告可通过“更新六维分析”升级；原文、revision、证据引用与无依据不补分的校验继续保留。

## 逐题重练与原报告更新

逐题复盘位于 `/reports/:id/practice` 独立页面。重练结束后“面试报告”返回来源面试。
报告读取附带 `answer_sources` 和 `needs_refresh`；前端重新进入或刷新时，如有新的已完成重练，
通过同源 POST 的 `scope=latest` 更新报告版本、逐题分析和总评，持续轮询生成进度。
每题使用结束时间最新且已作答的完成重练，进行中及无有效回答的重练不替换来源答案。
原面试、首次回答和各次重练记录不改写；展示最新回答时仍可展开首次回答或进入对应重练记录。
删除已采用的重练后，再次打开报告会重新选择仍存在的最新回答。

此次无新增表或迁移。`ReportRequest.scope` 新增 `latest`，`InterviewReport` 新增可选
`answer_sources` 与 `needs_refresh`，API Zod 合同与 core DTO 同步。报告分析通过面试服务
获取组合视图，引用保留重练本身的 turn_id/revision，旧报告任务按版本与来源摘要隔离。
