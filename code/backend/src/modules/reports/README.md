# 报告与单题重练

专业、业务、综合面评分规则为 `question-six-v1`；新HR面使用 `question-observed-v2`，分析提示为 `text-review-v12`。本模块复用原有任务、鉴权、版本和 JSONB 存储，无新增数据库迁移，不清空已有报告。

## 评分与计算

每道主问题及其追问构成一个评分单元。逐回合分析保留亮点、缺口和原文；每个回合的六维评分综合同题此前回答，最后一个已作答回合的完整评分作为本题得分依据。最后回合失败时不回退到前一回合冒充完整评分。

六维为专业基础、项目理解、逻辑思维、表达沟通、岗位匹配、综合素质，固定权重 25/25/25/15/5/5。每维必须返回 0–100 整数及理由，不允许未观察、空值或跳过；完全未体现可为 0 分，取消固定 20 分。非零分须引用本题组中 revision 一致的连续原文；无证据只可为 0 分，不推断用户真实能力、人格或招聘结果。

上述完整六维规则适用于专业、业务、综合面。HR仍使用六维注册表，但模型以null标记未考察位置，服务端将其从feedback_assessments中省略，不补零；已评分项（包括0分）必须有原文证据。到岗、地点、薪资及出勤条件只记录，不按条件高低评价能力。单题按已考察维度权重归一化；整场每维仅对考察过它的主问题等权平均，再按已有维度权重归一化。纯安排题不产生能力分，未完成的分析仍阻止完整总分发布。

HR图表只显示已考察维度，少于三维使用条形图；表格保留六维并标明未考察。不同评分版本不混合比较，历史报告不自动改分。

程序计算单题加权分、各主问题等权的整场维度分、最终总分。保留精度至最终展示再四舍五入。追问不额外增加权重。模型总结不再另行打分。失败及生成中是任务状态，不能以 0 分代替失败。尚未完成全部主问题时不发布完整总分。

## 重练与建议

单题重练沿用冻结快照、原主问题及追问要求，只生成本题评分和建议，不入队整场总结、不改原报告及原回答。报告 GET 附带本人历次完成重练的评分记录，包括首次分数、评分版本和时间；不同版本不参与差值或折线比较。删除重练后相应记录消失。旧 `latest`、`rubric` 请求范围及页面升级入口已删除。

`reports.advice.v1` 为独立建议任务，评分提交后再入队。建议任务可读取本场冻结简历，将已有项目/技能用于安排具体练习和验收方式；评分与总结调用不接收简历。建议响应只允许 next_steps，不允许返回分数。建议失败不会回滚评分；GET 反映 pending/ready/failed，前端保留原练习目标作基础建议。旧模板和辅助指标仅供历史数据读取，不再生成。

## HTTP 与共享合同

沿用同源 Cookie 身份、资源归属、Origin 和 Idempotency-Key。

- GET `/api/v1/interviews/:id/report`：只读，无自动重生成。
- POST 同路径：`{version, scope?: "missing" | "summary"}`，分别重试缺失分析或整场总结。重练不生成整场总结。
- 新可选字段：evaluation.feedback_assessments/question_scoring_version；report.question_scores/feedback_assessments/question_scoring_version/practice_history；report.advice_task_id/advice_status/next_steps。
- 保留历史报告字段，缺少新评分的历史记录不补造分数、不混合比较。新记录存于原 JSONB，无表结构迁移。

新任务处理器注册于 reports.handlers，运行组合自动注入 worker。API 与 worker 必须使用同一代码版本并重启。

## 验证

`npm run check`、`npm run build:backend`、前端构建；数据库回归只使用独立 `interviewlab_test*` 数据库。重点验证六维完整性、零分/非零证据、同题追问合并、固定权重与精度、迟到版本、重练不改原报告、建议失败隔离、身份和删除。

## 模型延迟修复

逐题调用只生成六项 `[分数,短理由,证据编号]`、简短优缺点与练习目标；ID、revision、维度键和完整引用由服务端恢复并校验。原文在输入中只传一次，专业参考保持冻结。报告调用与实时出题一致设置 `thinking=disabled`，逐题输出上限1000 tokens；取消、超时与有限重试继续生效，不以默认分代替模型失败。
