# 报告与单题重练

`interview-policy-v3` 准备快照启用 `question-evidence-v3`，分析提示版本为 `text-review-v16`，响应协议版本为 `text-review-v3`。本模块复用原有任务、鉴权、版本和 JSONB 存储，无新增数据库迁移，不清空已有报告。旧 `question-six-v1` 和 HR 的 `question-observed-v2` 快照保持原读取兼容，不自动改分，不与新版本混合比较。

## 评分与计算

每道主问题及其追问构成一个评分单元。逐回合分析保留亮点、缺口和原文；每个回合综合同题此前回答，最后一个已作答回合的分析作为本题得分依据。最后回合失败时不回退到前一回合冒充完整评分。后续问候不能作为新证据，也不抹掉同题此前的真实回答。

六维为专业基础、项目理解、逻辑思维、表达沟通、岗位匹配、综合素质，固定权重 25/25/25/15/5/5。专业、业务、综合面保持整场六维规划覆盖目标，每道题只评价实际考察且有回答证据的维度。逐题六维观察状态保留审计记录，单题只对其实际内容计分；整场展示规则单独汇总。整场专业、业务、综合面完成逐题分析后，固定输出六维雷达图；本场回答未体现的维度计0分，无引用时不编造证据。该分数衡量本场展示，不断言真实能力不存在。HR和单题重练保留实际维度；少于三维使用条形展示。

模型在同一次逐题调用中先按实际问句确定 `question_scope`，再判断每个回答的资格、关联性、充分程度和是否已到表达上限。封闭事实题正确简答可以充分，不要求回答未问到的原理、推导或边界，也不因此额外评逻辑或沟通。到岗、地点、薪资及流程题只记录条件，不产生能力评分或优缺点。判断依据是业务语义，不依赖字数或关键词；`O(1)` 可以是有效回答，知识题明确表示不知道可以只形成对应知识不足的观察，不能推断全维能力、态度或人格。

评分模型不接收简历。候选人证据目录仅包含本题组实际回答的连续原文，题目、面试官话、简历及专业参考不进入目录。服务端恢复证据对应的 turn/revision，验证原文、回答资格、题意允许的维度及观察状态；逐题数字（含0）必须有可评价的候选人证据；整场缺失维度的0分由统一汇总规则产生，不伪造引用。问候、澄清、拒绝或离题回应不产生能力分、亮点或缺口，模型输出违反契约则明确失败，沿用已有有界任务重试，不补默认分。

新执行同时记录 `knowledge_evidence`，区分实际知识展示、仅自述熟练度、未出现知识内容和含义不清。专业数字只接受实际知识展示或知识题明确不会；项目陈述中的具体机制、方法和推理也属于知识展示，未经外部核验不等于空泛自述。标准自我介绍只观察介绍本身的表达沟通，其他五维在全介绍题组的响应 schema 中固定为 null；不传六维深度锚点、完整岗位要求及专业参考，不把未要求的技术、完整项目复盘或量化结果当介绍缺口。后续明确考察项目、动机等的问题用实际阶段与问句单独评价。开放解释、经历、决策和反思可同时体现实际推理组织及沟通，不要求问句直接点名这两种能力；闭合事实简答不因此扩维。语音输入明确标为转写，缺少音频质量证据时不能断言杂音、口音、流利度或紧张，更不能据此评价专业性、态度与素质。等待、网络和催促等元对话不作为能力优缺点或扣分依据；只分析清楚可辨的回答内容，保留原文供复核。

单题按实际评分维度的权重归一化；整场每维只对实际考察它的主问题等权平均。非HR整场在题组分析完整后以固定25/25/25/15/5/5权重计算总分，未体现维度以0分计入，不再因维度缺失隐藏总分。整场汇总标准标记为`whole-interview-six-v1`。提前结束同样适用；只有问候时逐题不产生能力分，整场六维展示分为0。没有提交回答的记录仍不生成能力评分。HR按实际维度归一化。任务失败或等待中不以0分代替分析。保留精度至最终展示再四舍五入，追问不增加权重，总结不另行打分。

只有一个已评分主题且其他主题没有实质分析结果时，总结直接复用该题最终累计评分、已有优缺点与原重练目标，不创建额外总结模型任务。范围说明明确只完成一个主题，行动计划留空；没有优缺点时，总体印象只能逐字复用已有维度评价，不能凭同一引用另造结论。一个维度仅有一道题贡献时保留该题原评价，不改写为平均分描述。多主题仍调用模型综合，单题重练仍不生成整场总结，纯问候无能力总结。

早期分析按稳定回答启动：文字提交、语音最终转写并经过静默确认或手动完成提交后，立即把当前版本分析排入独立报告队列，与下一题生成并行；原始 ASR 片段不调用回答提交、不逐片段评分。实际补充产生新 revision 时取消旧版本任务，按新版本继续，结束封存始终补齐。相同回答 revision 与输入摘要继续复用任务，已成功且有效的分析不会因结束重新生成。面试 Agent 不等待分析结果，两者通过有版本的问答记录协调，不互相对话；六维与证据在逐题结果中累计，结束只等未完成分析与整场汇总。

## 重练与建议

单题重练沿用冻结快照、原主问题及追问要求，只生成本题评分和建议，不入队整场总结、不改原报告及原回答。重练仅按本题实际维度计分，不要求本题覆盖整场六维；报告头部与重练历史采用本题加权分。报告 GET 附带本人历次完成重练的评分记录，包括首次分数、评分版本和时间；不同版本不参与差值或折线比较。删除重练后相应记录消失。旧 `latest`、`rubric` 请求范围及页面升级入口已删除。

`reports.advice.v1` 为独立建议任务，稳定评分集合形成后与总结同时入队，不等待总结完成；全部是非作答回应时不编造练习建议。两任务共享同一已校验评价摘要，各自保持幂等、报告版本和输入摘要发布校验，先完成建议也不会丢失后续总结。建议任务可读取本场冻结简历，将已有项目/技能用于安排具体练习和验收方式；评分与总结调用不接收简历。建议响应只允许 next_steps，不允许返回分数。建议失败不会回滚评分；GET 反映 pending/ready/failed，前端保留原练习目标作基础建议。旧模板和辅助指标仅供历史数据读取，不再生成。

## HTTP 与共享合同

沿用同源 Cookie 身份、资源归属、Origin 和 Idempotency-Key。

- GET `/api/v1/interviews/:id/report`：只读，无自动重生成。
- POST 同路径：`{version, scope?: "missing" | "summary" | "advice"}`，分别重试缺失分析、整场总结或练习建议。`advice` 仅递增报告版本并重排建议任务，复用成功评分与总结；沿用幂等键，不重复排队尚在执行或已成功的建议。重练不生成整场总结。
- 新可选字段：evaluation.response_assessment/response_assessments/feedback_observations；其中各 response_assessments 保存对应问题的 question_scope 及回答版本。report.feedback_observations 用于内部六维审计；数值继续使用 feedback_assessments/question_scores/question_scoring_version，重练使用 practice_history，建议使用 advice_task_id/advice_status/next_steps。
- 保留历史报告字段，缺少新评分的历史记录不补造分数、不混合比较。新记录存于原 JSONB，无表结构迁移。

新任务处理器注册于 reports.handlers，运行组合自动注入 worker。API 与 worker 必须使用同一代码版本并重启。

结束面试后，前端进入全屏分析过渡，按逐题分析、总结、建议的真实任务状态展示进度；报告status为ready但advice仍pending时继续等待。所有已安排阶段完成后才跳转报告；失败可重试对应阶段，或主动查看已完成部分。零回答、无需整场总结的重练及尚未生成的历史报告有明确终态，不用空栏目表示分析进度。

## 验证

`npm run check`、`npm run build:backend`、前端构建；数据库回归只使用独立 `interviewlab_test*` 数据库。重点验证问候不评分、事实简答不越界扣分、明确不会仅对应知识不足、零分/非零原文证据、行政条件不评分、整场六维真实聚合、单题重练例外、同题追问合并、固定权重与精度、迟到版本、建议失败隔离、身份和删除。

## 模型延迟修复

逐题仍只调用一次模型，同时生成回答资格、题意范围和简短优缺点。六个评分位置仅输出 `null` 或 `[分数,短理由,证据编号]`；空维不生成理由，服务端根据实际题意范围与评分恢复六维观察状态。回答解释与题意期望各限一句，非作答的优缺点、参考与练习目标不重复生成文字。ID、revision、维度键和完整引用由服务端恢复并校验。此紧凑合同同时支持 `json_object` 与 `json_schema`，不依赖切换输出模式。原文只传一次，动态题可使用提问时冻结、来源校验通过的专业参考；参考独立于回答证据，不能视为所有题的必答清单。报告调用设置 `thinking=disabled`，1400 tokens 是输出硬上限，提示要求仅输出必要短句；不提高全局超时，取消与有限重试继续生效，不增加第二轮资格判定或无限修复。
